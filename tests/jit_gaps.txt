# Cranelift compiled end-to-end; it says nothing about whether the example runs.
# Run coverage is measured by the corpus gate, tests/jit_corpus_gate.txt.
# Compiled is not the same as runs, and #1509 was filed because the old section
# name (`covered`) claimed both.

# gaps list the first compile/unsupported reason.
# run_gaps list stems this file calls compile_covered that the corpus gate still
# records as failing at the run tier. tests/dev.rs::ledger_cross_check_holds
# fails on any such stem that is not listed here, so a new run-tier parity
# failure cannot hide between the two ledgers.
#
# Directional ratchet (D-LENS-RUN2 / #778, hole closed by #1663). Each section
# moves one way only, and the audit names the direction it rejects:
#   compile_covered may only GROW. Its row count is pinned by
#     COMPILE_COVERED_FLOOR in tests/dev.rs::jit_coverage_audit, so a hand-edit
#     cannot delete a covered stem to green the audit. A stem that stops being
#     covered is a REGRESSION: fix it or file it, never drop the row.
#   gaps and run_gaps may only SHRINK. A new compile gap is a lowering bug to
#     fix (AGENTS.md I9), not a row to park here.
# This file is scoped to the stems the audit could judge, never to the corpus.

# could not be judged (#1998), so an empty `gaps:` here is not a claim that the
# corpus has no compile gap. The audit prints the unjudged stems and their
# diagnostics on every run.
