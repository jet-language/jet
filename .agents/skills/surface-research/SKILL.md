# Surface Research

Research is evidence for a Jet surface choice, not ratification. Start with
one named gap or question, the peer language or source set, and the workload
that makes the question matter. Do not widen the question because a source
mentions another surface.

## Route

Before running, read `.agents/skills/_shared/audit-dispositions.md`. It owns
shared publication, workflow-boundary, and disposition mechanics. This method
owns source selection, provenance, comparison, failure modes, and
non-ratifying recommendations.

Apply `.agents/skills/_shared/standing-lens.md` contextually. A focused
question uses relevant sections; a broad comparison loads the full requested
categories.

- **Focused question (default):** inspect only the named surface and the
  evidence needed to answer it. Use relevant standing-lens questions and
  categories. Record non-applicable checks instead of doing unrelated work.
- **Broad comparison:** when the owner asks for several peers, a full sweep, or
  contextual comparison, load
  [`references/broad-comparison.md`](references/broad-comparison.md). It adds
  the full micro sweep and contextual peer comparison. It does not change the
  report-only boundary.

## Evidence and completion

Prefer primary sources. For every source, record its exact URL or repository,
version or commit, publication or retrieval date, and locator: section,
file:line, timestamp, issue, or decision ID. Separate observed source evidence
from Jet inference. Preserve the failure mode beside every admired idea.

For each idea, state the Jet use, Jet state, and uncertainty. Stop when the
named question has evidence, a Jet alignment or gap, a failure to avoid, and a
recommendation or explicit no-change result. A broad route stops only when all
named peers and requested categories are covered or marked unavailable.

## Competitive detail

When the question supports it, record the origin's **Ceiling**, Jet's version
under Jet's invariants, and what the peer must change to match Jet. Do not claim
a competitive win when the peer can copy the idea in its next release.

## Output

Write one Markdown report under `docs/research/` through the
project-approved non-serve CLI. Read `.agents/skills/_shared/audit-dispositions.md`
and include its required finding-disposition table. Do not create Tower work,
ballots, or implementation edits unless the owner explicitly asks. Report
completion does not ratify or implement an idea.
