# HTML design brief

Read this file for every HTML page after the report or tool branch is known. The orchestrator writes this plan before delegation. The worker implements it and does not resolve its open choices.

## Resolve before handoff

State each item in the brief:

- **Subject:** what the page is about.
- **Audience:** who reads or uses it.
- **One job:** what the page must make the reader know, decide, or do.
- **Content:** the real copy, values, records, and source material.
- **Shape:** for a report, the approved status, proposal, hybrid, or owner-approved fluid shape and its acts; for a tool, the resolved interaction and state model.
- **Hero:** the thesis plus journey or findings for a report, or the characteristic first interaction for a tool.
- **Signature moment:** the one orchestrated visual or interactive moment.
- **Layout:** every resolved block, surface, sequence, control, and responsive choice.
- **References:** the selected asset and `theme.css`; add `fonts.css` and `hl.js` through the identity rules.
- **Constraints and acceptance:** exact paths, allowed scope, project conventions, technical limits, and observable completion checks.

## Ground the design in the subject

Use the subject's own identifiers, receipts, diagnostics, traces, ledgers, and instruments. Build with real content throughout. Never sample data when the real data exists.

For a report, the hero follows the approved shape. For a tool, open with the one screen, diff, trace, or interaction the reader must see first. The header uses a legend line with source and date, a placard title, an ignition line, and a thesis when a thesis fits the page.

Group by what the reader decides between, not by how the system is built. Eyebrows, ticks, and rules must say something true. Number steps only for a real sequence. Cards hold one decision, finding, or record each.

## Signature and restraint

Use one orchestrated moment: the legend, title, and thesis rise on load; the ignition line draws left to right; sections reveal on scroll; ticks light as sections arrive. Hover is one micro-interaction: a card's left edge turns ember. Nothing else moves. `prefers-reduced-motion` removes every animation and shows everything at once.

Name controls by what the reader controls and recognizes, such as “Filter by wave”, not “Apply wave predicate”. Buttons say what happens and keep the same name through the flow. Errors and empty states say what happened and what to do next. Use sentence case, plain verbs, and no filler. Keep source identifiers, commands, and diagnostic text verbatim.

Spend boldness on the ignition line and placard title. Keep the rest disciplined. Compare the plan with the generic version of the same page and change anything that reads as a template. After the build, inspect a screenshot and remove one accessory.
