# First-principles decisions

These obligations apply to a normal first-principles invocation because Tower work is part of this method's outcome. An explicit report-only request overrides them and permits no board writes.

1. Home one Tower card in the correct epoch. Attach the proposal reference and exit criteria: the ballots are ready, every touched ratified decision has an amendment note, ratified outcomes are recorded in the spec, and implementation cards are minted per adopted outcome.
2. Mint the full direction-level ballot slate without asking permission to mint a deliverable the method already owns. Use the full `tower-ballot` profile, with genuine alternatives, worked code for each option, and the required review passes. Do not pad the slate with derivative spellings or implementation minutiae.
3. Name every ratified decision that the design amends inside the relevant ballot, not only in the proposal.

A report-only run may cite existing Tower records read-only and may list ballot titles or card IDs as next actions. It does not create cards, decisions, ballots, or implementation edits. A recommendation never authorizes implementation. Follow the shared audit-dispositions contract for publication and finding markers.

## Decision stop

The decision phase is complete when the normal card and ballot slate are recorded and read back, or when the report-only boundary is recorded with no board writes. Do not treat a reader reaction, a zero-loss result, or an unimplemented proposal as a missing decision obligation.
