# First-principles audit

Rethink one owner-declared Jet area into one coherent, simpler, more capable design. The normal outcome is an executive-summary proposal, a complete evidence and silhouette account, worked surface redesign, and the method's authorized Tower decisions. This is not a cosmetic pass or an implementation task.

Before running, read [`_shared/audit-dispositions.md`](../_shared/audit-dispositions.md) and [`_shared/standing-lens.md`](../_shared/standing-lens.md). The shared files own publication, permissions, finding dispositions, scope depth, and common evidence rules. This method owns the area rethink, full corpus and silhouette pass, proposal visuals, magic/control ladder, Tower deliverables, and closeout.

## Scope

At activation, record the named area and its finite related-concept closure. A concept is related when it shares the area's user job, value or data flow, declaration or representation mechanism, control or effect boundary, dependency needed to understand it, ratified decision, or relevant lexical space. Include every source in that closure: specifications, compiler and sema code, prelude, examples, tests, tools, prior audits, Tower state, promised or missing surfaces, and direct analogues where they explain the design. The full-corpus and silhouette pass means complete coverage inside this closure, not an invitation to sweep unrelated Jet.

Parent and child work uses this same definition. Neither may silently add a distant feature, workload, or source set. Record an out-of-closure opportunity for the owner instead of widening the run.

When the owner requests a full audit, cover the entire declared closure and every required category. Do not silently turn a full request into a sample.

## Quality bar

Use the three reader reactions — “duh,” “how did I miss that?”, and “ohhh” — as a quality aspiration. Record where the connection lands, but never use a reaction as the stop predicate.

Apply the relevant standing-lens sections to the declared closure. Use the four questions, agent quantities, micro sweep, or runtime probes when the subject calls for them; do not force unrelated lenses. Probe the running binary for executable claims, cite paths, lines, syntax, and decision IDs, and mark unavailable evidence `unknown`.

- Unify, simplify, and power up together. Preserve capability, add natural instances, and delete duplicate mechanisms rather than adding a parallel one.
- Test the model at both extremes of the declared area, from a trivial default to the most demanding expert case.
- Every redesign element shows beginner magic and expert control. The ladder runs from no user text to explicit authority, uses real code at each opt-in rung, and states that no upper rung changes the lowest rung's behavior.
- The surface is the product. Each unification needs a visibly better before/after pair, and the final vision needs complete examples plus a structural view.
- Greenfield breaking changes are allowed. Any touched ratified law needs an explicit amendment in a ballot; frozen walls remain closed unless a ballot names their reopening.
- Every automatic default has a ledger command, an explicit replacement spelling, and a project-level refusal switch. Check for ceremony creep and magic without an exit.

## Completion and permissions

The evidence and proposal are complete only when the declared closure has a finite coverage ledger with evidence or an honest `unknown` for every required slice; the full corpus and silhouette are accounted for; one idea, its axes, law, and kill-check are stated; the proposal contains the required worked redesign and magic/control ladder; the final vision, owner decisions, adoption boundary, and authorized review are complete; and the appropriate report or Tower obligations are recorded.

| Requested outcome | Output and board behavior |
| --- | --- |
| Chat-only proposal or explicit no-file request | Deliver the proposal in chat. No retained report, disposition-table scaffold, board writes, or implementation edits. |
| Retained report-only audit or proposal | Write only the requested report and its disposition table; cite existing Tower records read-only; create no cards, decisions, ballots, or implementation edits. |
| Normal first-principles invocation | Complete the method-owned homed card and full direction-level ballot slate in [`references/decisions.md`](references/decisions.md); do not ask permission to mint those declared deliverables. |
| Explicit implementation request | Follow the approved implementation boundary. A proposal or recommendation alone never authorizes implementation. |

Report completion never means implementation completion. An explicit report-only request overrides the normal first-principles Tower deliverables. Zero negative findings or a missing probe is valid only when the required scope is complete and the missing evidence is marked honestly.
