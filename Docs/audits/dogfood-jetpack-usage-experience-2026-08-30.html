Using Jet to build Jetpack

Jet expressed a real package-manager slice in compact source and ran it well. The authoring experience was not yet better than Rust overall. Jet was easiest to read, but correction took too many passes.

What worked

Jet’s language ideas stayed visible

Typed failure

String !ParseError, local #Error records, and ?? kept success paths and error conversion compact. Pure-looking helpers that also needed caller failure domains weakened this benefit.

Dense data declarations

Records, collection literals, interpolation, #Codable, and #Test kept models and fixtures short. The source ratio remains directional because the Rust envelope includes more behavior.

Auditable ownership

~ exposed copy and retention boundaries. Stable code was clear, but finding each boundary often took another compiler pass.

Strong diagnostics—sometimes

E0209, E2404, E0109, E0121, E0602, E0358, and L0507 could name exact sites and fixes. Root causes still sometimes appeared downstream or only during execution.

Campaign-process confounds

  • Several worker lanes could not run checks. One plan contribution reached integration with 61 diagnostics.
  • Some agents preserved behavior under narrow correction briefs. Direct Result matching, incomplete module graphs, and broken tools also discouraged refactoring.

Before another self-hosting port

Shrink the distance to idiomatic, cross-tier-green Jet

  1. Make canonical Jet visible. Teach and lint ordered same-subject dispatch.
  2. Fix the authoring loop. Make one project check cover modules, outputs, Core, JIT, interpreter, and AOT.
  3. Improve ownership diagnostics. Name the consuming call, later reuse, and exact ~ site.
  4. Improve failure-domain diagnostics. Name the helper and show the needed !ErrorType signature.
  5. Expose typed package and profile models. Stop forcing line-scanner reimplementation.
  6. Give deterministic structured-output builders. Exact JSON and framing must not need escaped interpolation.
  7. Complete demand-driven incrementality. Skip unchanged work before the final binary cache gate.
  8. Keep package boundaries sovereign. Optimize inside declared boundaries; never redefine them.
  9. Resume only after owner approval. Stabilize the Rust implementation first and avoid double maintenance.
Durable owner direction

Rust active. Jet canary frozen.

Tower card #2327 records the directive. docs/agents/prompts/dogfood-jetpack.md carries the stop notice and states that side-by-side isolation was a campaign rule, not a permanent rejection of replacement.

The Jet source remains a canary, benchmark fixture, and compiler regression corpus. It is not an active second Jetpack product. Eventual replacement is not rejected.

Final assessment

Jet expresses this software with much less source than the conservative Rust envelope. Its explicit effects, compact models, executable tests, small binary, and fast runtime are real strengths.

The experience still falls short of simple and frictionless. The final source hides the correction load. Jet must reduce the distance from a plausible first draft to an idiomatic, cross-tier-correct, project-green program before preference over Rust can be established.
