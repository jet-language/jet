# Compiler functions no path calls (2026-11-10, #6637 criterion 1)

This audit lists every top-level Compiler function that no code path reaches at dev
`76955986d0`, and gives each one a disposition. Every disposition here is **deleted**:
no row is a feature that a test, a route table or a caller still asks for, so wiring
one would add a caller only to keep it.

## Method

The census walks every source and data file in `Compiler/`, `Core/`, `Jetpack/`, `Tools/`,
`tests/`, `Examples/`, `Benchmarks/`, `Experimental/`, `Docs/spec/` and the root `.jet`
files. For each top-level `name: fn` declaration under `Compiler/<Package>/Source/`, it
counts every other occurrence of `name` as a word. Strings, route tables, `use` lists, tests
and fixtures all count, so a name that a table spells, a test calls or another package
(the Jetpack packages import Compiler packages) imports stays live.

A function counts as unreached when its name appears only in its own declaration and body,
or only inside other unreached functions' bodies. The pass repeats until nothing changes, so
a chain of helpers that only an unreached entry used is unreached too.

These declarations are out of the census:

- **Generated files.** A file whose first line is `// Generated by …` belongs to its
  generator, which keeps its rows.
- **Marked declarations.** A declaration with a `#[…]` line above it, such as `#[FFI(asm)]`
  or `#[Export]`, is reached by its marker's contract.
- **Repeated names.** A name declared twice, such as a per-target variant, is left alone.
- **Test packages.** Everything under `Compiler/<Package>/Tests/` is a test or fixture.

After the deletion, the same census over the changed tree finds no unreached function,
and `jet build Compiler` builds it.
