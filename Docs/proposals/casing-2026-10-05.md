## 1. The proposal in one paragraph

A name is a list of words taken from one lexicon. Inside Jet source, the case
of those words tells you what kind of thing the name is. Everywhere outside
Jet source (files on disk, URLs, JSON, environment variables, command lines,
SQL, HTML, C symbols, generated code), Jet writes the same words in that
medium's own published convention through one mechanical projection that the
compiler computes. Nobody writes a rename by hand unless an outside name is
genuinely irregular, and then they write it once, on the field, where every
format reads it.

Inside Jet source there are exactly three cases:

| Case | Means | Used for |
|---|---|---|
| `PascalCase` | a kind of thing, or a place | types, traits, enum variants, markers (including the library part, `#Server.Get`), effects and capabilities (`FS.Read`), generic type parameters, unit families; code files and folders in the Jet repository |
| `snake_case` | a value or a namespace | functions, methods, fields, parameters, locals, module paths, import aliases, unit members, lint names, labels |
| `SCREAMING_SNAKE` | a fixed value at module level | module-level immutable bindings (`MAX_ROWS :: 100`), compile-time number parameters (`<prep N: Int>`) |

Acronyms come from one closed list. They are written in full capitals whenever
the case capitalizes words (`HTTPClient`, `MAX_HTTP_RETRIES`) and in full
lowercase when it does not (`http_client`). Two touching acronyms keep an
underscore in PascalCase (`HTTP_API`). Coined words such as `Wasm` and
`Bindgen` are ordinary words.

This is not a new law. It is Jet's ratified law (D-SHAPE-CASE1=C, D-ACRO-CASE1=A,
D-ACRO-LEX1=A, D-ONCE-CASE1=A, D-MARKER-CASE1=A, D-PATH-CASE1=A, and the owner's
ALL_CAPS constant ruling), stated once, completed for the categories nobody
decided, and extended with one boundary mechanism so the outside world gets its
own conventions without hand-written renames.

## 3. Research findings

### 3.1 Readability studies

| Study | Subjects | Finding |
|---|---|---|
| Binkley, Davis, Lawrie, Morrell, "To camelcase or under_score", ICPC 2009, doi:10.1109/ICPC.2009.5090039 | 135 programmers and non-programmers | camelCase had 51.5% higher odds of a correct answer; camelCase took 13.5% longer; training in a style reduced its cost (as reported in Sharif & Maletic 2010, sec. I and IV.A) |
| Sharif & Maletic, "An Eye Tracking Study on camelCase and under_score Identifier Styles", ICPC 2010, doi:10.1109/ICPC.2010.41 | 15 programmers | no accuracy difference; underscore 932 ms (20%) faster; for three-word names camelCase took 36% longer and needed more fixations; novices gained about twice as much from underscores as experts |
| Binkley et al., "The impact of identifier style on effort and comprehension", Empirical Software Engineering 18(2), 2013, doi:10.1007/s10664-012-9201-4 | 150, five studies | experienced developers are less affected by style; beginners benefit from camel casing in accuracy and effort (abstract) |

What this supports:

- No study shows a large, stable winner. Effects are tens of percent on an
  identifier-recognition task, they shrink with training, and the 2013 paper
  says code reading differs from prose reading.
- The cost of joined words grows with word count (Sharif & Maletic: no gap at
  two words, 36% at three). Jet's functions and constants are the long names
  (section 2.1), so they are the worst place to remove separators.
- Consistency and training matter more than the choice. A language that uses
  one style per role, enforced by the compiler, gets the training effect for
  free.

### 3.2 What other languages chose

| Language | Types | Functions | Values | Constants | Acronyms | Notes |
|---|---|---|---|---|---|---|
| Rust (RFC 430, API guidelines C-CASE) | UpperCamel | snake | snake | SCREAMING | word-cased: `Uuid`, `Stdin`; lowercase in snake | "type-level" vs "value-level"; Jet's current model |
| Go (spec; CodeReviewComments "Initialisms") | either | either | either | either | consistent case: `ServeHTTP`, `appID`, `xmlHTTPRequest`, never `Url` | case is semantics: an upper-case first letter exports the name |
| C# / .NET (Framework Design Guidelines) | Pascal | Pascal | Pascal properties, camel params | Pascal | two letters caps (`IOStream`), three or more word-cased (`HtmlTag`); `Id`, `Ok` | names "cannot differ by case alone" because some CLR languages ignore case |

| Kotlin (coding conventions) | Pascal | camel | camel | SCREAMING | `[INFERENCE]` two letters caps, longer word-cased | enum constants may be either |
| Java (Google style 5.3) | UpperCamel | lowerCamel | lowerCamel | SCREAMING | deterministic word-casing: `XmlHttpRequest`, `newCustomerId` | defines an algorithm from prose to name |

| Zig (style guide) | TitleCase | camelCase | snake | snake | word-cased, "even acronyms that are only 2 letters long" | file named TitleCase when it is a struct, else snake; directories snake |
| Odin | `Ada_Case` | snake | snake | SCREAMING | caps inside `Ada_Case` | `[INFERENCE]` from core library sources, not re-read |

| Ada (RM 2.3; Ada 95 Quality and Style Guide 3.1.3) | `Mixed_Case` | `Mixed_Case` | `Mixed_Case` | | "use uppercase for abbreviations and acronyms" (`Text_IO`) | identifiers are case-insensitive after case folding |
| Pascal / Delphi | Pascal (`T` prefix) | Pascal | Pascal | Pascal | | case-insensitive `[INFERENCE]` |
| Nim (manual; NEP-1) | PascalCase | camelCase | camelCase | either | | style-insensitive: only the first letter is case-sensitive, underscores ignored |
| Haskell (2010 report 2.4) | upper first letter | lower | lower | lower | | case is grammar: constructors and types vs variables |

Patterns:

1. Almost every modern language separates "kinds" from "values" by case
   (Rust, Python, Swift, Kotlin, Java, Zig, Nim, Haskell). The ones that do not
   (C#, Delphi, Ada) either use a second case for parameters (C#) or are
   case-insensitive (Delphi, Ada).
2. The acronym question has two camps, and both are proven at scale. Caps camp:
   Go, Swift, Python, Ada. Word-case camp: Rust, .NET, Kotlin, Google Java, Zig.
   The caps camp needs either human judgment or a list; Ada's guide says
   abbreviations "should be project-wide" and formatted by a tool. Jet already
   has that list (D-ACRO-LEX1), so it pays the caps camp's only real cost.
3. Case as visibility (Go) creates a boundary tax: every exported field is
   PascalCase, so JSON keys need per-field tags. This is the strongest
   real-world argument against making fields PascalCase.
4. Case-insensitivity and style-insensitivity (Nim, Ada, Delphi, SQL) remove
   one class of mistakes and add another: search tools and other languages do
   not share the folding. Nim keeps the first letter case-sensitive so `Foo`
   and `foo` stay distinct, and its manual notes that it was once fully
   style-insensitive. .NET forbids names that differ only by case for the same
   reason. Jet's answer is the reverse: exact names in source, and a
   mechanical fold only where Jet meets a case-insensitive outside world
   (file systems, HTTP header names).

### 3.3 Mapping layers: proven right and wrong

| Mechanism | What it shows |
|---|---|
| Swift `JSONDecoder.KeyDecodingStrategy.convertFromSnakeCase` (Apple docs) | `base_uri` becomes `baseUri`, not `baseURI`; Apple's note: the strategy "can't infer capitalization for acronyms or initialisms". Without a lexicon, a caps convention cannot round-trip; every acronym field needs hand-written `CodingKeys`. |
| Protocol Buffers JSON mapping (protobuf.dev) | fields are `lower_snake_case` in the schema and mapped to `lowerCamelCase` JSON keys; parsers accept both; `json_name` overrides one field. The guide also documents that `x_0` → `x0` does not round-trip. One canonical name, one mechanical projection, one per-field escape: the model this proposal adopts. |
| Google AIP-140 | protobuf field names "must use lower_snake_case", mapped "to an appropriate naming convention in JSON and in generated code". |
| serde `rename_all` (serde.rs) | eight case styles per type, independent serialize and deserialize styles. Proven, but per type: a 40-type API repeats it 40 times. |
| System.Text.Json `PropertyNamingPolicy` | one policy per serializer options object; `JsonNamingPolicy.CamelCase` turns `TempCelsius` into `tempCelsius`; a per-type attribute overrides it. Per-call policies let one type have two wire shapes. |
| Pydantic `alias_generator` | one generator per model config; `to_camel` capitalizes each word. |
| EF Core + PostgreSQL (EFCore.NamingConventions) | default mapping keeps .NET PascalCase, which "forces double-quotes" because PostgreSQL folds unquoted names to lowercase; the plugin projects to snake_case. Evidence that SQL wants lowercase snake and that a projection layer is the fix. |
| PostgreSQL lexical rules | unquoted identifiers fold to lowercase; quoted identifiers are case-sensitive; the SQL standard folds to upper case. Lowercase snake is the only spelling that works unquoted everywhere. |
| Go `encoding/json` | `[INFERENCE]` exported PascalCase fields serialize as `"UserID"` unless tagged; tags are ubiquitous in Go code. |

Right: one canonical name; one deterministic projection per medium; one
override, written once, read by every consumer; exact matching on decode.
Wrong: inferring acronyms without a list; per-call naming policies that give
one type several shapes; case-insensitive matching that the outside world does
not share; leaking source case into media with their own rules.

There is no single case the outside world agrees on. Any rule that makes Jet
source case leak outward will be wrong for most media. The rule must separate
the two.

## 4. What each domain needs

**Web (first).** Friendly lowercase-hyphen URLs that never depend on the file
system's case rules; JSON that is camelCase for browser and Google-style APIs
and snake_case for many server APIs, chosen once per service; HTML attributes
and CSS classes in lowercase-hyphen; header names compared without case and
emitted in lowercase; query parameters in the same case as the JSON body; route
parameters that bind by name to handler parameters (`:user_id` ↔ `user_id`);
OpenAPI and generated TypeScript clients that match the JSON. Web authors copy
examples, so Jet's own examples must produce the URLs a web developer expects.

**Systems and FFI.** C symbol names exactly as the header spells them, because
the documentation, the debugger and the linker all use those bytes; Jet
wrappers in Jet case beside them; exported symbols predictable from the Jet
name; no case-only twins (the linker and Windows DLL tools differ on case).

**Games.** Engine and graphics APIs through FFI with verbatim names
(`rl.DrawText`); asset paths that behave the same on a Windows dev box and a
Linux build server; shader and save-file keys that round-trip.

**Data science.** Column names from CSV, spreadsheets and Parquet that arrive
in any style (`Unit Price`, `unitPrice`, `unit_price`); typed rows that bind
to them; SQL that needs no quoting.

**Embedded.** Register and peripheral names from vendor SVD files kept
verbatim (`GPIOA.ODR`), constants in SCREAMING, linker symbols exact.

**Scripting and CLI.** Flags in `--kebab-case`, short flags case-sensitive,
environment fallbacks in SCREAMING, subcommands as plain lowercase words, job
names that are valid on the command line.

**GUI.** Component types in PascalCase; event and property names that project
to the host toolkit (DOM `aria-label`, `data-*`); user-visible labels follow
the separate prose law (D-CASE-CHROME1=C).

**Every domain.** Search: one spelling per name in source, so `grep` finds
every use. Teaching: a beginner can predict a spelling and the compiler fixes
the rest.

## 5. Recommendation

### 5.1 The rule set

**R1. Words are the identity.** Every name is a list of words. Word boundaries
are underscores, hyphens, a lowercase-to-uppercase change, and the end of an
acronym from the lexicon. Digits attach to the word before them (`utf8`,
`base64`, `ipv6`; see edge cases). Two names with the same words project to
the same outside name in every medium, so they may not sit where one
projection would collide (two fields, two files in one folder).

**R2. In Jet source, case shows the role.** The three-row table in section 1.
New rows completed by this proposal:

| Category | Case | Status |
|---|---|---|
| Generic type parameters | PascalCase (`T`, `Key`) | already the practice; written into the law |
| Compile-time number parameters | SCREAMING (`N`, `ROWS`) | new; consistent with the ALL_CAPS constant ruling |
| Effect and capability names | PascalCase with caps acronyms (`FS.Read`, `DB.Write`) | ratified; written into the table |
| Marker library part | PascalCase of the import alias (`#Server.Get`, `#HTTPClient.Retry`) | D-MARKER-CASE1=A |
| Import aliases and module paths | snake_case | ratified |
| Lint names, labels | snake_case | ratified |
| Plural acronyms | a trailing lowercase `s` is a plural: `URLs`, `IDs`; snake `urls`, `ids` | new; zero uses today (Core grep found only comments) |
| Brand words with inner capitals | one word unless listed in the compound table (`MacOS`, `IPv4`, `IPv6`; candidates `GitHub`, `OAuth`, `JavaScript` by ballot) | ratified table, extension by ballot |

**R3. Acronyms.** One closed lexicon (`Syntax::ACRONYMS`, mirrored in
`Casing.jet`). In capitalizing cases (PascalCase, SCREAMING) an acronym is all
caps; in snake it is all lowercase. This is the owner's rule and the Go,
Swift, Python and Ada rule. Jet can afford it because the lexicon makes every
projection reversible, which is exactly what Apple's decoder lacks.

**R4. Files and folders.** Code files and folders in the Jet repository are
PascalCase with caps acronyms (D-PATH-CASE1=A). Files a tool looks up by a
fixed name (`package.jet`, `run.jet`, `.gitignore`) are lowercase everywhere,
including the repository, so a file copied between Jet and a user project
never changes name. User projects may spell files any way; an import finds a
file by its words, and two files with the same words are an error on every host
(D-PATH-CASE2, revised). Scaffolds write the house style.

**R5. The boundary rule.** Every name that leaves Jet source is a projection
of its words. One function computes it, `name.project(medium)`, from one table
of medium defaults. One override chain changes it:

1. a per-field or per-variant name, `#Rename("legacy_id", json: "legacyId")`
   (ratified D-RENAME-CASE1=A, D-SHAPE-ONE1=A);
2. a per-type case, `#Rename(.Camel)` (ratified);
3. a per-package default in `package.jet`, `naming: .{ json: .Camel }`
   (new, D-WIRE-CASE1);
4. the medium default below.

Decoding matches the projected name exactly. A near miss (same words,
different case) is a diagnostic that names the expected spelling, never a
silent match.

| Medium | Default projection | Example from `avatar_url` / `UserProfile` / `FreeTier` |
|---|---|---|
| JSON, CBOR, TOML, YAML, XML, CSV keys | the Jet name verbatim (snake fields, Pascal variants) | `avatar_url`, `FreeTier` |
| …with `.Camel` | words, first lowercase, rest capitalized, acronyms word-cased (D-WIRE-ACRONYM1) | `avatarUrl`, `freeTier` |
| …with `.Pascal` | acronyms word-cased | `AvatarUrl` |
| …with `.Kebab` / `.Snake` / `.Screaming` | lowercase or uppercase words | `avatar-url`, `avatar_url`, `AVATAR_URL` |
| Query parameters | same as the package JSON case | `?avatar_url=` or `?avatarUrl=` |
| URL path segments from names | lowercase words joined by `-` | `/user-profiles` |
| Route parameters | snake, binding to the handler parameter of the same name | `:user_id` |
| Environment variables | prefix plus SCREAMING words, `__` between nesting levels, exact match | `APP_AVATAR_URL`, `APP_DATABASE__URL` |
| CLI flags | `--` plus lowercase words joined by `-`; enum values likewise | `--avatar-url`, `--plan free-tier` |
| CLI metavar | SCREAMING | `AVATAR_URL` |
| HTML attributes, CSS classes, custom properties | lowercase words joined by `-` | `aria-label`, `.user-profile`, `--avatar-url` |
| HTTP header names | compared without case; emitted lowercase | `content-type` |
| SQL tables and columns | lowercase snake, no automatic plural; reserved words quoted by the generator | `user_profile.avatar_url` |
| Package names | lowercase words joined by `-`; identity compared after folding `-` `_` `.` and case (PEP 503 rule) | `profile-service` imports as `profile_service` |
| C exports | the Jet name verbatim (snake) | `avatar_url` |
| C and other foreign imports | verbatim; never re-cased | `rl.DrawText` |
| Generated foreign code (TypeScript client, C header) | the target language's own published table, computed from the same words | `UserProfile`, `avatarUrl` |
| Diagnostic codes, IDs, hashes | opaque tokens, verbatim and case-sensitive | `E0358` |

Where this lives in code: one module that owns word splitting, the lexicon and
every projection (today split across `acronyms.rs`, `Shape.rs:305-340,946-952`
and five copies of the rename `match`). `ShapeFieldNames` already has one slot
per medium; it becomes the only place a projected name is computed.

### 5.2 One program, four styles

The program: a profile service with one record, one constant, one handler, one
settings struct. Recommended Jet first; lines marked `PROPOSED` use a surface
from this ballot set.

**Recommended (role-based, words projected):**

```jet
// package.jet
name: "profile-service"
version: "0.1.0"
naming: .{ json: .Camel }                       // PROPOSED, D-WIRE-CASE1

// App/UserProfile.jet
#Codable
struct UserProfile {
    user_id: Int
    display_name: String
    avatar_url: String
    plan: Plan
}
#Codable
enum Plan { FreeTier, ProTier }

// run.jet
```

### 5.3 Why not PascalCase everywhere

The owner prefers PascalCase with caps acronyms. The recommendation keeps it
everywhere it carries meaning: every type, trait, variant, marker, effect,
generic parameter, and every code file and folder in Jet. It stops at values
for four reasons, each with evidence:

1. **Long names need separators.** Functions average 2.95 words and constants
   3.22 (section 2.1). The eye-tracking study found no gap at two words and a
   36% gap at three.
2. **Caps acronyms collide in long names.** PascalCase with caps acronyms needs
   an underscore at every touching pair. Types never hit it in Jet today;
   functions hit it 43 times.
3. **Case is Jet's cheapest type-or-value signal.** `geo.Point.origin`,
   `.FreeTier`, `HTTPError` vs `http_error` all read at a glance. Rust, Python,
   Swift, Haskell and Zig keep the split for this reason.
4. **The boundary tax.** Go's PascalCase fields need a tag on nearly every JSON
   field. Snake fields project to the most common wire, SQL and env spellings
   with no annotation.

### 5.4 File-routed URLs: a recommended change to the owner's latest answer

The owner asked that a page's URL be "the file name directly." Recommended
instead: the URL is the file name's **words**, written lowercase with hyphens.
For every user who already names files `order-items.jet` or `orders/[id].jet`,
the two rules give the same URL, so user freedom is unchanged. They differ only
for capitalized or underscored names, and there the evidence is one-sided:

- Jet's own examples are PascalCase by the owner's repository rule. Under the
  literal rule they would publish `/OrderItems` and `/Index`, teaching every
  beginner a URL style Google, Microsoft and common practice advise against,
  or the repository would need a route-folder exception the owner did not
  want.
- URLs are case-sensitive (RFC 3986) while Windows and macOS file systems are
  not. A literal rule makes the public URL depend on a spelling the file
  system does not even preserve reliably.
- The same word reading already finds files for imports (D-PATH-CASE2), so it
  is one mechanism, not a new one. Razor Pages ships the same transform.
- `#Server.Get("/Exact")` on the page replaces the derived URL whenever a
  different address is wanted.

Both options are on the ballot (D-ROUTE-FILES2: A words, B literal).

### 5.5 Edge cases

1. **Touching acronyms.** `HTTP_API` (Pascal), `http_api` (snake), `httpApi`
   (camel wire), `http-api` (kebab), `HTTP_API` (SCREAMING). All reversible
   through the lexicon.
2. **Digits.** Digits attach to the word before (`utf8`, `base64`, `ipv6`).
   A digit-only word such as `x_0` is rejected by E0357 with the fix `x0`,
   because protobuf's documented `x_0` → `x0` round-trip loss would otherwise
   reach every projection. A version pair keeps an underscore between numbers
   (`windows10_1709`), as RFC 430 allows.
3. **Plural acronyms.** `URLs`, `IDs` in PascalCase; `urls`, `ids` in snake.
4. **Brands.** `MacOS`, `IPv4`, `IPv6` are fixed compounds today. New compounds
   join by ballot, otherwise a brand is one word (`Github`), never a guess.
5. **Unicode.** Uncased scripts satisfy every case (`Syntax.rs:889-893`). All
   case changes use locale-independent simple folding, as Ada's RM requires;
   Apple's decoder uses the system locale, which breaks Turkish `i`.
6. **Case-only twins.** Rejected for files on every host, and for exported
   names that differ only by case (the .NET rule), because other languages and
   file systems cannot tell them apart.
7. **Keywords on the wire.** A field whose wire name is a Jet keyword
   (`type`) uses `#Rename("type")`.
8. **Environment matching.** Today Jet matches environment names without case
   (`FSIoEnvOsTesting.rs:622-628`). POSIX says names "shall not be folded".
   Recommended: exact SCREAMING match, plus a hint naming the expected variable
   when only a differently cased one exists.
9. **HTTP headers.** Compared without case, emitted lowercase; typed header
   fields project with kebab.
10. **Opaque URL segments.** IDs, hashes and diagnostic codes (`/e/E0358`)
    are values, not words, and stay verbatim.
11. **SQL reserved words.** `order`, `user` as tables are quoted by the
    generator; the projection never changes the words.
12. **Foreign islands.** Inside `#Bindgen`, `#Extern` and `extern rust`
    modules, names stay verbatim; a Jet wrapper module re-exports them in Jet
    case if the author wants. SVD register names follow the same rule.
13. **Asset paths.** A literal asset path whose case differs from the file on
    disk works on Windows and macOS and fails on Linux. `[INFERENCE]` Jet does
    not check this today; a compile-time exact-case check of literal project
    paths is a natural follow-up card, not part of these ballots.
14. **Human-written column headers.** CSV and spreadsheet headers such as
    `Unit Price` can opt into word matching on decode (`match: .Words`), which
    binds `unit_price`; ambiguity is an error. JSON and env stay exact.
15. **Markers from snake imports.** `use core.http.client as http_client`
    gives `#HTTPClient.Retry` (D-MARKER-CASE1=A).
16. **Scaffold names vs reserved roots.** `package.jet` and `run.jet` stay
    lowercase; scaffolded code files are PascalCase (`Routes/Index.jet`).

### 5.7 Beginner and expert paths

**Beginner.** Write names in plain words. The compiler says when a name has
the wrong case and `jet fix` rewrites it (`HttpClient` → `HTTPClient`). Never
write a rename to talk to a normal web API: put one line in `package.jet` or
keep the default. Name a page file `OrderItems.jet` or `order-items.jet` and
get `/order-items` either way.

**Expert.** `#Rename("exact")` on a field or variant, with per-format
arguments, for irregular legacy names; `#Rename(.Case)` on a type that must
differ from its package; `naming:` per package; `#Server.Get("/Exact/Path")`
for any URL; verbatim foreign names inside binding modules;
`jet inspect shapes` prints every projected name for every medium, so a reader
can audit the wire contract without running the program.
