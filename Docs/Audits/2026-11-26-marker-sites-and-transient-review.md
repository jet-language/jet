# Adversarial Design Review: Marker Sites, Wrapping Block Policies, and `Err.transient()` (#7011 / P13)

- **Date:** 2026-11-26
- **Scope:** Proposal item P13 (`Docs/Proposals/2026-11-24-greenfield-language.md` Part 2 P13, §3.7, §3.11) and issue #7011 — (1) markers apply uniformly at every site they declare across all 21 `Site` variants (`Package`, `File`, `Module`, `Function`, `Method`, `Block`, `Statement`, `Expression`, `Type`, `Impl`, `Trait`, `Declaration`, `Constant`, `Field`, `Variant`, `Parameter`, `Test`, `Operation`, `Text`, `Arm`, `TypeUse`); (2) wrapping policies work on blocks (cleanly aligned with the `#7004` wrap-role seam); and (3) `Err` (and Core/user error types) answer `transient()` safely for retry policies.
- **Verdict:** **NEEDS BALLOT** (5 bounded owner ballots **Q1–Q5** below before starting implementation).

---

## 1. Executive Summary

Jet already has a single typed marker vocabulary (`Compiler/Prelude/Markers.jet`), a 21-variant `Site` enum (`Core/Prelude/Prelude.jet:601-623`), a lexical policy resolution ladder (`Compiler/JetFoundation/Source/Policy/Policy.jet:363-420`), a two-audience `Describe` trait (`Core/Prelude/Prelude.jet:175-178`), and a ref-counted `ERR_PAYLOAD` box inside the 96-byte native `Err` handle (`Compiler/JetBackend/Source/ErrLayout.jet:8-24`, `Compiler/JetIR/Source/BuildTypes.jet:4064-4097`).

However, inspecting the live compiler and Core libraries exposes **five structural gaps** that prevent P13 / #7011 from shipping cleanly without architectural rulings:

1. **Fragmented, marker-name-switched parsing and silent marker drops across the 21 sites.** `JetParser` does not have one uniform marker-attachment pass. Instead, `Statements.jet:2425-2600` hardcodes 16 block marker names, hardcodes 4 local-declaration marker names (`Track`, `Meta`, `Local`, `Shared`), drops argument labels on user block markers (`Stmt.ScopeMember`), and only permits one marker per block/statement/parameter. `Items.jet:852-861` **silently drops** any registered Prelude marker other than `#Root` on parameters. `Declarations/Tests.jet:49-75` **silently drops** every marker on `#Test` blocks (and everything except `#Pre` on property tests). `Expressions.jet:1252-1297` parses `#Name expr` only as a zero-argument value tag (`Expr.Tainted`), cannot parse `#Name(args) expr`, and has inconsistent postfix precedence (`#Tag xs.len()` vs `#Tag [1, 2].len()`). `RuleSite.Constant`, `RuleSite.Operation`, `RuleSite.Text`, and `RuleSite.TypeUse` are **never emitted** anywhere in `JetParser` or `JetSema`, and `MarkerRules.jet:139` omits `"TypeUse"` from `sema_marker_rules_site_value`.
2. **Block `#Policy(...)` rejects wrapping calls, and function `#Policy(...)` rejects labeled args and stubs builtins.** `Parser/Declarations/Policies.jet:70-75, 155-196` parses block `#Policy(...) { ... }` strictly as declarative `PolicyDeclaration` settings (`copies: .Explicit`, `failures: .Explicit`, etc.) and rejects call arguments like `retry(3)` with a shape error. Even on functions, `Policies.jet:139-152` rejects labeled arguments (`retry(3, backoff: .exponential(100ms))`), and `CallablePolicies.jet:5-7, 25, 247` skips wrapping for every built-in policy name (`cache`, `retry`, `trace`, `registration`, `route`)!
3. **Wrapping blocks collide with block value-tails, control-flow escapes, and outer mutation.** Only `#Unsafe { ... }` propagates block value tails (`ValueTail.jet:89`, `Statements.jet:2508`). Lowering a wrapping block to a closure (`wrapper.wrap(fn() { ... })`, the `#7004` wrap seam) breaks `return`, `break`, and `continue` escaping the block and exposes partial mutation of outer `^` locals across retry attempts.
4. **Overloading `#Policy(...)` between lexical `.Tighten` settings and runtime wrappers creates a semantic collision.** Lexical policies (`Policy.jet:363-402`) reject nested loosening (`PolicyError.Widening`) and same-scope conflicts (`PolicyError.Conflict`). Runtime wrappers (`retry`, `deadline`, `trace`) compose dynamically outer-to-inner; two nested `#Policy(retry(...))` blocks must compose (or be ruled), not collide in `PolicyDeclaration`.
5. **`Err.transient()` faces both the Go `net.Error.Temporary()` pitfall and `Err` type erasure.** Go 1.18 formally deprecated `net.Error.Temporary()` (Go issue #45729) because a naive boolean conflated `EMFILE` spin-loops, non-idempotent ambiguous timeouts, caller cancellations, and overload storms. Furthermore, Jet's `Err` is a concrete struct (`Compiler/Prelude/Errors.jet:85-95`) whose Core conversions (`impl <CoreError> -> Err { return Err("{self}") }`) erase the source error into text; without capturing transience at conversion time (e.g. in the unused offset-8 word of `ir_err_payload_node`), `Err.transient()` cannot distinguish `NetError.Timeout` from `NetError.InvalidInput`. And today `DBError.Failed(String)` collapses transient `SQLITE_BUSY` / deadlock errors with permanent SQL syntax errors, while HTTP 429 / 503 are `Ok(HTTPResponse)` rather than `HTTPError`.

## 2. Strongest Existing Solutions & Primary-Source Lessons

| System | Primary Source | What It Does Best | Concrete Lesson for Jet #7011 |
| :--- | :--- | :--- | :--- |
| **Rust Attributes & Proc Macros** | The Rust Reference (*Attributes*, *Procedural Macros*); RFC 1566; RFC 2527; `proc_macro_hygiene` | Unified `#[attr]` syntax across items, statements, expressions, match arms, fields, variants, and parameters; explicit distinction between outer `#[attr]` and inner `#![attr]`. | Rust kept proc-macro attributes on expressions and statements unstable for years because (a) macro expansion order interacts with operator precedence (`#[a] x + y` vs `#[a] (x + y)`), and (b) rewriting arbitrary expressions breaks hygiene and control-flow analysis. Jet must pin down expression-marker precedence and restrict block wrappers to explicit block/item forms. |
| **C# `AttributeTargets`** | ECMA-334 §22 (*Attributes*); Microsoft Learn `System.AttributeTargets` | Explicit 15-member target bitmask (`Assembly`, `Module`, `Class`, `Struct`, `Enum`, `Constructor`, `Method`, `Property`, `Field`, `Event`, `Interface`, `Parameter`, `Delegate`, `ReturnValue`, `GenericParameter`) plus disambiguating target specifiers (`[return: NotNull]`). | C# deliberately excludes expression, statement, and block targets from attributes so attributes never compete with expression/statement grammar. Where two targets share one token position (e.g. method vs return type), explicit grammar disambiguation is mandatory. |
| **Java `@Target` / JSR 308** | JLS §9.6.4.1 (`@Target`, `ElementType`); JSR 308 (*Type Annotations*) | Separates declaration annotations (`FIELD`, `PARAMETER`, `LOCAL_VARIABLE`) from type-use annotations (`TYPE_USE`, `TYPE_PARAMETER`). | Retrofitting `TYPE_USE` exposed painful attachment ambiguities (`@NonNull String[]` vs `String @NonNull []`, `@A Outer.Inner` vs `Outer.@A Inner`). ## 5. Adversarial Attacks & Technical Analysis

### Attack 1: `Err.transient()` vs. the Go `net.Error.Temporary()` Pitfall (Go #45729)
- **Claim attacked:** "An error answers `transient()`, which retry reads" (`Docs/Proposals/2026-11-24-greenfield-language.md:431, 1560`).
- **Attack:** Go shipped `net.Error.Temporary() bool` and had to formally deprecate it in Go 1.18 (Go issue #45729) because a naive boolean on errors caused severe production failures:
  1. **Local resource exhaustion spin-loops:** `IOError.ResourceLimit` (`EMFILE`/`ENFILE`/`ENOSPC`) is NOT solved by immediate retry; marking it `transient() == true` recreates Go's infamous 100%-CPU `accept()` spin-loop.
  2. **Non-idempotent / ambiguous delivery corruption:** `ServiceError.Ambiguous` (`Core/Service/Service.jet:35`) explicitly means the remote side *may already have executed the operation*. Even `NetError.Timeout` or `NetError.ConnectionReset` during a non-idempotent POST/charge can cause double execution if retried blindly.
  3. **Caller cancellation & outer deadline loops:** `TaskFailure.Canceled`, `NetError.Canceled`, `HTTPError.Canceled`, and `IOError.Canceled` represent deliberate cancellation — retrying a canceled operation violates structured concurrency and hangs shutdown. Similarly, retrying after the *enclosing* `#Deadline` has expired (`TaskFailure.DeadlineBlown`) wastes work; only a per-attempt timeout (`NetError.Timeout`, `HTTPError.Timeout`, `IOError.TimedOut`) is transient, and the retry loop MUST check the enclosing `context.deadline` before sleeping/retrying.
  4. **Coarse Core error variants hide transience today:**
     - `DBError` (`Core/DB/DB.jet:171-175`) has only `Failed(String)`, `Exists`, `Denied` — transient `SQLITE_BUSY` / Postgres `40001` (serialization failure) / `40P01` (deadlock) are collapsed into the same `Failed(String)` variant as permanent SQL syntax or constraint errors!
     - `HTTPError` (`Core/HTTP/HTTP.jet:55-76`) covers transport/framing errors only; HTTP `429 Too Many Requests` and `503 Service Unavailable` are returned as `Ok(HTTPResponse)`, NOT `Err(HTTPError)`! Furthermore, `HTTPError.IO(operation)` is reused for static-file open failures (`Core/HTTP/Server.jet:969`, permanent `ENOENT`) as well as transient socket drops, and `HTTPError.Resolve(host)` conflates `NXDOMAIN` (permanent) with `SERVFAIL`/`EAI_AGAIN` (transient).
  5. **Retry storms without backoff/jitter/budget:** Blindly retrying `HTTPError.ResourceUnavailable` or `ServiceError.Full` across thousands of clients amplifies outages unless the retry policy mandates bounded attempts, exponential backoff with jitter, and deadline respect.
- **Required resolution:**
  - Define `transient()` with a **strict, documented, fail-closed contract**: "`true` means *the failure cause itself is expected to clear on a later attempt with backoff*, NOT that the caller's operation is idempotent." Default MUST be **`false`** on every error type (`Err`, `Describe` default, unknown/custom errors).
  - **Hard invariants across Core:**
    - `Canceled` (`NetError.Canceled`, `HTTPError.Canceled`, `IOError.Canceled`, `TaskFailure.Canceled`) -> ALWAYS `false`.
    - `ServiceError.Ambiguous` -> ALWAYS `false` (retrying requires an explicit idempotent recovery path, never blind retry).
    - `IOError.ResourceLimit` -> ALWAYS `false` (avoids Go #45729 `EMFILE`/`ENOSPC` spin-loop).
    - `NetError`: `true` ONLY for `.Timeout(_)`, `.ConnectionReset(_)`, `.ConnectionRefused(_)`, `.DNS(.Failure(_))`; `false` for `.InvalidInput`, `.PermissionDenied`, `.AddressInUse`, `.AddressUnavailable`, `.NotConnected`, `.Closed`, `.Canceled`, `.Unsupported`, `.TLS`, `.Protocol`, `.Other`, `.DNS(.NotFound(_))`.
    - `IOError`: `true` ONLY for `.TimedOut(_)`; `false` for all others (`NotFound`, `PermissionDenied`, `InvalidInput`, `Canceled`, `Closed`, `AlreadyExists`, `Unsupported`, `ResourceLimit`, `Protocol`, `Other`).
    - `HTTPError`: `true` ONLY for `.Timeout(_)`, `.Connect(_)`, `.ResourceUnavailable(_)`; `false` for all validation/framing/TLS/canceled/policy/IO/resolve errors unless `HTTPError` splits `Resolve` into `NotFound` vs `Temporary` (tracked as a Core cutover gap).
    - `ServiceError`: `true` ONLY for `.Unavailable(_)`, `.Partitioned(_)`, `.Full(_)`; `false` for `.Ambiguous`, `.Unknown`, `.NotStarted`, `.Policy`, `.Revoked`, `.Stale`, `.Expired`.
    - `DBError`: MUST add structured transient variant(s) (e.g. `Busy(String)` / `Unavailable(String)` / `Conflict(String)`) rather than regex-matching `Failed(String)`!
    - `AllocError`, `ParseError`, `EncodingError`, `CryptoError`, `RangeError`, `TextError`, `UTF8Error`, `SendError`, `TaskFailure`: ALWAYS `false`.
  - Document and enforce that `#Policy(retry(...))` (and Core `Retry` wrapper) checks the enclosing deadline/cancellation before every retry sleep and adds jittered backoff by default.

### Attack 2: `Err` Type Erasure Destroys Value-Dependent Transience
- **Claim attacked:** `Err` answers `transient()`, and Core errors propagate via `?` into default `Err` functions.
- **Attack:** Look at `Compiler/Prelude/Errors.jet:85-235`: `Err` is a concrete struct backed by the native `Err96` layout (`Compiler/JetBackend/Source/ErrLayout.jet:8-24`), strictly verified by `ir_default_err_drift` (`Compiler/JetIR/Source/BuildExpr.jet:5196`). Every Core conversion writes `impl NetError -> Err { return Err("{self}") }`. Today, `Err` does NOT dispatch `Describe` methods to its boxed `ERR_PAYLOAD` (`Core/Prelude/Prelude.jet:278-305`). If `Err.transient()` simply returns `false`, then ANY function with an unnamed `!` return contract (`fetch: fn() -[Net]> Data !`) loses transience the moment `NetError.Timeout` converts to `Err`, making `#Policy(retry(3))` silently stop retrying!
- **Resolution (Zero-ABI-Break Path Discovered in Live IR):**
  - Look at `Compiler/JetIR/Source/BuildTypes.jet:4064-4097` (`ir_err_payload_node`): every `source -> Err` conversion ALREADY allocates a ref-counted `ERR_PAYLOAD` node whose **word at offset 8 is unused (`zero`)**!
  - At `ir_try_convert_typed` (`BuildTypes.jet:4043-4062`), when `source` implements `Describe` (which every Core error type already does after P12), lowering can evaluate `source.transient()` once at conversion time and store that 1-bit flag in the `ERR_PAYLOAD` node's offset-8 word (or store an explicit `transient: Bool` bit in `Err` / `__jet_ErrorMetadata` if `Err` also supports manual `Err.transient(...)` construction).
  - For `?("while fetching rates")`, context-frame attachment mutates/copies the same `Err` handle while retaining `ERR_PAYLOAD` (`Compiler/JetRuntime/Source/Err.jet:171-173, 243-245`), so transience is **automatically preserved across `?("...")` breadcrumbs**!
  - For `Err{message: "...", cause: Val(inner)}` where the outer `Err` has no payload of its own: **needs Ballot Q1** on whether `Err.transient()` walks `self.cause` (returning `inner.transient()`) or requires opt-in/explicit propagation (walking `cause` is convenient for thin wrappers, but risks retrying when an upper layer intentionally converted a transient transport error into a permanent domain error!).

### Attack 3: `#Policy(...)` Overload — Lexical `.Tighten` Settings vs. Runtime Wrapping Calls
- **Claim attacked:** "`#Policy(retry(3, backoff: .exponential(100ms)), deadline(2s)) { … }` wraps a block" (`Docs/Proposals/2026-11-24-greenfield-language.md:430`), while `Compiler/Prelude/Markers.jet:30-39` declares `Policy` with `inherits: true, resolution: .Tighten, scopes: [.Package, .Module, .Function, .Block]`.
- **Attack:** `#Policy` is currently doing **two incompatible jobs** under one marker name:
  1. **Lexical compiler settings** (`#Policy(copies: .Explicit, failures: .Explicit)`, `#Policy(sentries: .Off)`): statically resolved outer-to-inner by `policy_resolve` (`Policy.jet:363-402`) under `PolicyCombine.Tighten`, where writing the same key twice in one scope is `PolicyError.Conflict` and loosening in an inner block is `PolicyError.Widening`.
  2. **Runtime execution wrappers** (`#Policy(retry(3), deadline(2s), trace("op"))`): dynamically wrap execution around a function or block body. They do NOT participate in `PolicyKey` / `PolicyCombine.Tighten` (for example, an inner block inside a retried function may legitimately have its own `#Policy(retry(2))` or `#Policy(trace("step"))`, and wrapping order is outer-to-inner, not lattice tightening).
  - Today this split already causes bugs: `Policies.jet:38-41` uses a 2-token heuristic (`IDENT LPAREN`) to guess whether file-level `#Policy(...)` is a file setting or a callable policy, `Policies.jet:70-75` flat-out rejects callable wrappers on blocks, `Policies.jet:145` forbids labeled args in `retry(3, backoff: ...)`, and `CallablePolicies.jet:6` silently skips built-in policy names!
  - **Seam with `#7004` (wrap role):** Under `#7004`, any marker struct implementing `wrap(self, call)` is a first-class wrapping marker (`#Retry(times: 3) { ... }`, `#Deadline(2s) { ... }`). `#Policy(w1(...), w2(...))` on a function or block is then merely sugar composing a chain of `wrap` markers outer-to-inner — OR `#Policy(...)` stays strictly for lexical compiler settings while wrapping markers are written directly (`#Retry(3) #Deadline(2s) { ... }` or `#[Retry(3), Deadline(2s)] { ... }`). **Needs Ballot Q5!**

### Attack 4: Control-Flow Escapes, Value Tails, and Outer Mutation Inside Wrapped Blocks
- **Claim attacked:** "Allow wrapping policies on blocks (P2's wrap role makes this the same code)" (`Docs/Proposals/2026-11-24-greenfield-language.md:436-437`).
- **Attack:** Wrapping a function body (`fetch: fn() -> R E!`) is easy because `return` inside the function body simply returns `R E!` from the closure passed to `wrap(call: fn() -[E]> R F!)`. Wrapping an **inline block inside a function** is fundamentally harder in three ways:
  1. **Escaping control flow (`return`, `break`, `continue`):**
     ```jet
     load: fn(items: [Item]) -> Result Err! {
         loop item in items {
             #Policy(retry(3)) {
                 if item.skip -> next
                 if item.stop -> return Ok(empty)
                 fetch(item)?
             }
         }
     }
     ```
     If `#Policy(retry(3)) { ... }` lowers to `retry(3).wrap(fn() { ... })`, then `next`/`break` cannot target the outer `loop`, and `return Ok(empty)` returns from the *closure* instead of `load` (changing program meaning silently unless either refused or lifted through a `ControlFlow` return envelope!).
  2. **Value-yielding block expressions:** Writing `data: #Policy(retry(3)) { fetch()? }` requires marked blocks to work in **expression position** AND propagate tail expressions (today `ValueTail.jet:89` and `Statements.jet:2508` only support `#Unsafe`, and `Expressions.jet:1151` parses `#Policy` as a value tag `Expr.Tainted`!).
  3. **Partial mutation of outer `^` locals across retries:** If the block captures `^count` or `^buf` by mutable reference (`buf.push(chunk); send(buf)?`), attempt 2 sees the mutated state left by failed attempt 1! Moreover, if `wrap` takes a `fn()` closure, Jet's own borrow/aliasing rules (`^buf` captured in a multi-call closure) interact directly with retry loops.
- **Resolution:** Requires **Ballot Q2** to lock the exact control-flow rule (refuse escaping `return`/`break`/`continue` in wrapped blocks with a dedicated diagnostic vs lift via `ControlFlow` envelope) and require uniform tail-value / expression-block parsing across all `.Block` markers.

### Attack 5: Grammar & Precedence Ambiguities Across Sites
Inspecting `JetParser` reveals **six concrete grammar ambiguities** that must be resolved before making markers uniform across all 21 sites:
1. **`#Name(args) expr` vs `#Tag (expr)` in expression position (`Expressions.jet:1252-1297`):** Today `#M(1) x` fails because expression markers never parse `(...)`. Disambiguation rule: just like `foo(x)` vs `foo (x)`, when `(` immediately follows `Name` with **no intervening whitespace** (`name.span.end == lparen.span.start`), `(args)` are the marker's arguments and the target expression follows `)` (`#M(1) x`); when whitespace separates `#Tag (a + b)`, `#Tag` has zero arguments and `(a + b)` is the target expression! (Or if `)` is followed by a non-expression token, `#M(1)` is a standalone expression marker like `#Todo`? Wait: if `#M(1)` has no target expression, reject unless it is a freestanding expression like `#Todo`!)
2. **Expression-marker postfix/unary/binary precedence (`Expressions.jet:1289-1296`):** Today `#Tag xs.len()` parses as `#Tag (xs.len())`, while `#Tag [1, 2].len()` parses as `(#Tag [1, 2]).len()` and `#Tag -x` parses as `#Tag (-x)` and `#Tag a + b` parses as `(#Tag a) + b`. **Fix:** Unify expression markers at **unary-prefix precedence** wrapping a full `postfix` expression (`parser_parse_prefix` already calls `parser_parse_postfix` on its atom, so removing the ad-hoc `if named && inner.expr == .Ident` hack in `Expressions.jet:1292` makes `#Tag xs.len()`, `#Tag [1, 2].len()`, `#Tag (a + b).len()`, and `#M(k) foo().bar` all parse uniformly as `#M (postfix)` while `#M a + b` stays `(#M a) + b`!).
3. **Statement head: `#Marker expr` vs `#Marker stmt` vs `#Marker x: val` vs `#Marker { ... }` (`Statements.jet:579, 2449-2506`):** Today the parser guesses by hardcoded marker name (`Todo`, `Track`, `Meta`, `Local`, `Shared`, `Allow`, `Off`, `On`). **Unified syntactic rule (independent of marker name!):**
   - Parse the full marker prefix list (`#M`, `#M(args)`, `#m.M`, `#[A, B]` — zero or more, skipping ASI newlines between stacked markers and their target).
   - Inspect what follows the marker prefix:
     - `{ ... }` -> **`RuleSite.Block`** (and in expression position, a marked block expression!).
     - Local binding (`name: ...` or `^name: ...`) -> **`RuleSite.Declaration`**.
     - Statement keyword (`loop`, `return`, `break`, `continue`, `defer`, ...) -> **`RuleSite.Statement`**.
     - Expression statement (`expr` followed by `;`/newline) -> **`RuleSite.Statement`** (or if the marker declares `.Expression` and not `.Statement`, e.g. `#Tag foo()` or `#ExprMark foo()`, attach to the leading expression / resolve unambiguously via Sema site check, with `#Todo` remaining a standalone expression literal!).
4. **`TypeUse` precedence (`Types.jet:368-373`):** Today `#Secret String | Int` calls `parser_parse_type`, capturing the whole union `#Secret (String | Int)`. Calling `parser_parse_type_atom` instead makes `#Secret String | Int` parse as `(#Secret String) | Int` and `#Secret String?` parse as `#Secret (String?)` (matching `?` tightness), while allowing qualified `#mod.Tag T`, `#M(args) T`, and `#[A, B] T`!
5. **Top-level `File` vs first item (`Entry.jet:1706-1712, 1908-1960`):** Currently only `NoPrelude`, `Target`, `HTML`, `#FX` before `use`, `#Policy(...)` before `;`/EOF, and EOF markers become `RuleSite.File`. Any user marker with `sites: [.File]` written at the top of a file before a `fn` or `struct` is misattached to that item. **Fix:** Either support a blank-line / `use`-prefix rule OR let Sema check whether a marker at file start declares `.File` (and NOT the following item's site) — or adopt a single explicit file-marker rule (e.g. before `use`, or detached by a blank line / file header, checked consistently in `Entry.jet`).
6. **`Arm` prefix vs postfix (`Statements.jet:1222-1235`):** `#Through` is postfix (`1 -> { a() } #Through`), whereas every other marker in Jet is prefix. Supporting prefix markers before an arm (`#MyArm 1 -> ...`) while preserving postfix `#Through` (already documented in `Core/Prelude/Prelude.jet:625` and `Compiler/Prelude/Markers.jet:447`) keeps backwards compatibility while unblocking `.Arm` markers.

### Attack 6: Stacking, `#[A, B]` Groups, and AST Representation
- **Claim attacked:** Markers apply uniformly at every site they declare.
- **Attack:** Today `#[A, B]` marker groups and multi-line marker stacking work ONLY on top-level/member items (`Func`, `Struct`, `Enum`, `Trait`, `Impl`, `Field`, `Variant`, `Module`). Writing:
  - `#[Deadline(2s), Frame("load")] { ... }` (block),
  - `#Allow(Jet.X) #Off(.Release) debug_check()` (statement),
  - `#Root #Web.ColumnOf(User) id: Int` (parameter),
  - `#Allow(Jet.X) #Test("...") { ... }` (test),
  - `#[Secret, PII] String` (type use)
  all fail to parse or silently drop markers! Furthermore, `Param`, `TestDef`, `SwitchArm`, `Stmt`, and `Expr` do not carry uniform `markers: [Marker]` lists, forcing Sema and `JetFormatter` (`Formatter.jet:2642`) to reconstruct marker attachment indirectly from `state.statement_rules` spans.
- **Resolution:** Introduce one shared `parser_parse_marker_prefix` helper returning `[Marker]` (supporting `#M`, `#M(args)`, `#m.M`, `#!M`, and `#[A, B]`) used uniformly at blocks, statements, declarations, parameters, tests, arms, expressions, and type uses, and attach `markers: [Marker]` directly on `Param`, `TestDef`, `SwitchArm`, `Stmt.MarkedBlock` / `Stmt.Marked`, and `Expr.Marked` so `MarkerRules` validates every site through one table without per-marker drops.

### Attack 7: Phantom Sites (`Site.Operation` and `Site.Text`)
- **Claim attacked:** "Markers apply at every site they declare" across the 21-site `Site` enum.
- **Attack:**
  - `Site.Operation` is declared ONLY by `Unsafe` (`Compiler/Prelude/Markers.jet:68`) and has **zero** parser syntax or Sema emission.
  - `Site.Text` is declared by **zero** markers anywhere in `Compiler/` or `Core/` and has **zero** parser syntax or Sema emission.
  - Leaving unparseable variants in the public `Site` enum means a user can legally write `impl Marker { sites: [.Operation] }` or `impl Marker { sites: [.Text] }`, pass registration cleanly, and then have **no syntactic position in the language** where the marker can ever be applied!
- **Resolution:** **Ballot Q4** — either give `Operation` and `Text` real, specified grammar and Sema lowering, or retire `Site.Text` and fold `Operation` into `Expression` so 100% of `Site` variants are live, parseable, checkable, and reflection-accessible.

## 6. Owner Ballots Required (`NEEDS BALLOT`)

### Q1 — `Err.transient()` Surface, `Describe` Integration, and Cause-Chain Propagation
Where does `transient()` live, and how does `Err` answer it after type erasure?
- **Option A (Recommended):** Add defaulted `transient: fn(self) -> Bool Never! { false }` to `Describe` (`Core/Prelude/Prelude.jet:175-178`, matching proposal §3.7), implement conservative fail-closed overrides on Core error types (`NetError`, `IOError`, `HTTPError`, `ServiceError`, plus new structured transient variant(s) on `DBError` — NEVER `true` for `Canceled`, `ResourceLimit`, or `ServiceError.Ambiguous`), and capture `source.transient()` into the unused offset-8 word of `ir_err_payload_node` during `source -> Err` conversion (`BuildTypes.jet:4043-4097`, zero `Err96` ABI break). For `Err` with an explicit `cause` and no direct payload, default `Err.transient()` to `false` unless explicitly constructed via `Err.transient(...)` (or `err.with_transient(true)`), while `?("note")` preserves the original `Err`'s payload transience automatically.
- **Option B:** Same as Option A, except `Err.transient()` also walks `self.cause` when `ERR_PAYLOAD == 0`, returning `true` if any cause is transient. (Convenient for manual `Err{message: "...", cause: Val(e)}`, but risks accidentally retrying when a higher layer intentionally wrapped a transient error into a permanent domain error.)
- **Option C:** Keep `Describe` purely textual (`public()`, `detail()`), put `transient()` as a separate optional trait `Retryable` / method on `Err` only. (Diverges from proposal §3.7 `impl LoadError.Describe` and requires a second trait bound on generic retry wrappers.)

### Q2 — Escaping Control Flow & Outer Mutation in Wrapped Blocks (`#Policy(...) { ... }` / `#7004` Wrap Seam)
When a wrapping policy or `#7004` `wrap` marker wraps an inline block `{ ... }` (lowered as `wrapper.wrap(fn() { body })`):
- **Option A (Recommended):** Refuse escaping `return`, `break`, and `continue` inside a wrapped block with a clear compile error (same lexical boundary as a lambda), allow tail-value expressions (`x: #Policy(retry(3)) { fetch()? }`) via uniform expression-block parsing and `ValueTail` propagation, and emit a tidy/warning lint if a multi-attempt `retry` block mutates an outer `^` local across attempts (or disallow outer `^` writes when the wrapper closure is callable more than once).
- **Option B:** Lower escaping `return`/`break`/`continue` through a compiler-synthesized `ControlFlow` envelope across `wrapper.wrap(...)` so `return` inside `#Policy(retry(3)) { ... }` exits the enclosing function cleanly. (More ergonomic, but complicates `#7004` `wrap` signatures because `wrap` sees `ControlFlow<Ret, Val>` instead of plain `R`.)

### Q3 — Expression-Site Marker Syntax & Precedence (`#M(args) expr` vs `#Tag expr`)
How should `JetParser` distinguish `#Marker(args) expr` from `#Tag (expr)` and set precedence?
- **Option A (Recommended):** Parse full marker prefix syntax (`#Name`, `#m.Name`, `#Name(args)`, `#[A, B]`) at expression prefix position using **no-space attachment** for marker arguments (`name.span.end == lparen.span.start` parses `(args)` as marker args; whitespace `#Tag (a + b)` treats `(a + b)` as the parenthesized target expression). Unify precedence at **unary-prefix over postfix** (`#M a.b().c` -> `#M (a.b().c)` for ALL postfix atoms including `[1, 2].len()`, while `#M a + b` -> `(#M a) + b`). Emit `RuleSite.Expression` (or `RuleSite.TypeUse` for value-tag sites) uniformly in Sema instead of forcing every `#Name expr` into `Expr.Tainted`.
- **Option B:** Restrict expression-site markers to parenthesized target syntax `#M(args)(expr)` or block-only `#M(args) { expr }`, keeping `#Name expr` exclusively for zero-argument value tags. (Simpler parser, but breaks the claim that arbitrary markers apply cleanly at `.Expression`.)

### Q4 — Phantom Sites `Site.Operation` and `Site.Text`
What should happen to the two unimplemented variants in `Core/Prelude/Prelude.jet:619-620`?

- **Option B:** Keep all 21 variants and specify concrete grammar + Sema rules for both `.Operation` (single unchecked operation prefix `#Unsafe("reason") *ptr`) and `.Text` (marker prefix on a string / checked-text literal `#M "text"`).

### Q5 — `#Policy(...)` Split vs. Direct Wrapping Markers (`#7004` Seam)
Should `#Policy(...)` continue to host BOTH lexical compiler settings (`copies: .Explicit`) AND runtime wrappers (`retry(3)`), or should they be separated?
- **Option A (Recommended — aligns cleanly with `#7004`):** Keep `#Policy(retry(...), deadline(...))` working on BOTH functions and blocks for proposal P13 parity, **forbidding** mixing lexical `PolicyKey` settings and runtime wrapper calls in a single `#Policy(...)` invocation (distinct diagnostic), allowing labeled arguments (`retry(3, backoff: .exponential(100ms))`), routing runtime wrapper chains on both functions and blocks through the `#7004` `wrap` role (`outer(inner(body))`), and allowing nested `#Policy(retry(...))` blocks to compose cleanly without triggering `PolicyError.Conflict`. Simultaneously allow direct wrap markers (`#Retry(times: 3) { ... }`) once `#7004` lands.
- **Option B:** Keep `#Policy(...)` strictly for lexical compiler settings (`PolicyKey` under `.Tighten`), deprecate/migrate callable `#Policy(retry(3))` to direct `#7004` wrap markers (`#Retry(3) { ... }`, `#Deadline(2s) { ... }`, `#[Retry(3), Deadline(2s)] { ... }`).
