## 4. Stated Limits & Implementation Guardrails (Binding for Slices 1–3)

These four narrow guardrails do not block `#6796 c1` approval, but must be honored during implementation:

1. **Tighten `TOKEN_IDENT` head check (`Entry.jet:417–419, 632`):** Accept `TOKEN_IDENT` as a chunk head **only** when followed by `TOKEN_COLON` or `TOKEN_COLON_EQ` (matching `Chunks.jet:131` and `Entry.jet:1209` `parser_module_binding_ahead`), never bare `TOKEN_IDENT`, so top-level script statements (`Entry.jet:1230–1236`) are never split mid-script.
2. **CRLF safety on `cut - 2 == '}'`:** In `Chunks.jet:123–153, 294–302`, either record `rbrace_pos` explicitly for `}\r\n` or decline CRLF boundaries so Windows-EOL inputs never violate `source[cut - 2] == '}'` or shift `TOKEN_SEMI` spans.
3. **Zero-copy `source` representation & empirical Amdahl verification (`State.jet:104`, `Entry.jet:749–752`):** Because `JetParserState.sources` is an owned `[[U8]]` field (and `View<U8>` cannot be stored inside a struct field without threading `source: View<U8>` through parser calls), Slice 1 must either pass `View<U8>` outside `JetParserState` or pass per-chunk `source.slice(chunk_start, chunk_end)` with a `source_offset` base (`1×` total bytes across 16 workers instead of `16×`, with chunk-local `line_starts`). Slice 1 must verify empirically that residual serial work (`name_pool_adopt`, `parser_join_effect_impls`, chunk merge) plus allocator contention stay `< 6.7%` of 1-thread wall time so 16t reaches `>= 8×` on both `Core/Math/Math.jet` and `Statements.jet` (falling back to per-chunk arena pre-reservation if allocator contention caps scaling below `8×`).
4. **Greenfield `Lanes<U8, N>` cutover & Jet `-O2` codegen proof (`c5`):** Under `D-LANES1=A` (`tower.json:85550–85551`), Slice 2 must not keep legacy `U8x16`/`U8x32` as permanent aliases alongside `Lanes<U8, N>` (migrate in one cutover per greenfield law). And because the `0.110–0.112 ns/B` cold probe is C (`jet cc -O3`), Slice 3 must verify `<= 1.0 ns/byte` on the actual Jet-compiled `Classify.jet` via `JET_TRACE_FILE` on the self-host unit.
