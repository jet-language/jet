## What bears on Jet

These are the lessons the claims support, each with the claim ids that carry
it. They are evidence for decisions, not decisions.

- **Data stacks instead of a heap (Goose).** Every growable value lives on one
  of N compiler-assigned data stacks: an address-space reservation with a bump
  pointer, at most one resizable value live per stack and always on top, and
  scope exit frees everything above a saved mark in one store
  (goose-001, -019, -023, -063, -064, -173, -180, -182). The survey finds no
  precedent for assigning growable values to stacks by liveness, as registers
  are assigned (goose-145).
- **What that model costs (Goose, its own record).** Recursion is opt-in and
  may not call back into its cycle while a growable local is live, so the stack
  count stays a compile-time constant (goose-048, -053). Resizable values may
  not be array elements, and only one is allowed per struct (goose-024).
  References into a stack-top array are second-class (goose-040). Constructing
  in place forces layout-order evaluation and memmoves for some exits
  (goose-085, -185, -187). The model needs virtual-address reservation; on
  WebAssembly every growth site needs a capacity check, at an estimated 1.1x
  to 1.5x cost (goose-143). Sanitizers can't see object bounds inside a data
  stack (goose-166). Specialization keys on roots, stacks and placements and
  needs a finite, whole-program instantiation set (goose-051). The
  annotation-free root analysis grew to about 5,000 lines and caused about
  half of recent compiler churn (goose-146).
- **Prior region systems retreated (Goose's own survey).** The ML Kit added a
  garbage collector for what region inference leaks; Cyclone kept LIFO arenas
  only where callers know lifetimes (goose-144).
- **Layout.** Packed structs by default measured as costing nothing in Goose's
  suite (goose-022, -065, -118). Narrow array metadata, 1-byte ADT tags,
  fixed and variable ADT modes (goose-005, -025, -026). Relative and
  pool-relative references stored as narrow offsets, which serialize as bytes
  (goose-006, -007, -031, -124).
- **Checks and placement as checked properties.** `checkfree` functions that
  fail the build when any bounds check survives, and report every kept check
  with its reason (goose-057, -195). In-place result construction is part of a
  function's checked summary, not an optimizer outcome (goose-009, -035,
  -126).
- **Lobster.** Compile-time reference counting, which elides most count
  operations by ownership analysis, and its whole-program inlining and
  specialization; see the Lobster claims below.

## Claims

Each row: id, stance, topic, the claim, and its locator in the source at the
revision above.

- **goose-001** (neutral, `goose-data-stack-memory-model`, README.md:5-17,29-31,78-93): Goose replaces the heap with N data stacks whose count the compiler derives; each is an address-space reservation with a bump pointer, at most one resizable value is live per stack and always on top, so growth never moves or checks capacity and scope exit frees everything above a saved mark in one store.
- **goose-002** (neutral, `goose-stable-references-under-growth`, README.md:32-34,95-108): Because a grow-only array is the only resizable value on its stack and growth never relocates it, push can return a reference to the new element that stays valid for the array's lifetime; the README credits this for several benchmark gains over C++ reserve() and Rust u32 indices.
- **goose-003** (supports, `goose-root-inference-no-annotations`, README.md:36-38,110-133,230-232): Goose gives every reference and slice a static root variable, infers roots without annotations, specializes functions per root, and has no aliasing or exclusivity rules; references are transparent and .= rebinds.
- **goose-004** (neutral, `goose-inline-variable-size-layout`, README.md:39-42,135-169): Goose arrays are one family [metadata][elements] stored inline (fixed, sized-at-construction, inline-capacity, grow-only, grow-shrink) and structs may hold variable-size fields inline in declaration order; a nested Order record is 29 bytes and 0 allocations versus 160 B/1 alloc in C++ and 153 B/4 allocs in Rust, at the cost that arrays of variable-size elements cannot be indexed.
- **goose-005** (neutral, `goose-adt-fixed-and-variable-mode`, README.md:43-45,171-203): Every Goose ADT can be stored in fixed mode (tag plus room for the largest payload, indexable and overwritable) or variable mode (exact variant size, sequential, never changes variant, references into payloads allowed), chosen at the point of use; case functions dispatch per variant through a jump table with exhaustiveness checking. The README reports 4x less memory and 2x speed versus a Rust enum on one benchmark.
- **goose-006** (supports, `goose-relative-references`, README.md:46-50,204-229): Goose relative references store a typed link as a 1/2/4-byte offset, either self-relative within the same array (T&<u32>) or relative to a named pool's base (T&<u32 in pool>), with offset 0 as null; a BST node with two links is 12 bytes.
- **goose-007** (supports, `goose-data-is-file-format`, README.md:51-53,238-251): Self-relative Goose structures serialize by writing their bytes; from_bytes verifies framing, every tag, every length and every link before the bytes become a value, so hostile input yields false and an empty value rather than a wild reference.
- **goose-008** (neutral, `goose-reusable-pool-type-stable`, README.md:232-236,409-410): For non-nested lifetimes Goose offers a reusable pool (grow-only array plus hidden freelist); free hands a slot back but memory is never released, so a stale reference reads a different value of the correct type: a logic bug, never memory corruption.
- **goose-009** (neutral, `goose-in-place-construction-guarantee`, README.md:54-57,253-266): Goose guarantees a constructed value is built in its final destination, propagated top-down through any depth of calls, so items.push(parse(line)) writes the parsed record into the array slot and returning a growable array by value costs nothing.
- **goose-010** (neutral, `goose-return-from-outer-call`, README.md:58-60,268-295): return E from f returns from the innermost active call of f however many frames up, statically checked so every caller path lies inside f, lowered as a hidden discriminant checked per frame rather than an unwinder.
- **goose-011** (neutral, `goose-compile-time-function-values`, README.md:61-64,297-322): Goose function values are compile-time generic parameters: every call is direct and inlinable, they cannot escape, there are no closure objects or function pointers, and a block can return from its enclosing function, so xs.filter() { it > 0 } compiles to the loop and builds its result straight into its destination.
- **goose-012** (supports, `goose-share-nothing-threads`, README.md:65-67,324-343): A Goose thread_fn and everything it calls is compiled as its own program with its own data stacks and global copies; values cross through one typed queue per type and must be flat (no references at any depth), so crossing is a memcpy and the language has no shared mutable memory, locks, atomics or orderings.
- **goose-013** (supports, `goose-contained-worker-failure`, README.md:345-359): thread_spawn_contained makes a failed check or abort end only that worker, delivering its message to the first thread_wait caller so a supervisor loop can log and restart.
- **goose-014** (supports, `goose-bounds-check-elimination-reporting`, README.md:375-384): Goose bounds-checks every index, removes provable checks, lets an assert on a slice length eliminate the rest and enable vectorization, reports surviving checks per line with --bce-lines, and lets checkfree fn reject a kernel if any check survives; index types keep validation done at construction.
- **goose-015** (neutral, `goose-benchmark-geomean`, README.md:24-28,386-394): Over 16 benchmarks Goose reports geometric-mean speed of 3.51x idiomatic C++, 1.24x hand-optimized C++ and 1.13x best safe Rust (MSVC backend; 3.54x/1.26x/1.19x with clang) and 1.95x/1.32x/1.25x less peak memory, measured as whole-process wall time including teardown.
- **goose-016** (disputes, `goose-costs-and-restrictions`, README.md:396-411,586-594): Goose's stated costs: programmers decide where data lives; recursive functions cannot keep growable data across a recursive call; arrays of variable-size elements do not index; fixed enums cannot be pointed into and variable ones cannot be overwritten; no escaping closures, function pointers or dynamic dispatch beyond ADT tags; whole-program compilation only; no moves for resizable values and at most one resizable per struct.
- **goose-017** (neutral, `goose-provenance-ai-built`, README.md:586-635): Goose is new (about 30K lines of C++), produced almost entirely by an AI implementer from the author's design, with the compiler structured after the author's Lobster compiler; there is no adoption or migration evidence yet.
- **goose-018** (neutral, `goose-c-backend-ffi-packaging`, README.md:69-71,361-373,476-531): Goose emits one C file per program plus a separately compiled runtime C file, binds C through extern fn with slices crossing as {data,len} and unsupported signatures rejected at the declaration, runs in-process through bundled TinyCC (which cannot place thread-local storage, so threaded programs need goose build), and builds packages from git tags once per C compiler.
- **goose-019** (neutral, `goose-data-stack-reservation-sizing`, README.md:496-501): Every Goose data stack reserves 2 GB of address space committed as used; --stack-reserve changes it, --stacks reports how many stacks the program and each worker take and the resulting cap on hardware_threads(), and GS_STACK_STATS reports actual use at exit.
- **goose-020** (disputes, `goose-debug-only-overflow-checks`, README.md:488-495): Goose turns on overflow, range and tag checks in the generated C only under --debug; builds default to -O2 and in-process runs to -O1.
- **goose-021** (supports, `goose-exact-width-integer-arithmetic`, goose_spec.md §3.1, §6.2): Goose integer types i8..u64 are usable in every position and every operation computes at its operands' exact width without C-style promotion, so an i32 or u8 loop stays in 32- or 8-bit registers end to end and backends vectorize it; untyped literals and named constants adapt to any type whose range holds them, and varint is a storage-only width decoding to i64.
- **goose-022** (neutral, `goose-packed-structs-by-default`, goose_spec.md §3.2, Appendix C.2): Goose structs are packed by default with no automatic padding (i8[3] + i32 is 7 bytes) on the premise that unaligned access is cheap on current hardware; pad n and bare pad restore foreign alignment explicitly.
- **goose-023** (neutral, `goose-stack-invariant-rules`, goose_spec.md §1.1-1.3): Goose's stack invariant: lifetimes on one data stack are strictly nested; at most one resizable is live per stack and it is always topmost, with its length header below its elements or in the owning frame; while a value is under construction on a stack nothing else allocates there; variable values may be buried once complete; disjoint-lifetime locals reuse stacks; guard pages abort overflow; trim_memory returns unused pages.
- **goose-024** (neutral, `goose-placement-rules-resizable-tail`, goose_spec.md §3.3 members, §3.4): Goose restricts resizable values to locals, globals, by-value parameters, returns, the final field of a struct and variable-ADT payloads, never array elements, with at most one per struct; growth always supplies element values; shrinking a grow-only array is legal only where no reference into it is visibly live; index_of on an exactly rooted reference needs no runtime check.
- **goose-025** (neutral, `goose-narrow-array-metadata`, goose_spec.md §3.3 table): Goose sizes array metadata to need: T[k] stores nothing, T[] a u32 length by default, T[u8]..T[u64] or T[varint] a chosen width, T[..k] only a length in the smallest int fitting k; an over-range length is rejected statically or aborts, never producing a disagreeing image.
- **goose-026** (supports, `goose-adt-mode-soundness`, goose_spec.md §3.5): Goose ADTs use the smallest tag type that fits the variant count (1 byte by default) and keep soundness by allowing either in-place variant replacement (fixed mode, no interior references) or interior references (variable mode, no replacement), never both, citing Grossman's existential-types result.
- **goose-027** (neutral, `goose-varint-storage-type`, goose_spec.md §3.6, §3.1): Goose's varint is a storage-only integer (canonical LEB128, unsigned for lengths and pool offsets, zigzag-signed elsewhere) chosen by measurement for usually-small values with outliers; it is written only at construction, never byte-copied across encodings, and makes its container variable-size.
- **goose-028** (disputes, `goose-strings-as-byte-arrays`, goose_spec.md §3.7): Goose has no string type: any u8 array is a string, literals are static const u8[:] data, and no encoding is enforced (UTF-8 is a library convention), so one array family serves builders, finished strings, small inline strings and views.
- **goose-029** (supports, `goose-size-class-binding`, goose_spec.md §3.8 binding contexts, §4.1): In Goose an inferred binding copies a fixed-size value but binds a non-fixed lvalue by reference (let w = words[0] names the element), so large or variable values are never implicitly copied by a let.
- **goose-030** (supports, `goose-optional-as-nullable-reference`, goose_spec.md §3.8 Optionals): Goose's T? is a nullable reference to existing T storage (null = address 0, no space cost) for every T, including i64?, narrowed by flow typing; an optional never allocates.
- **goose-031** (supports, `goose-relative-reference-rules`, goose_spec.md §3.9): Goose relative references (widths u8..u64 or varint) are storage-only: loads yield plain references, stores re-encode; self-relative stores need the reference and destination to share one exact root and copies of values holding them are compile errors; pool-relative links (target - base + 1, 0 = null) are copyable, typed by their pool, and usable as indices; the store-time range check is elided when the region's reservation fits the width; self initializers make null-free sentinel links whose load is one add.
- **goose-032** (supports, `goose-index-types`, goose_spec.md §3.11): Goose index types (u32 in a: below a.len) and bound types (u32 upto a) tie an integer to a named global grow-only array; the conversion x as (u32 in a) is checked once in every build, indexing a with one needs no check, loops over index bounds yield index types, and the named array may never shrink so the proof stays true wherever the value travels.
- **goose-033** (neutral, `goose-explicit-copy-of-nonfixed`, goose_spec.md §4.1): Goose copies fixed-size values silently but never copies a variable-size or resizable value implicitly: storage binds by reference or is an error at a value destination, and copy(x) spells the O(size) cost; the only ownership transfer is the return move, and deallocation is only scope exit (no destructors, Drop or refcount).
- **goose-035** (neutral, `goose-construction-contexts-and-placement`, goose_spec.md §4.2-4.3): Goose creates non-fixed values only at construction contexts whose storage is statically known (let/var init, by-value argument slot, return, push/append, field of a value under construction), writes metadata first then parts in order, forbids growing the receiving array during construction, and makes result channels name the receiving storage through calls, selected branches and nonlocal returns without depending on inlining; varint length prefixes may be relocated once their width is known.
- **goose-036** (disputes, `goose-whole-assignment-restrictions`, goose_spec.md §4.4): Whole assignment of a Goose resizable is clear-then-construct in place, so its right-hand side may not read the array (x = f(x) and x = [x[1], x[0]] are errors; build in another variable and copy), and variable-class values (T[], variable-mode ADTs, varint fields) are frozen after construction and must be rebuilt to change.
- **goose-037** (supports, `goose-structural-equality-lowering`, goose_spec.md §4.5): Goose defines == memberwise with pad bytes excluded and allows memcmp lowering only for gap-free layouts without floats (since -0.0 == 0.0 and NaN != NaN); references compare pointees at top level and identity inside composites to avoid unbounded traversal.
- **goose-038** (supports, `goose-shrink-safety-analysis`, goose_spec.md §5.1): Goose's grow-only shrink check is a flow-sensitive, annotation-free borrow check: a shrink is legal where no live reference, slice, in-construction value or holder roots into the array; liveness is syntactic and optimizer-independent with dead-after-last-use references allowed; holders are tracked exactly per store and errors name the holder and the store line; each function specialization exports summaries of the globals and parameter pointees it shrinks and stores into, checked at every caller, with globals judged after the whole program.
- **goose-039** (neutral, `goose-safety-rule-complexity`, goose_spec.md §5.1, §4.4): Goose's no-annotation safety pushes its complexity into the rules themselves: the shrink and whole-assignment sections run several pages of interacting conditions (holders, emptied parts, inexact roots, recorded parameter pairs, whole-program judgment of globals).
- **goose-040** (supports, `goose-second-class-stack-top-refs`, goose_spec.md §5.2): References and slices into a Goose grow-shrink (stack-top) array are second-class: they live only in variables, arguments and returns and are never stored, so a shrink is checked by scanning the live variables in scope and the diagnostic names the variable and its binding line.
- **goose-041** (supports, `goose-balanced-calls-mark-release`, goose_spec.md §5.2 Balanced calls): Goose treats a call as no shrink when it is balanced for an array: every shrink it makes is resize back to a let mark taken from the same array's length at entry (or a balanced call), so callees can push scratch onto a caller's stack and pop it back while the caller's views stay valid; recursion is judged by induction once the cycle is checked.
- **goose-042** (disputes, `goose-type-safe-pools`, goose_spec.md §5.4): Goose's reusable pools pair a grow-only array with a hidden freelist (slots or merged spans); a freed slot remains a valid value of its type, so a stale reference or index reads another same-typed value but never corrupt memory, and frees are bounds-checked in every build; slice pools grow runs in place where adjacent space allows.
- **goose-043** (supports, `goose-syntactic-nonnegative-compare`, goose_spec.md §6.1 Comparisons and u64): Goose allows comparing u64 with a signed value without a cast exactly when the signed operand is syntactically non-negative (a literal, .len, .cap, or an unaliased let of one), compiling to a single unsigned compare, and makes acceptance depend only on the written code, never on optimizer proofs.
- **goose-044** (neutral, `goose-elementwise-aggregate-math`, goose_spec.md §6.1 Elementwise math): Goose applies + - * / % memberwise to two values of one struct or fixed-array type whose numeric leaves are uniformly integer or float, and * or / with one scalar when all leaves share a type, giving vector math (float3) without operator overloading.
- **goose-045** (supports, `goose-euclidean-mod-bce`, goose_spec.md §6.2): Goose's % is Euclidean at every integer width, so x % n is always in [0, n) and indexing a length-n array with it needs no bounds check; the signed cost is one predictable conditional add on an operation that already divides.
- **goose-046** (supports, `goose-narrow-width-literal-adaptation`, goose_spec.md §6.3): Goose's conversions are implicit exactly where value-preserving, and float literals plus literal-derived float expressions adapt to the destination's f32 or f64 and compute at that width throughout, so f32 kernels stay 32-bit without casts; checked conversions (as) are range-checked only in debug while float-to-int is defined (truncate, wrap, NaN to 0).
- **goose-047** (supports, `goose-narrow-loop-counters`, goose_spec.md §6.5, §10.4): Goose loops run at the bounds' type (an i32 range gives a 32-bit counter), allow an end one past a narrow type's maximum without counter overflow (for i: u8 in 0..256), and allow a narrow index type for an array only where every possible index fits, since lengths are capped at 2^48-1.
- **goose-049** (neutral, `goose-multi-return-calling-convention`, goose_spec.md §7.1 Multiple return values): Goose has no tuple type: multiple return values are a calling convention, and each non-fixed result gets its own construction destination (possibly on a different stack).
- **goose-050** (supports, `goose-guaranteed-nrvo-destination-requests`, goose_spec.md §7.3): Goose guarantees NRVO when every return of a non-fixed result returns the same local, warns where a return forces a copy, builds other returns behind the local and moves them down, and compiles callees against a destination request (one value or an element run for append) that is part of the specialization signature, so returning a built value costs the same as an out-parameter.
- **goose-051** (disputes, `goose-specialization-key-breadth`, goose_spec.md §7.4, §7.7, §10.2): Goose monomorphizes on far more than types: reference roots, writability provenance, static function values, free-variable placement and destination stacks, falling back to hidden arguments or fat references when one body must serve several stacks; it requires the instantiation set to be finite and whole-program.
- **goose-052** (supports, `goose-captures-as-hidden-ref-params`, goose_spec.md §7.5-7.6): Goose lowers nested functions and block literals by turning free variables into hidden reference parameters; because function values can never be stored or returned, every call can pass them, and once inlined into the HOF the parameters vanish, leaving a plain loop.
- **goose-048** (disputes, `goose-recursion-annotation-and-stack-count`, goose_spec.md §7.8): Goose makes recursion opt-in (recursive fn on each cycle entry, full signatures) and forbids any call back into the cycle while a non-fixed local, by-value non-fixed parameter or non-fixed temporary of the activation is live, so the number of data stacks is a compile-time constant; recursive code must hoist values, pass scratch from outside the cycle with mark/resize(mark), or build into a caller-owned buffer.
- **goose-053** (neutral, `goose-recursive-cycle-root-rules`, goose_spec.md §7.8 Cycle store rule, Cycle return roots): Inside a Goose recursive cycle, references rooted at an activation's locals may be passed down but not stored or returned, references rooted outside the cycle store freely (pools must be passed by the same reference at every back edge), and the roots of back-edge results are found by iterating rounds to a fixpoint.
- **goose-054** (supports, `goose-return-from-discriminant-lowering`, goose_spec.md §7.9): Goose lowers return E from f by giving every function between the target and the return site a hidden return discriminant (an enum when several targets exist) that each caller tests and propagates, with normal epilogues and the value built in f's call-site destination: no unwinder, no tables, no destructors.
- **goose-055** (supports, `goose-c-ffi-shapes-and-builders`, goose_spec.md §7.10): Goose's C boundary passes only flat shapes (scalars, packed flat structs by value, T& as pointer, T[:] as {data, len}) plus one growable form, u8[>..]& as a builder handle C may only append to; references inside structs, varints, optionals and non-fixed values by value are rejected at the declaration; generated names carry a _g suffix so no C keyword or header name can clash.
- **goose-056** (supports, `goose-simd-multiversioning`, goose_spec.md §7.12): Goose's simd fn compiles a function for the baseline ISA and each wider one (AVX2, AVX-512) and dispatches per call to the widest available, with every version required to compute exactly what the baseline does (no FMA contraction, same checks), so output never depends on the CPU.
- **goose-057** (supports, `goose-checkfree-minimum-proof-set`, goose_spec.md §7.14): Goose's checkfree fn rejects the program if any bounds or index-type check survives BCE in any specialization, SIMD version or inlined copy, requires every callee to be checkfree, a builtin or extern, and fixes a minimum set of facts every implementation must prove (constant index, index types, asserted length relations with no intervening growth/shrink, for-loop indices, condition-established ranges, repeated checks), so acceptance is portable across implementations.
- **goose-058** (neutral, `goose-case-function-dispatch`, goose_spec.md §8.2): Goose lets each case of a match be a separate overload taking one variant type; calling the set with the ADT dispatches on the tag through a jump table with match-level exhaustiveness, giving virtual-function style code without vtables or inheritance in a closed world.
- **goose-059** (disputes, `goose-no-exclusivity-rule`, goose_spec.md §9.1): Goose's entire borrow checker is one outlives-and-type rule: it has no lifetime annotations and no aliasing or exclusivity restrictions, justified by the absence of shared-memory concurrency and by layout rules that keep aliased writes type-safe.
- **goose-060** (neutral, `goose-root-rules-and-readback`, goose_spec.md §9.2, §9.5 Read-back roots): Goose checks references with exact or inexact static roots: stores require the pointee's scope to contain the container's, merged values carry all roots, struct types with reference fields are implicitly generic over those roots, reference variables commit to their first root, and a reference read out of a container re-derives its roots from type-based candidates, with diagnostics that name the container and the candidates it could not choose between; there is no escape hatch.
- **goose-061** (disputes, `goose-residual-runtime-checks`, goose_spec.md §9.3): Goose's remaining runtime checks are bounds and index-type conversions (elided where proven, and disabled wholesale in a designated unsafe-fast build), pool and capacity checks, shrink-below-empty, relative offset overflow where the region can exceed the width, division by zero, asserts, guard-page and native-stack exhaustion as safe aborts, while integer overflow and lossy as checks run only in debug.
- **goose-062** (disputes, `goose-inferred-constness`, goose_spec.md §9.5): Goose infers the writability of references and slices per instantiation: parameters and results are generic over constness, a write through a parameter fails only at instantiations given read-only data, and storage slots must be declared const to hold read-only views so constness is never laundered through storage.
- **goose-064** (neutral, `goose-stack-assignment-recipe`, goose_spec.md §10.2-10.3, Appendix E Stack assignment): Goose assigns every simultaneously live non-fixed value (locals, by-value parameters, in-flight returns) a data-stack index by a deterministic DFS over specializations from main, taking the lowest free index and freeing it at scope exit, so N stacks suffice for the whole program; the spec permits pinning stacks per specialization (pushes as direct bumps of a known stack), while the shipped compiler uses the permitted hidden-argument strategy (each function takes a base index and addresses its non-fixed locals at constant offsets from it, callees start above its watermark); fixed values above 4096 bytes move to data stacks outside recursive cycles to protect the native stack.
- **goose-066** (neutral, `goose-wasm-fallback`, goose_spec.md §10.4): Goose's model depends on address-space reservation; on platforms without it (wasm today) it falls back to index-based references and bounds-checked growth at reduced performance, and wasm32 caps sizes at 2^32.
- **goose-067** (supports, `goose-48-bit-size-bound`, goose_spec.md §10.4 The 48-bit size limit): Goose fixes in the specification that no value or element count exceeds 2^48, so every length, index and byte offset lies in [0, 2^48]; with 15 bits of headroom, size arithmetic (len - 1, i + 1, len * 2, i * elemsize) cannot overflow, which the optimizer and BCE assume, and signed i64 lengths cost nothing.
- **goose-068** (supports, `goose-bce-language-facts`, goose_spec.md §10.5): Goose's bounds-check elimination is sound-only and fed by facts the language guarantees: index types, type-based non-interference between arrays of different types, grow-only monotonicity, static roots, constant extents and total operations, plus interprocedural facts where each call site records argument length relations, each specialization enters with their meet, and callees are summarized by an effect fixpoint so a call kills only what it can touch.
- **goose-069** (neutral, `goose-per-thread-stack-blocks`, goose_spec.md §11.2): Each Goose thread_fn is compiled as a separate program with its own stack assignment; a spawned worker gets a fresh block of N' reserved stacks addressed off one hidden register-resident base, copies of its flat arguments and of every global it uses, and releases everything on return; code is shared across programs only where stack references arrive by hidden arguments.
- **goose-070** (disputes, `goose-context-of-borrowed-tables`, goose_spec.md Appendix A.6): Because a Goose struct may own at most one resizable and recursive functions may hold none across recursion, a program with several growable tables (a compiler's nodes, text, scratch) must own each as a local of a driver function and pass the rest of the program one struct of references to them.
- **goose-063** (supports, `goose-data-stack-runtime-representation`, goose_spec.md Appendix C.1-C.2): A Goose data stack is only a control block { top }: allocation is p = top; top += size, scope exit restores a recorded watermark, and a push onto a resizable is a store, a top bump and a length increment with the header { base, len } kept in the owning frame; no other runtime allocator state exists.
- **goose-065** (supports, `goose-normative-packed-unaligned-layout`, goose_spec.md Appendix C.2): Goose's C backend layout is normative: scalars at declared width little-endian, bool one byte, packed structs with every load and store allowed to be unaligned, length fields of the smallest declared type, u8 ADT tags up to 256 variants, one-pointer references with 0 as null, and slices as { data, int64 len }.
- **goose-071** (neutral, `goose-bce-known-gaps`, goose_spec.md Appendix B 0f): Goose's BCE uses a difference-constraint domain that cannot represent disjunctive loop exits (!(i < n && p)), so post-loop bounds rely on inferred invariants, and values loaded from arrays have no range, so indirect indexing like dist[out[k]] keeps its check unless the stored element type is an index type.
- **goose-072** (neutral, `goose-packed-simd-cost-open`, goose_spec.md Appendix B 10): Goose lists as unmeasured whether its packed, unaligned layouts cost real SIMD performance, and considers opt-in aligned types if they do; whether narrow-lane elementwise operations vectorize is also still to verify.
- **goose-073** (supports, `goose-c-calling-convention`, goose_spec.md Appendix C.3): Goose's calling convention passes fixed values up to 4096 bytes as native C values (first result in the return register, more by out-pointer), explodes slices and resizable references into separate member parameters, passes larger fixed values by a caller-made private copy on a data stack, writes non-fixed results at the destination's stack top returning only metadata in registers, and signals return-from through one thread-local int so ordinary returns write nothing.
- **goose-075** (neutral, `goose-c-target-inherits-compiler-bugs`, goose_spec.md Appendix E C locals at function scope): Goose's generated C hoists every aggregate local to function scope and zero-initializes partially written literal temporaries to work around an MSVC 19.44-19.51 miscompile, at any optimization level, of reads through copies of structs holding addresses of block-scoped locals.
- **goose-076** (supports, `goose-implementation-equivalence-contract`, implementation.md introduction): Goose's implementation notes define equivalence for an independent implementation as the same type and lifetime decisions, evaluation, results, runtime failures and exposed layouts, explicitly not the same specialization count, stack numbering, optimization thresholds, C text or diagnostic wording, and require that acceptance never depend on an optimization proving a lifetime safe.
- **goose-077** (neutral, `goose-compiler-arena-architecture`, implementation.md §1 Pipeline, Ownership): The Goose compiler is a single translation unit whose Ast owns every node, type, symbol and specialization in append-only tables with no destructors, clones function bodies per specialization with an origin link, and groups each pass's per-node code in one file.
- **goose-078** (supports, `goose-optimization-outcome-annotations`, implementation.md §1 Driver flags): Goose makes optimization outcomes observable and testable: --bce-test verifies // bce:elide and // bce:keep annotations in sources, --bce-lines prints per-line elided and kept counts, --stacks reports data-stack counts per function and thread program, and an unsound --unsafe-no-rf-check flag exists only to measure the cost of return-from checks.
- **goose-079** (supports, `goose-per-root-error-recovery`, implementation.md §2 Recovery, §3.1 Roots and recovery): Goose recovers from errors per statement in the parser and per root in the checker: a failed root restores the checker to its entry, marks in-progress specializations failed and never reuses them, and goose check reports every error in root order, so one error costs only the diagnostics of what its root reached after it.
- **goose-080** (disputes, `goose-unchecked-generics-exemplars`, implementation.md §3.1, Exemplars): Goose checks generic and nested function bodies only when instantiated (type variables are never checked abstractly), so the language server checks uninstantiated generics as exemplars with opaque types, abandoning silently at the first operation an opaque type cannot support.
- **goose-081** (neutral, `goose-lifetime-roots-and-depth`, implementation.md §3.1 Frames, §3.4 Roots and provenance): Goose's lifetime checker represents every reference-like value as a set of root alternatives (the variable whose scope bounds the pointee, exactness, container read out of, writability, pool bits) and decides 'outlives' by comparing scope depth counted along the compile-time call path, which is sound only because each callee is checked per call path and specialization; temporaries are rooted one past the current scope and freed at statement end.
- **goose-082** (supports, `goose-pending-empty-array-type`, implementation.md §3.2 Pending arrays): In Goose, var out = [] needs no element type: the first push, append, format or whole assignment completes the element type in place, and a pending array left uncompleted at scope exit is an error.
- **goose-083** (neutral, `goose-declaration-order-in-place-construction`, implementation.md §3.2 Named initializer order): Goose evaluates struct literal initializers in declaration order so each is constructed directly in its destination, and accepts a literal written in a different order only when a conservative, optimization-independent proof shows the reordered expressions and intervening defaults have no observable effects, failures or nonlocal exits; it never emits staging copies.
- **goose-084** (disputes, `goose-ast-level-fixpoint-checking`, implementation.md §3.4-3.7, §3.11): Goose's lifetime checking is an AST-level fixpoint: loop bodies are re-checked until rebinding roots, container contents and narrowings settle, recursive cycles are checked in rounds, callee store records are replayed at each call site until they stop growing, and errors are held through discovery passes; the implementation notes need roughly 550 lines (§3.4-3.7) to describe roots, classes, store replay and read-back alone.
- **goose-085** (neutral, `goose-construction-locks-its-array`, implementation.md §3.10 Growth during construction, Uses during a whole assignment): Building values in place at a growable array's top obliges Goose to forbid any growth or shrink of that array while the value's expression runs, and building whole-assignment contents over the old ones obliges it to forbid any use of the location in the right-hand side; both are checked from logged growth events and callee summaries, with distinct resizable types exempt because a stack holds only one resizable.
- **goose-086** (supports, `goose-backend-asserts-checker-invariants`, implementation.md §3.11 Recursion): Goose's code generator re-asserts the checker's recursion verdict, raising an internal error at any call into the caller's cycle emitted while one of the caller's data-stack indices is in use, so a checker gap fails loudly instead of silently costing a data stack per activation.
- **goose-087** (disputes, `goose-transparent-refs-in-overloading`, implementation.md §3.12 Resolution): Goose resolves overloads by the worst argument's match tier with no specificity tiebreak, lets reference transparency and implicit lvalue binding take part in matching so that writing & can select a different overload, never lets the expected result type choose, and re-checks every argument (and re-resolves nested calls) in a second phase.
- **goose-088** (supports, `goose-emit-stores-to-preserve-alias-info`, implementation.md §3.15 Assignment): Goose emits an assignment to a destination the right side cannot move as a store spelled like the destination's loads (a member or element path) after the right side runs, rather than through a pointer taken first, because a member store lets the C compiler's type-based alias analysis keep it apart from other structs' fields and lets gcc's loop-invariant motion keep a read-and-written element in a register so the loop vectorizes.
- **goose-089** (supports, `goose-inlining-heuristics-cold-and-loop`, implementation.md §4 Inlining): Goose's inliner uses per-call-site thresholds (inline if used once, or small, or small times uses; -O1 8/48, -O2 16/96), raises the budget fourfold inside loops, refuses both the raise and the single-use rule in cold branches (a guard's else, arms ending in return, break, abort or exit) and marks such callees noinline so the C compiler does not inline them either, and defers single-use callees on a branch so the caller stays small enough to inline.
- **goose-090** (supports, `goose-recursion-transforms`, implementation.md §4 Base-case inlining, Accumulator tail-recursion elimination): Goose removes recursion overhead with base-case inlining (a self-call tests the callee's leading base case inline, halving the calls of a complete tree walk, also for the guarded tree-building shape) and accumulator tail-recursion elimination (tail returns of self(args) or E op self(args) with one associative integer operator become an accumulator loop).
- **goose-091** (supports, `goose-loop-restatement-for-vectorizer`, implementation.md §4 Min/max regrouping, Loop shaping): Goose restates loops the C compiler handles badly, with bit-identical results: counters used % K (K 2..16) are strip-mined into blocks of K, float s += e reductions compute a block of terms first and add them in order, countdown loops get a known trip count, and min/max chains carrying a loop dependence are regrouped to combine the carried operand last.
- **goose-092** (supports, `goose-bce-difference-constraints-generations`, implementation.md §5.1-5.3): Goose's bounds-check elimination is a flow-sensitive difference-constraint domain (l <= r + c over variables and place lengths, queried by saturating Bellman-Ford, capped at 200 facts per state) where kills open new generations instead of deleting facts, length mutations add bridge facts (exact for push and constant append), and terms cover Euclidean %, masks, quotients, interval arithmetic, narrow-typed loads and linear multiples/quotients.
- **goose-093** (supports, `goose-bce-facts-drive-codegen`, implementation.md §5.9-5.10): Goose uses its bounds facts for codegen decisions beyond eliding checks: reading a loop's view once when the body cannot change it, bounding a loop by a proven constant length, hoisting base and length of indexed arrays into locals, evaluating a short-circuit right operand unconditionally (branchless) when its checks hold without the left, computing provably non-negative signed division, modulo and shifts in unsigned arithmetic, and merging identical leading checks of an if's arms so the stores become a select.
- **goose-094** (supports, `goose-bce-differential-fuzzing`, implementation.md §5.11 Verification): Goose verifies its bounds-check elimination three ways: per-line // bce:elide and // bce:keep fixtures that also run as programs, an A/B benchmark of the pass against --no-bce, and a differential fuzzer that runs random loop-shape programs with off-by-one mutations with the pass on and off; the fuzzer found a real misreading of inlined multi-return bodies within a few hundred programs.
- **goose-095** (supports, `goose-measured-micro-lowerings`, implementation.md §6.1 Fixed-size types, Resizable values): Goose's runtime compares byte runs up to 16 bytes inline with two overlapping word loads per side and up to 256 bytes 16 at a time, calling memcmp only beyond, after lookups of ~60-byte strings spent a fifth of their time in the call; copies up to 256 bytes inline (string building up to a fifth faster); and indexes 2/4/8-byte elements through a typed pointer so the scale stays in the address mode (nsieve 138 vs 150 ms).
- **goose-096** (supports, `goose-warn-on-hidden-copy-cost`, implementation.md §6.5 Named results): Goose guarantees named-result placement where every return hands back one top-level local or a value that cannot reach it, and where a return would instead cost a copy of the named result the checker warns at that return, because the copy shows nowhere in the source.
- **goose-097** (supports, `goose-runtime-owned-text-formatting`, implementation.md §6.9 Text compatibility, Output): Goose owns its number formatting instead of using the C library: integers through a digit loop producing two digits per division by 100, floats as the shortest round-trip digits of their own type by Burger-Dybvig in integer arithmetic, and inf/nan spelled by the runtime, so every backend (including msvcrt under TinyCC, which rounds printf ties differently) prints identical text; print writes each whole line with one fwrite.
- **goose-098** (supports, `goose-store-forwarding-aware-lowering`, implementation.md §6.4, §6.9 gs_eq, §6.10 Fills and stores): Goose shapes its emitted stores and loads around store-to-load forwarding: small pushed aggregates (2, 4, 8 bytes) are stored as one integer so a later whole-element load forwards, small fixed values compare field by field rather than by memcmp of just-stored registers, and slices and fat references are passed as separate members so a callee's wide load never waits on a caller's narrow stores (a recursive descent parser had spent half its time there).
- **goose-099** (supports, `goose-loop-arithmetic-strength-reduction`, implementation.md §6.10 Divisors, §7 sqrt): Goose replaces unsigned (or proven non-negative) division and remainder by a loop-invariant divisor with libdivide magic-number multiplication computed once before the loop, using a 32-bit magic for operands of 32 bits or fewer so the loop vectorizes (7x with AVX-512, 4.3x at baseline x86-64); a zero divisor falls back to the plain checked division so the abort occurs where it would; and its sqrt avoids errno so loops around it vectorize.
- **goose-100** (supports, `goose-short-circuit-lowering-policy`, implementation.md §6.11): Goose lowers && and \|\| in conditions to branch chains (inlined bool calls branch on their returns), and in straight-line innermost loops evaluates an effect-free, non-failing right operand unconditionally and combines with & or \|; measured 5.4x on a vectorizable block compare, but 25-30% and 30% slower when applied outside such loops (heap sift, JSON whitespace skip), which set the limits; signed arithmetic, division, narrowing casts and unsettled indices stay short-circuited.
- **goose-101** (supports, `goose-fp-contraction-off`, implementation.md §6.13 Exactness): Goose turns floating-point contraction off for the whole generated unit under clang, GCC and MSVC so SIMD versions, arm64 and x86-64 produce identical float results (a golden test prints other digits without the guard); contraction also measured 2x slower on an AVX-512 matrix multiply.
- **goose-102** (supports, `goose-stack-capacity-knobs`, implementation.md §7 Trimming, Stack counts and the thread cap): Goose exposes data-stack capacity to experts as configuration and one call: GS_STACK_RESERVE, GS_STACK_GAP, GS_MAX_STACKS (compile error past it, since stack counts are a compile-time constant over the call graph), GS_STACK_BUDGET capping hardware_threads(), --stacks and GS_STACK_STATS reports, and os.trim_memory returning pages above each stack's top; beginners never see any of it.
- **goose-103** (supports, `goose-checked-arith-must-inline`, implementation.md §7 Integer semantics): Goose's integer helpers were measured at 13-37% of runtime under a non-inlining backend when they were functions; they are now macros equal to the release expression and check only under GS_DEBUG, with file and line arguments dropped unevaluated in release; bounds checks are one unsigned compare.
- **goose-104** (supports, `goose-simd-byte-set-search`, implementation.md §7 Byte search, §9.9): Goose's std byte search (find_any, find_pair over a prepared ByteSet) tests 16 bytes at a time: SSE2 compares for up to three bytes or one range or their complements, with a separate force-inlined loop per set kind and kind pair because a switch inside the loop cost two indirect jumps per block, SSSE3 pshufb nibble tables for arbitrary sets, memchr for single bytes, and a tail that reloads the last whole block and masks already-tested positions so no load passes the range end.

- **goose-106** (supports, `goose-compactness-is-the-win`, bench/summary.md Compact representation, Allocation and interfaces): Goose's clearest measured advantage is compact representation and allocation-free construction, not raw arithmetic: records runs 2.02-2.26x faster than safe Rust on 3.98x less memory, interp 1.29-1.41x faster on 2.04x less memory, sexp uses 2.43x less memory than the Rust arena, bintrees beats the C++ and Rust arenas (206 vs 393 and 235 ms), and an inline response DTO builds in 507 ms against Rust's 1338.
- **goose-107** (neutral, `goose-benchmark-aggregate-caveats`, bench/summary.md Losses, Read the aggregate, whole-process measurements): Goose's headline geomean selects the fastest Goose implementation separately per backend and tier and the smallest separately for memory, measures whole processes best-of-three without pinning, and still shows losses or ties to safe Rust on calc, lru (under MSVC) and scene, whose causes the refresh does not re-establish.
- **goose-108** (supports, `goose-bytes-touched-thesis`, bench/design.md feature list, Where the gains should compound): Goose's benchmark design states one thesis behind all its memory features: inline layout, relative links, narrow scalars, flat nested containers, no allocator headers, exact-size growth, O(1) teardown and in-destination construction all reduce bytes touched per unit of work, so the benefit scales with how pointer- and allocation-rich the data is and widens with working-set size; flat scalar arrays are the control with no expected advantage.
- **goose-109** (disputes, `goose-predicted-weaknesses`, bench/design.md Where we should expect Goose to lose): Goose's own design lists its expected weaknesses: packed unaligned layouts may cost SIMD; it deliberately permits aliasing and so gives the backend no noalias information; every copy is real because there is no move; non-nested lifetimes (caches, long-lived mutable graphs) must go through pools and recursive cycles cannot own growable locals; and page-granular commit per stack can look worse than malloc at small sizes.
- **goose-110** (supports, `goose-arena-beats-box-per-node`, bench/design.md The suite as built): In Goose's suite the safe Rust Vec-plus-indices arena ran 2.8x to 5.9x faster than Box-per-node on the three benchmarks with both, confirming that the arena, not per-node allocation, is the fair comparison for pointer-heavy data.
- **goose-111** (supports, `goose-agent-branch-ab-method`, bench/adoption.md introduction, Measurement notes): Goose ran one round of sixteen compiler optimizations as parallel agent branches, each with tests, then measured all of them on a quiet machine with interleaved baseline/candidate runs, best of five, checked outputs, under two toolchains, using rows whose generated C was byte-identical as the noise floor (0.94-1.08, so single-row gains under about 5% are noise), and recorded an adopt/hold/drop verdict with a predicted future-code frequency per item.

In generic code, T {} gives the default value of a non-struct type. Declaring `constructor Foo(...)` makes it the only way to build a Foo outside that function, so every Foo satisfies the invariant that function establishes.
- **lobster-020** (supports, `lobster-non-escaping-function-values-as-code-pointers`, docs/source/language_reference.md Function Values, Scope, Explicit Free Variables): Lobster function values are non-escaping. They refer to free variables rather than capture them, so a function value is one code pointer with no environment, and closures never allocate. A function value passed through a generic parameter is always inlined, so higher order functions match hand-written loops. Declaring a named function type for the parameter turns inlining off, to limit code bloat. Calling a stored function value after its free variables have gone out of scope is an error; one section says compile time and another says run time. Explicit free variables, `def foo(a, b) [c, d]`, resolve c and d from the caller's context on the call stack.
- **lobster-021** (supports, `lobster-per-call-devirtualization-and-removed-multimethods`, docs/source/language_reference.md Overloading and dynamic dispatch, Operator overloading): In Lobster, overloading and dynamic dispatch are one system. The compiler sees the whole program and decides per call whether dispatch is virtual: a call is static whenever only one implementation can apply, so fewer calls are virtual than in other languages. Dispatch looks only at the first argument; the remaining arguments are still specialized statically. Multi-methods were removed because in practice they were slow, needed complicated lookup tables, and were ambiguous: they sometimes merged unrelated functions and caused unexpected errors or slowdowns. Overloaded operators are ordinary functions parsed with built-in precedence.
- **lobster-022** (neutral, `lobster-trailing-block-calls-as-control-structures`, docs/source/language_reference.md Function calls, Function Values, for, while, User defined control structures, String Interpolation): Any Lobster call can be followed by function-value blocks with no fn keyword, so g(10) i: print(i), or g 10: print _, reads like a built-in control structure. Parameters named with a leading _ are declared implicitly. Built-in if, for and while share the same syntax; while is the one exception, turning its condition expression into a function value. Library calls such as gl.translate take a body and restore state after it. Dot calls put the first argument in front, and string interpolation writes {expr} inline.
- **lobster-023** (neutral, `lobster-function-scoped-and-frame-reset-state`, docs/source/language_reference.md Global and Class member variables with function scope): In Lobster, `member b = 2` inside a method stores b in the object but makes it visible only in that method; `static` does the same for a global inside a function. member_frame and static_frame go further: each resets to its initializer on any frame that does not use it, so a system's state exists only while control flow keeps it active, which the doc calls immediate mode for state. The cost is an extra frame-count variable and check.
- **lobster-024** (disputes, `lobster-whole-program-textual-import`, docs/source/language_reference.md Programs Structure, Modules and Name Spaces, Declaration order): A Lobster program is one main file. import merges each imported file into the program at the import site, once, with names resolved through the main file's directory, the install directory, their modules subdirectories, import from roots, or file-relative leading-dot paths. private hides a top-level item outside its file, and namespace foo qualifies a file's top-level names. The whole program is type checked together: functions in call order and types in source order. Several features depend on that whole-program view, including per-call dispatch decisions, specialization and lifetime analysis.
- **lobster-025** (neutral, `lobster-enum-switch-out-of-range-case`, docs/source/language_reference.md switch): A Lobster switch accepts multiple values and inclusive ranges per case. A value that is not part of its enum's definition, for example one read from a file, is an uncatchable runtime error in a switch with no default. An `out_of_range` case replaces exactly that error at no extra cost and runs only for such values. Unlike default, it keeps the switch exhaustive, so a missing case for a defined value is still a compile error, and inside it the value is a plain int. type_enum_value_valid checks the range before a switch.
- **lobster-026** (supports, `lobster-isolated-vm-per-thread-tuple-space`, docs/source/language_reference.md Multi-threading): Lobster threads share no memory and no VM state. Each hardware thread runs its own isolated copy of the program, and threads communicate through a tuple space of objects that are copied, not shared. Each VM therefore runs as if single-threaded, with single-threaded allocators, no GIL and no synchronization. The doc says overall performance can exceed shared-memory systems, and recommends worker-style load balancing. It calls the feature early-stage.
- **lobster-027** (disputes, `lobster-free-variables-are-saved-global-slots`, docs/source/language_spec.md Function values (free variables, functions as environments, explicit free variables), return): Lobster's normative spec gives free variables dynamic, shallow-bound semantics. Each free variable has a single storage location for the whole program. The declaring function saves it on entry and restores it on exit. A function value therefore sees the most recent activation of the declaring function that is still active, not the activation that created it. Calling a function value is valid only while every declaring function is on the call stack; a violation the compiler can see is an error. A named function declared inside g can be called by name from outside g while g is active, and explicit free variables bind at type-check time to the nearest active variable with that name. return from f must not pass through a function value call.
- **lobster-028** (supports, `lobster-spec-corners-not-to-copy`, docs/source/language_spec.md Lexical structure, Function declarations, Class and struct declarations, Grammar and precedence, Names in expressions, Operators on numbers, Operators on strings, Logical operators and truth, Call resolution, Numeric conversions): Lobster's spec documents these rules precisely: - Integer + - * wrap modulo 2^64. - Shift counts are taken modulo 64. - int(f) out of range is unspecified. - The smallest integer has no literal, and hex literals are reinterpreted as signed. - 1e5 lexes as 1 followed by the identifier e5. - & \| ^ share one precedence level, so a \| b & c is (a \| b) & c, and and/or share one, so a or b and c is (a or b) and c. - Whitespace decides parsing: f (1) * 3 is f((1) * 3), and ident< begins type arguments only with no space. - E(e) converts an int to an enum with no range check. - -0.0 and nan are true. - and/or quietly convert to bool when the operand types have no union, so true and 5 is true. - Byte-writing builtins change immutable strings in place, visible through every reference. - Field names are program-wide identities. - Once a namespace is declared, the lexer reads ns.x as one token. - Call resolution has five steps, then a seven-tier overload filter. - Defaults are evaluated in the caller's context. - Extra return values are dropped.
- **lobster-029** (supports, `lobster-normative-spec-and-diagnostic-hints`, docs/source/language_spec.md Scope and conventions, Tokens, Whitespace and comments, Scopes, Variable declarations, Statements, Runtime errors defined by the language): The Lobster spec is written to be normative for its implementation: a disagreement between the two means one has a bug. It uses four defined terms: error, warning, runtime error and unspecified, the last for behaviour inherited from the host C compiler. Familiar mistakes get errors that name the fix. `;` is an error saying it is not a statement terminator. `!`, `&&` and `\|\|` point to not, and and or. Shadowing any visible outer variable is an error. Warnings cover an unread local, a var that is never reassigned (suggesting let), an expression statement with no effect, a constant-true assert, and a condition that is always true. The language lists exactly six runtime errors of its own. Compilation stops after the pass that reported an error.
- **lobster-030** (neutral, `lobster-borrow-conflict-decision-rule`, docs/source/language_spec.md Borrowing): The spec gives the exact rule behind the ownership inference of lobster-001 and lobster-002. A borrow is taken when a path such as x, x.a.b or v[i] is used as a function argument, as the object of a field access or index, as the initializer of a single-assignment variable, or as a for-loop element. When a write may alias a live borrow, there are two outcomes. If the write happens in a called function, after the borrowing variable was initialized, or in a later argument of the same call, as in f(v[0], v.pop()), the borrower is made to own a reference and the program is accepted. A write elsewhere in the same expression, such as v[0] + v.pop(), is an error. All elements of a vector count as one location unless both indices are different constants, and builtins that remove elements count as writes. A parameter the function assigns to owns its own reference. Calls through a declared function type pass every argument borrowed, and an assigned parameter copies on entry.
- **lobster-031** (disputes, `lobster-flow-promotion-untracked-alias-hole`, docs/source/language_spec.md Flow-sensitive typing): Lobster promotes variables and field paths, never indexed elements, after if x, is, assert, non-nil assignment and type switches. A promotion is dropped by a write to the path or any prefix of it, by writes in called functions through tracked parameter aliases, and by writes through a variable assigned from the path. The spec says plainly that aliases arriving another way are not tracked: through a function result, through an element or field the object was stored in, through the reference fields of a copied struct, or through an alias assigned later in a loop body on the next iteration. A write through such an alias does not drop the promotion.
- **lobster-032** (neutral, `lobster-value-conversion-and-evaluation-rules`, docs/source/language_spec.md Kinds of types, Conversions, Operators on structs, Field access and indexing, is typeof assert nil, Evaluation order, for, String conversion): The spec fixes several value rules worth comparing with Jet: - T? exists only for reference types, so int? never exists. - Vectors are invariant, except that a fresh literal or constructor converts covariantly because nothing else can alias it. - A struct never converts to a supertype that would truncate it. - == on structs compares field by field with each field type's ==. - In an assignment the right side is evaluated first, then the left side's object and index once each; a multiple assignment assigns right to left. - A for over a vector re-reads the length each iteration, so appended elements are visited. - is never binds an inference variable. - Floats print in fixed notation with the shortest round-trip digits and always a fractional part.
- **lobster-033** (disputes, `lobster-whole-program-specialization-key-and-dispatch-closure`, docs/source/language_spec.md Program, Numeric structs and Generics, return, Specialization, Dynamic dispatch): Lobster type checks a function once per specialization. The specialization key combines four things: - the types bound to its type variables; - the number of return values the caller consumes; - the promoted types of the free variables it uses; - the ownership convention of its parameters. An uncalled generic function is never checked, while an uncalled function with concrete parameters is. Recursive functions must declare return types. Dynamic dispatch requires an implementation for every concrete subtype in the whole program, and a generic class specialization first used after a dispatch on its superclass was checked is an error. The pipeline is parse all files, declaration check, type check, optimize, generate code, each over the whole program.
- **lobster-034** (neutral, `lobster-three-execution-tiers-and-their-cost`, docs/source/command_line_usage.md Basic usage, --pak, --mir, --cpp, runtime flags): One `lobster FILE` command compiles and runs a program. The default JIT backend is libtcc, which starts fast but runs about 2x slower than the --cpp path. --mir is an optimizing JIT that is slower to start but much closer to --cpp in speed, recommended for speed-sensitive work during development. --cpp is for shipping builds. Runtime flags trade speed for diagnostics: --runtime-stack-traces adds line info and function tracking with a small speed effect, and --runtime-debug cuts inlining for a larger effect. --runtime-no-asserts removes asserts.
- **lobster-035** (supports, `lobster-compile-time-stack-traces-and-query-mode`, docs/source/command_line_usage.md --errors, --full-error, --query, --main, Output): Lobster prints up to --errors N errors (default 10). When type checking fails it prints a compile-time stack trace: the chain of specialized calls that led to the failing types. The trace is truncated, and shown only for the first error, unless --full-error is given, which also dumps the free and local variables in each function context. A runtime error prints a stack trace with every local variable's value. --query answers a definition or completion question at a file, line and identifier without full compilation, ignoring errors or stopping early, and is what the IDE and LSP use. --main checks the module being edited on its own, then runs the program's real main file.
- **lobster-036** (supports, `lobster-game-loop-workload-in-tutorial`, docs/source/shooter_tutorial.md 3: Input, Movement, and Collision; 4: Orientation and Shooting; 5: Enemies; 6: Score, and Game Over): Lobster's tutorial builds a complete Geometry Wars-style game in about 100 lines of top-level code. The code relies on four idioms. Numeric-struct arithmetic covers positions and directions, including any() over a vector of comparisons. Engine calls such as gl.translate, gl.color, gl.rotate_z and gl.line_mode take a body and restore their state after it. Entities live in class vectors and are updated in for loops. filter culls dead or distant entities after the update rather than during it, which the tutorial says avoids subtle bugs. Collision is brute force over every bullet and enemy pair.
- **lobster-037** (supports, `lobster-error-type-recovery-and-gated-later-passes`, dev/src/lobster/typecheck.h:36-82): Lobster's type checker is one pass, assembled from topic classes over a virtual base, that infers types and lifetimes together (TT with a lifetime argument such as LT_KEEP). After an error it substitutes an error type for whatever failed and keeps checking, so it can report several errors. The passes after type checking (optimizer, code generator) run only when there were no errors, and in debug builds a sweep asserts that no error type remains in any checked body. Dead code, meaning functions never called, is checked after the main traversal.
- **lobster-038** (neutral, `lobster-lifetime-inference-as-recipient-matching`, dev/src/lobster/typecheck_base.h:17-26, 133-190, 938-990): Lobster infers reference counting ops during type checking. Every node gets a lifetime: keep (owns a reference), borrow of a specific variable (an index into a borrow stack), or any (a scalar or a fresh value that adapts). TT checks each child against the lifetime its recipient wants. A borrow given where a keep is wanted sets an incref bit; a keep given where a borrow is wanted sets a decref bit. A ToLifetime node carries those bitmasks, up to 64 values. Each borrow stack entry counts outstanding borrowed values, and the variable cannot be assigned while the count is above zero. A variable that holds a borrow speculatively flips to owning when a write conflicts, instead of raising an error.
- **lobster-039** (supports, `lobster-lifetime-soundness-holes-in-code`, dev/src/lobster/typecheck_base.h:668-740, 862-874, 912-930): Lobster's lifetime checker has holes and conservative choices that its source admits. A function value with local free variables passed to a declared function type should be an error, since it can outlive them, but is accepted because plenty of code does this without escaping and detecting that would need new analysis. A negative borrow count "should really just not be possible, but hard to guarantee" and is reported as an internal-sounding error. A parameter owns its argument (an extra incref) whenever the function assigns to it or whenever it is a struct of references, conservatively, because the parser knows assignments and the type checker knows types, but not both together.
- **lobster-040** (supports, `lobster-no-silent-truncation-conversions`, dev/src/lobster/typecheck_base.h:452-530, 742-768): Lobster's conversion rules guard against silent data loss and aliasing errors. A struct value converts to a superclass struct only when the subclass adds no fields, because dropping them would be silent truncation. Abstract struct families share one layout, so any member converts to the family's supertype. Vector element types must match exactly unless the vector is a fresh constructor: an unaliased value can be covariant because nobody else can insert a supertype element through another reference. An int literal where a float is expected is converted with one warning per literal.
- **lobster-041** (supports, `lobster-consequential-error-suppression-and-trace-cap`, dev/src/lobster/typecheck_base.h:248-350): Lobster keeps type checking after errors with an error type that converts to and from anything. An error about a node whose own type or whose children's types involve the error type is not reported, because it is almost certainly a consequence of one already reported. Each error site must leave the checker well formed: no null types, no outstanding borrows, balanced stacks. The call chain that led to an error is printed only for the first error, cut to 5 functions when more than 7 are active, unless --full-error. Uncalled functions are checked at the end only for their errors and are silently abandoned where they need a real caller.
- **lobster-042** (neutral, `lobster-type-variable-cycles-overwritten-in-place`, dev/src/lobster/typecheck_base.h:406-450): Lobster unifies type variables without a union-find table. Unified variables form a cyclic linked list. Two variables are merged by swapping their next pointers, an O(1) splice. Binding a variable overwrites every Type struct in the cycle in place with the bound type. The source notes that the overwrite relies on callers not creating nonsensical types.
- **lobster-043** (disputes, `lobster-whole-program-alias-replay-cost`, dev/src/lobster/typecheck_locations.h:394-525, 762-800): Lobster's borrow and flow checks track aliasing across calls. A write is recorded in every enclosing function up to the variable's definition, as the path each function can see. When a specialization is reused at a new call site, its recorded writes are replayed against that caller's borrows and promotions. Paths are compared after expanding parameter aliases and owning aliases. The source says these checks are expensive. Borrow stack lookup is a linear scan marked "FIXME: this path is slow". Free variable checks are "very expensive"; memoizing per caller removes about 30% of them, and skipping top-level variables culls over 90%.
- **lobster-044** (supports, `lobster-narrowing-lost-note-names-the-write`, dev/src/lobster/typecheck_locations.h:102-195): When a nil or missing-field error happens on a path that flow typing had promoted earlier, Lobster appends a note saying why the promotion was lost: "x is no longer known to be non-nil after the assignment to y at file:line, in the call to f at file:line". If the write went through another name, it adds "x may be an alias of z". The checker records each demotion, with the write's line, the paths compared and the call made by the promoted code, so the note can point at a write that is far away or in another function.
- **lobster-045** (disputes, `lobster-uncalled-generic-code-never-checked`, dev/src/lobster/typecheck_functions.h:33-130, 331-350): Lobster checks a function only when a call reaches it, because types and lifetimes come from the call. After the main pass it also checks uncalled top-level named functions, but only those with no generic parameters and every argument concretely typed. Uncalled generic or partly annotated functions, uncalled methods and nested functions are never checked, so their errors appear only when some later program first calls them. Everything the dead-code pass creates is reverted, so the optimizer and code generator see such functions as dead. Lints such as var-never-reassigned (use let) also run per specialization and are deduplicated.
- **lobster-046** (neutral, `lobster-non-local-return-checking`, dev/src/lobster/typecheck_functions.h:132-170, 387-570): Lobster supports return from an outer named function inside a block passed to a higher-order function. The checker finds the active specialization of the destination, unions the return type into it, and walks every caller path (including recursive ones) to mark each function the return passes through, so the generated code can check for unwinding. A function reused for a later call replays its recorded returns there. Returning through a dynamic function value is rejected, because the value was checked against one context and may be called in another. A return whose destination is not active is "called out of context". Returned values are always owned, because returning a borrow would need a proof that it does not outlive its owner.
- **lobster-047** (neutral, `lobster-specialization-reuse-key-and-size-cap`, dev/src/lobster/typecheck_calls.h:20-25, 77-200, 301-400): Each Lobster call either reuses an existing specialization or clones the function body and checks it again. Reuse requires the same borrow-or-own decision for every argument, equal type variable bindings, equal current types and flow promotions of free variables, and non-local returns that fit the active callers. To bound the number of copies, functions with more than 25 AST nodes get a single specialization with borrowing parameters that every caller adjusts to; the comment says per-argument lifetimes pay off only for small functions that are later inlined. Overload selection reuses scratch vectors because otherwise calls "cause a LOT of allocations".
- **lobster-048** (neutral, `lobster-call-resolution-order-and-first-argument-dispatch`, dev/src/lobster/typecheck_calls.h:402-700, 702-835, 930-1200): Lobster resolves a call name in a fixed order. A variable holding a function value wins unless a function of that name is declared in a deeper scope, and a builtin wins over both unless a function matches the receiver better. A dot without parentheses that names a field is field access. Among arity variants, the one with the closest receiver type wins, with generic receivers last, then the one with the most arguments, counting an implicit self from an enclosing method and default arguments. Overloads are then filtered argument by argument, left to right: exact type, generic class instance, closest subtype, plain conversion, type variable, explicit specializers, then coercion. Dynamic dispatch happens only on the first argument, only for classes and abstract struct families, and only when a subclass has its own method. All implementations of one dispatch share argument lifetimes, and their return types are unioned without coercion.
- **lobster-049** (supports, `lobster-annotations-required-at-recursion-and-overload-errors`, dev/src/lobster/typecheck_calls.h:27-75, 193-198, 561-640, 1201-1240): Lobster asks for annotations only where its call-driven inference cannot finish. - **lobster-054** (neutral, `lobster-multi-dimensional-indexing-by-int-struct`, dev/src/lobster/typecheck_lval.h:332-380): Lobster lets a nested vector be indexed by a struct of ints, one level per field, so grid[pos] with pos: int2 reads grid[pos.x][pos.y]. - **lobster-055** (neutral, `lobster-enum-and-vector-operator-typing`, dev/src/lobster/typecheck_ops.h:82-222, 332-360): Lobster types operators on enums and small vectors as follows. - **lobster-058** (supports, `lobster-stack-ir-rendered-as-register-friendly-c`, dev/src/lobster/codegen_base.h:57-215, 345-395, 707-716, 902-935, 1236-1300): Lobster generates C from a stack-machine view of the program without a runtime stack. The stack depth is tracked at compile time, so a pop emits no code. Each stack slot is a C local per value kind (i5, f5, s5 and so on) whose address is never taken, so the C compiler can keep it in a register. A pure int or float expression pushed to a slot is not written there. The slot remembers the expression and the variables it reads, so the operators of one source expression become one C expression. The expression is written out at labels and jumps, before a write to any variable it reads, or once it grows past 80 characters. Within one call, a later argument that writes what an earlier argument borrows makes the earlier one take a reference of its own, and the same holds for assigned-variable arguments and multiple return values; a write while another operand of the same expression borrows the location (v[0] + v.pop()) is instead a compile error. Across dynamic dispatch the ownership convention is uniform: assigning the parameter in any one implementation makes it owning in every implementation, a field overwritten only by a later-declared implementation forces the caller to retain the borrowed argument across the whole call, and a reused dispatch re-adjusts owning arguments before replaying a subclass's writes.
