# An any type: what it costs elsewhere, and a proposed Jet design

Date: 2026-11-09. Decisions: D-PRIM-ANY1 (the any box, open) and D-PRIM-TYPEKEY1
(ratified 2026-11-09 as A: an opaque `core.reflect.TypeKey`). The types-as-values
design in this report is a proposal: for TYPEKEY it would amend the ratified A as a
new ballot, D-PRIM-TYPEKEY2, and neither ballot has passed its adversarial review.
Where a table below says how the design removes a cost, that removal is proposed,
not built or measured.
It builds on two ratified decisions: D-REFLECT-TYPEINFO1 (one `reflect` call, with
run-time type info kept only for the types a program uses) and D-META-REFLECT2
(one signature schema for every callable).

Every probe below ran with the seed compiler a0_042 on the dev tree at
6a06b917cb. Each probe is short, and the section "Probe programs" at the end
gives each one, so anyone can rerun it. Each claim is marked **today**
(probed), **ratified** (decided but not built) or **proposed** (this report's
design, not decided).

## What an any type is for

An any type holds a value whose type is chosen at run time, and lets code ask
what that type is. Five uses come up again and again:

1. **Heterogeneous tables.** Settings, request context and blackboard maps hold
   a theme here and a number there, under string keys.
2. **Plugin registries.** A host stores values that plugins define and later
   hands each one back to the plugin that knows its type.
3. **Entity-component systems.** A world stores one table per component type,
   keyed by the type itself.
4. **Decoded-but-typed data.** A decoder produces a value of one of many types,
   and the caller branches on which type it got.
5. **Test doubles.** A fake records the arguments it was called with, whatever
   their types, for later checks.

The first, second and fourth need a box that holds any value. The third needs
a type as a value, to use as a map key. All of them need a safe way back from the
box to the real type.

## How other languages do it

| Language | Form | Representation | Allocation | Getting the type back | Failure mode | Ownership and lifetimes |
|---|---|---|---|---|---|---|
| Go | `any`, an alias of `interface{}` | two words: type, data pointer | since Go 1.4 the data word is always a pointer, so a non-pointer value usually allocates | `x.(T)`, `switch v := x.(type)` | `x.(T)` panics; `v, ok := x.(T)` does not; a type switch needs no exhaustiveness | garbage collected; no lifetimes |
| Rust | `Box<dyn Any>` | a box plus a vtable pointer | one heap allocation, except for zero-sized types | `downcast_ref::<T>()`, `Box::downcast::<T>()` | `None`, or `Err(box)`, which hands the box back | `Any` only for `T: 'static`, so no borrowed data |
| Swift | `Any`, `any P` existentials | a three-word inline buffer, type metadata and witness tables | inline when the value fits in three words; otherwise a side allocation | `as?`, `as!`, `switch` with `case let x as T` | `as?` gives nil; `as!` traps | reference counted; value types copied in |
| C# | `object`; `dynamic` | a reference to a heap object | boxing a value type allocates and copies | `is T t`, `switch` type patterns | `(T)o` throws; `as` gives null; `dynamic` binds at run time | garbage collected; `dynamic` gives up compile-time checking |
| Java | `Object` | a reference | primitives are boxed (a small `Integer` range is cached) | `instanceof T t`, pattern `switch` | a bad cast throws `ClassCastException`; a switch is exhaustive only over sealed types | garbage collected; generics erased |
| Kotlin | `Any`, `Any?` | a reference on the JVM | numbers boxed when typed as `Any` | `is T` smart casts, `when` | `as` throws; `as?` gives null; `when` is exhaustive over sealed types | garbage collected |
| TypeScript | `any` and `unknown` | erased at run time | none of its own | `typeof`, `instanceof`, user guards | `any` turns off checking; `unknown` must be narrowed before use | not applicable |
| Haskell | `Dynamic` with `Typeable` | a value paired with its type representation | a heap value, like all boxed values | `fromDynamic :: Typeable a => Dynamic -> Maybe a` | `Nothing` | garbage collected; `Typeable` derived automatically |
| Zig | `anytype` | none: the parameter's type is fixed while compiling | none | `@TypeOf`, `@typeInfo`, `switch` while compiling | a compile error | not a run-time box at all |
| Jai | `Any` | `type: *Type_Info` and `value_pointer: *void`, 16 bytes | none, because it points at the value | read `type`, then cast `value_pointer` | an unchecked cast reads the wrong bytes | the pointer does not own the value; it dangles if the value's storage goes away |

### The costs, gathered

- **Allocation.** Go, C#, Java, Kotlin and Rust usually allocate per boxed
  value. Swift avoids that for values that fit in its three-word buffer. Jai
  never allocates, because it does not own the value.
- **Descriptor size.** Every design needs a per-type record (Go type, Rust vtable
  and `TypeId`, Swift metadata, Jai `Type_Info`). Jai keeps type info for all
  types; the others keep it for the types that are used.
- **Lost static checks.** TypeScript `any` and C# `dynamic` turn checking off.
  Implicit conversion to a top type (Go `any` parameters, Jai `Any`, Kotlin and
  Java `Object`) lets a wrong argument compile.
- **Downcast failure.** A checked downcast gives an option (Rust, Swift `as?`,
  Haskell). An unchecked one panics or throws (Go `x.(T)`, Java, C#, Swift
  `as!`), or reads garbage (a Jai cast).
- **Ownership and lifetimes.** Rust refuses borrowed data in `Any`. Jai allows
  it, and the box can outlive the value. Garbage-collected languages avoid the
  problem by keeping everything alive, and they have no deterministic cleanup
  for boxed resources.

The spec lists a general `Any` top type under "Deliberately absent"
(`Docs/spec/spec.md`, section "Deliberately absent"), and
`Examples/Types/NoAnyAlternatives.jet` teaches the alternatives: an enum, a
generic, an optional and `Dyn`. Trait values are not copyable (E0211) and
cannot cross a task (the spec's task-boundary rule, E1102). Today, then, Jet
covers closed sets (enums), behavior sets (traits) and encodable data (`Dyn`).
It has no box that keeps an arbitrary owned value, and no type value.

## Jet's options, as the same program

Each option shows the same program. It keeps a theme and a font size in one
settings map, reads the font size back with a check that fails safely, and
counts entities by type.

**A, recommended (proposed): type values and one checked box.**

```jet
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Any]{}
    settings["theme"] = Any(Theme{dark: true})
    settings["font_size"] = Any(14)
    if settings["theme"] == {
        Theme(theme) -> print(theme.dark)        // true
        else -> print("no theme")
    }
    if settings["font_size"] == {
        String(text) -> print(text)
        else -> print("not text")                // printed
    }
    counts := [Type: Int]{}
    counts[Position] = 2
    p: Position{x: 1, y: 2}
    print(counts[type_of(p)])                    // 2
}
```

**B: today's tools (runs today, p12).**

```jet
use reflect: core.reflect

#Codable
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Dyn]{}
    settings["theme"] = Theme{dark: true}.encode()
    settings["font_size"] = 14.encode()
    theme: settings["theme"].decode<Theme>() ?? return
    print(theme.dark)                            // true
    if settings["font_size"].decode<String>() == {
        .Ok(text) -> print(text)
        .Err(errors) -> print("not text")        // printed
    }
    counts := [String: Int]{}
    p: Position{x: 1, y: 2}
    counts[reflect.of(p).path()] = 2
    print(counts[reflect.of(p).path()])          // 2
}
```

**D: library key and library box (the earlier D-PRIM-ANY1 A and D-PRIM-TYPEKEY1 A).**

```jet
use reflect: core.reflect

Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: reflect.Any]{}
    settings["theme"] = reflect.Any{Theme{dark: true}}
    settings["font_size"] = reflect.Any{14}
    if settings["theme"].get<Theme>() == .Val(view) -> print(view[0].dark)
    if settings["font_size"].get<String>() == None -> print("not text")
    counts := [reflect.TypeKey: Int]{}
    counts[reflect.key<Position>()] = 2
    p: Position{x: 1, y: 2}
    print(counts[reflect.of(p).key()])
}
```

**E: the box as a trait value (found while writing this report).** `Any` is
the trait every eligible type has, and a type pattern works on every trait value.
This reuses today's trait-value boxing (p03) and adds only the match that p10 lacks.

```jet
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Any]{}
    settings["theme"] = Theme{dark: true}        // boxes as any trait value does
    settings["font_size"] = 14
    if settings["theme"] == {
        Theme(theme) -> print(theme.dark)
        else -> print("no theme")
    }
    if settings["font_size"] == {
        String(text) -> print(text)
        else -> print("not text")
    }
    counts := [Type: Int]{}
    counts[Position] = 2
    p: Position{x: 1, y: 2}
    print(counts[type_of(p)])
}
```

E is the smallest addition, but it inherits two trait-value rules that conflict with
the uses above: a trait value cannot cross a task, and it converts wherever the
written type is `Any`. Converting wherever `Any` is written is the silent-conversion risk of C
in a milder form. A keeps E's type patterns and adds an explicit constructor,
so it gets neither cost.

## The recommended design (A), rule by rule

All of this is **proposed** unless marked.

1. **A type name in value position is a `Type` value.** `counts[Position]`
   and `type_of(p)` both give the `Position` type. In a generic body, `T` in
   value position gives the concrete type. `reflect(t)` takes a `Type`, so the
   ratified `reflect(Rock)` (D-REFLECT-TYPEINFO1) is this rule applied to
   `reflect`. Today, p09 is E0636 and p08 is E0102.
2. **A `Type` compares, hashes, keys maps and prints its path.** Identity is the
   compiler's canonical type identity. Aliases share it. Distinct nominal types,
   generic instances, and function types with different effect rows all differ.
   Equality is one comparison of the type's record.
3. **A `Type` grants nothing.** No value can be built from a `Type`, and nothing
   casts through one. The only way from a box back to a typed value is a type
   pattern that names the type in the source, so static checking is never
   bypassed.
4. **`Any(value)` is the only way to make a box.** Nothing converts to `Any`
   implicitly, so a wrong argument never compiles silently.
5. **A type pattern reads a box.** In `if box == { Theme(t) -> …, else -> … }`,
   `t` reads the payload in place, as any pattern binding does. `box.type` gives
   the payload's `Type`. `box.take<T>()` moves the payload out, or hands the box
   back unchanged on a mismatch. A switch on a box must end in `else`, because
   the set is open. When the set is closed, an enum is the tool, and it is
   exhaustive today (p05).
6. **What a box may hold.** It may hold any owned value whose type is known
   where the box is made, including functions and closures. A function's identity includes its whole
   signature and effect row, so calling one taken from a box is checked like
   any other call. Two facts of the payload are kept in the box's type, so
   nothing is hidden by boxing:
   - `Any` holds a value that may cross a task and whose drop only frees memory.
     This is D-PRIM-ANY1's original case, and it is sendable.
   - `Any.Local` holds a value that may not cross a task, and is itself
     not sendable.
   - `Any.Close` holds a Close value and is itself a Close value. Dropping it
     closes the payload exactly once, under the ordinary Close rules.
   - The two combine as `Any.Local.Close`.
   The constructor picks the narrowest type the payload allows. Storing an
   `Any.Close` where `Any` is expected is an error whose fix names the payload's
   close duty.
7. **`Any.View` borrows instead of owning.** It is a view, so it follows the view
   rules: it cannot be stored, returned or sent. It covers formatting and
   logging calls that take mixed arguments for the length of one call, the
   formatting case, without Jai's dangling pointer.
8. **Representation.** A box is four machine words: a pointer to its type's
   record, and a three-word inline buffer, as Swift's existential containers
   use. A payload that fits the buffer and its alignment is stored inline with
   no allocation. A zero-sized payload uses no buffer. A larger payload takes
   one allocation, owned by the box and freed once, under the ordinary
   allocation rule of the code that made it. A move or a borrow works the same for
   both forms.
9. **Type records only where used.** A type's record (identity, path, size,
   alignment, drop and close) is emitted only for types that are boxed, used as
   `Type` values, or reflected. That extends D-REFLECT-TYPEINFO1's requested
   default (**ratified** for reflection). A program that never boxes or names a
   type as a value carries no records.
10. **Secrets and capability tags.** A box prints only `Any(<type path>)`, never
    its payload. Taking a secret out gives the secret's own type back, with its
    own display limits. Moving a capability tag into a box and back keeps the
    same static type, and no box is built from integers or text, so authority
    is never forged.
11. **A box is never copied.** `.copy()` on a box is E0211, as for trait values
    today. A box is moved, or shared through `Shared<Any>`.

## Every downside, and how the design proposes to remove it

| Downside (from D-PRIM-ANY1, D-PRIM-TYPEKEY1 or the survey) | How A would remove it | Status |
|---|---|---|
| A box allocates per value | Inline three-word buffer; zero-sized payloads use none (rule 8) | proposed |
| Indirect access through a descriptor | One record comparison, then a direct read of the inline buffer or the one payload pointer: the same cost as an enum tag check plus a load | proposed |
| Descriptors cost space in every program | Records only for types boxed, named as values or reflected (rule 9) | ratified for reflection; proposed for boxes and types |
| Lost static checks | No implicit conversion (rule 4); no cast through a `Type` (rule 3); reads only through named type patterns (rule 5) | proposed |
| Downcast can panic or read garbage | A failed match takes `else`; a failed `take` hands the box back (rule 5) | proposed |
| Resources cannot be boxed | `Any.Close` closes its payload once (rule 6) | proposed |
| Functions cannot be boxed | A function's full signature and effect row are its identity (rules 2 and 6) | proposed |
| Thread-confined values cannot be boxed | `Any.Local` keeps them on one task (rule 6) | proposed |
| Loans cannot be boxed | `Any.View` for the length of a call (rule 7) | proposed |
| Secrets or tags could leak or be forged | Payload never printed; same static type out; no construction from data (rule 10) | proposed |
| An open switch can miss a case | `else` is required on a box; closed sets use enums, which are exhaustive (rule 5, p05) | today for enums; proposed for boxes |
| Types as values could bypass checks | A `Type` grants nothing (rule 3) | proposed |
| Type identity by display path is not exact (p07) | Canonical identity, not text (rule 2) | proposed |

## What remains, with its cost and best mitigation

- **Large payloads still allocate once.** A payload over three words costs one
  allocation per box. Mitigation: box a handle instead, such as a `Shared<T>`
  or a pool ID, which fits inline.
- **A stored box cannot hold a loan.** Jet has no stored borrow fields
  (spec, "Deliberately absent"), and a stored loan needs a lifetime the box cannot carry.
  Mitigation: `Any.View` for calls; an owned copy for storage.
- **A `Type` is not a persistent identifier.** Its identity holds within one
  built program. Its printed path is for people, and it can change between
  builds. Mitigation: an application that saves type names owns a versioned
  schema name, such as a field on its settings type.
- **A box is never copied.** Mitigation: share it with `Shared<Any>`, or take
  the payload out and copy that.
- **Four box types instead of one.** `Any`, `Any.Local`, `Any.Close` and
  `Any.View`. Mitigation: the constructor picks the type, the common case is
  plain `Any`, and each error names the fact that forced a wider type.

## Status ledger

- **Today:** enums with exhaustive match (p05), trait values with invisible
  boxing (p03), a type switch on generic parameters while building (p04), `Dyn`
  trees (p02), path-string keys (p07).
- **Ratified, not built:** one-call `reflect(x)` and `reflect(T)` with info kept
  only where requested (D-REFLECT-TYPEINFO1; p06 is E0102), and one signature
  schema for callables (D-META-REFLECT2).
- **Proposed here:** `Type` values and `type_of`, `Any` and its three
  variants, type patterns on boxes, the inline representation, and type
  records for boxes and type values.
- **Reversed if A is chosen:** the spec's "no general `Any` top type" line
  becomes "no implicit top type; `Any` is an explicit box", and the ratified
  D-PRIM-TYPEKEY1=A (an opaque `TypeKey`) is amended by D-PRIM-TYPEKEY2 to
  rule 1. `Examples/Types/NoAnyAlternatives.jet` gains a closing section on
  `Any` for the open-set case.
