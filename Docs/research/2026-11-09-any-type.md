# An any type: what it costs elsewhere, and a proposed Jet design

Date: 2026-11-09, corrected after BallotReview4 and repaired after BallotReview5. Decisions: D-PRIM-ANY1 (the any
box, open) and D-PRIM-TYPEKEY1 (ratified 2026-11-09 as A: an opaque
`core.reflect.TypeKey`). The types-as-values design in this report is a
proposal: it would amend the ratified TYPEKEY1 A as a new ballot,
D-PRIM-TYPEKEY2. Neither D-PRIM-ANY1's repair nor D-PRIM-TYPEKEY2 has passed an
adversarial review of its current text. Where a table below says how the design
removes a cost, that removal is proposed, not built or measured.
It builds on ratified decisions: D-REFLECT-TYPEINFO1 (one `reflect` call, with
run-time type info kept only for the types a program uses), D-META-REFLECT2
(one signature schema for every callable), D-OWES1 (`#MustFinish` duties with
`on_fail`), D-FNVAL-WRITE1 (access modes in function types, now `&` and `&&`
under D-MOVE-SIGIL1), D-MEM-WIPE1 (protected storage or refusal), D-SECRETEDGE1 (secret
sinks), D-TAG-MARKER1 (a tag is a field-less struct with a denial row) and S63
(automatic scope-end Close cleanup, including for List and Option payloads).

BallotReview5 independently reran p01–p14 on seed a0_042, using the dev
worktree's Core. Its logs are in that lane's `probes/any`. The snippets below
are illustrations of those cases; the full probe files are the evidence.
**Today** means exercised, **ratified** means decided, and **proposed** means
not decided or built. The current design remains **NOT CLEAN**.

## What an any type is for

An any type holds a value whose type is chosen at run time, and lets code ask
what that type is. Five uses come up again and again:

1. **Heterogeneous tables.** Settings, request context and blackboard maps hold
   a theme here and a number there, under string keys.
2. **Plugin registries.** A host stores values that plugins define and later
   hands each one back to the plugin that knows its type.
3. **Entity-component systems.** A world stores one table per component type,
   keyed by the type itself.
4. **Decoded-but-typed data.** A decoder produces a value of one of many types,
   and the caller branches on which type it got.
5. **Test doubles.** A fake records the arguments it was called with, whatever
   their types, for later checks.

These uses do not require one particular box design. Known sets can use an
enum; unknown plugins can implement an agreed trait interface. An arbitrary
box matters when the host must recover a concrete type outside such a closed
set or interface. ECS counting needs only the ratified `TypeKey`, not a box
or a new `Type` value.

## How other languages do it

| Language | Form | Representation | Allocation | Getting the type back | Failure mode | Ownership and lifetimes |
|---|---|---|---|---|---|---|
| Go | `any`, an alias of `interface{}` | type and data pointer | boxing can allocate; escape analysis and runtime scalar caches can avoid an allocation | `x.(T)`, `switch v := x.(type)` | `x.(T)` panics; `v, ok := x.(T)` does not; a type switch needs no exhaustiveness | garbage collected |
| Rust | `Box<dyn Any>` | a box plus a vtable pointer | one heap allocation, except for zero-sized types | `downcast_ref::<T>()`, `Box::downcast::<T>()` | `None`, or `Err(box)`, which hands the box back | `Any` only for `T: 'static`, so references with a non-`'static` lifetime are excluded; `&'static` data is allowed |
| Swift | `Any`, `any P` existentials | a three-word inline buffer, type metadata and witness tables | inline when the value's size and alignment fit the three-word buffer; otherwise a side allocation | `as?`, `as!`, `switch` with `case let x as T` | `as?` gives nil; `as!` traps | reference counted; value types copied in |
| C# | `object`; `dynamic` | a reference to a heap object | boxing a value type allocates and copies | `is T t`, `switch` type patterns | `(T)o` throws; `as` gives null; `dynamic` binds at run time | garbage collected; `dynamic` gives up compile-time checking |
| Java | `Object` | a reference | primitives are boxed, with some cached instances | `instanceof T t`, pattern `switch` | a bad cast throws `ClassCastException`; pattern switches must cover the input, often with a default for an open hierarchy | garbage collected; generic type arguments are erased |
| Kotlin | `Any`, `Any?` | a reference on the JVM | numbers boxed when typed as `Any` | `is T` smart casts, `when` | `as` throws; `as?` gives null; `when` is exhaustive over sealed types | garbage collected |
| TypeScript | `any` and `unknown` | erased at run time | none of its own | `typeof`, `instanceof`, user guards | `any` turns off checking; `unknown` must be narrowed before use | not applicable |
| Haskell | `Dynamic` with `Typeable` | a value paired with its type representation | a heap value, like all boxed values | `fromDynamic :: Typeable a => Dynamic -> Maybe a` | `Nothing` | garbage collected; `Typeable` derived automatically |
| Zig | `anytype` | none: the parameter's type is fixed while compiling | none | `@TypeOf`, `@typeInfo`, `switch` while compiling | a compile error | not a run-time box at all |
| Jai | `Any` | `type: *Type_Info` and `value_pointer: *void`, 16 bytes | none, because it points at the value | read `type`, then cast `value_pointer` | an unchecked cast reads the wrong bytes | the pointer does not own the value; it dangles if the value's storage goes away |

### The costs, gathered

- **Allocation.** A Rust heap box normally allocates, except for zero-sized
  payloads. C#/JVM primitive boxing can allocate; existing object references
  need no new box. Go also has escape-analysis and cached-scalar cases.
  Swift's inline buffer avoids a side allocation only when size and alignment
  fit. The cited Jai representation borrows storage instead of owning it.
- **Descriptors.** Runtime type recovery needs identity metadata. The exact
  retained graph and its cost depend on the language and build.
- **Lost static checks.** TypeScript `any` and C# `dynamic` turn checking off.
  Implicit conversion to a top type (Go `any` parameters, Jai `Any`, Kotlin and
  Java `Object`) lets a wrong argument compile.
- **Downcast failure.** A checked downcast gives an option (Rust, Swift `as?`,
  Haskell). An unchecked one panics or throws (Go `x.(T)`, Java, C#, Swift
  `as!`), or reads garbage (a Jai cast).
- **Ownership and lifetimes.** Rust refuses data borrowed for less than
  `'static` in `Any`. Jai allows any pointer, and the box can outlive the
  value. Garbage collection keeps referenced managed data alive. It does not
  itself perform scoped resource cleanup; explicit resource-management tools
  in those languages can still do so.

The spec lists a general `Any` top type under "Deliberately absent"
(`Docs/spec/spec.md`, section "Deliberately absent"), and
`Examples/Types/NoAnyAlternatives.jet` teaches the alternatives: an enum, a
generic, an optional and `Dyn`. Trait values are not copyable (E0211) and
cannot cross a task (the spec's task-boundary rule, E1102). Today, then, Jet
covers closed sets (enums), behavior sets (traits) and encodable data (`Dyn`).
An enum payload can hold a resource or a function, but only for a set of types
written in advance. Jet has no box that keeps an arbitrary owned value, and no
type value.

## Jet's options, as the same program

Each option shows the same program. It keeps a theme and a font size in one
settings map, reads the font size back with a check that fails safely, and
counts entities by type. D-PRIM-ANY1 also shows a larger program under every
option, with an open file, a save callback and an order that must be committed
or rolled back, because a settings map alone does not test resources,
functions or duties.

**A, recommended (proposed): an explicit box on the trait-value carrier, and
type values.** The `Type` half is D-PRIM-TYPEKEY2's option A. Under the
ratified D-PRIM-TYPEKEY1, the last three lines use `reflect.TypeKey` as in D
below, and the box half is unchanged.

```jet
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Any]{}
    settings["theme"] = Any(Theme{dark: true})
    settings["font_size"] = Any(14)
    if settings["theme"] == {
        Theme(theme) -> print(theme.dark)        // true
        else -> print("no theme")
    }
    if settings["font_size"] == {
        String(text) -> print(text)
        else -> print("not text")                // printed
    }
    counts := [Type: Int]{}
    counts[Position] = 2
    p: Position{x: 1, y: 2}
    print(counts[type_of(p)])                    // 2
}
```

**B: today's tools (runs today, p12).**

```jet
use reflect: core.reflect

#Codable
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Dyn]{}
    settings["theme"] = Theme{dark: true}.encode()
    settings["font_size"] = 14.encode()
    theme: settings["theme"].decode<Theme>() ?? return
    print(theme.dark)                            // true
    if settings["font_size"].decode<String>() == {
        .Ok(text) -> print(text)
        .Err(errors) -> print("not text")        // printed
    }
    counts := [String: Int]{}
    p: Position{x: 1, y: 2}
    counts[reflect.of(p).path()] = 2
    print(counts[reflect.of(p).path()])          // 2
}
```

**D: library key and library box for plain owned data (the open D-PRIM-ANY1
text on Tower and the ratified D-PRIM-TYPEKEY1 A).**

```jet
use reflect: core.reflect

```

**E: the box as the empty trait, with implicit conversion.** `Any` is the
trait every type has, and a type pattern works on every trait value. This is
A's mechanism and rules, with one difference: values convert to `Any`
wherever it is written, as they convert to any trait today (p03).

```jet
Theme: struct { dark: Bool }
Position: struct { x: Int, y: Int }

run: fn() {
    settings := [String: Any]{}
    settings["theme"] = Theme{dark: true}        // boxes as any trait value does
    settings["font_size"] = 14
    if settings["theme"] == {
        Theme(theme) -> print(theme.dark)
        else -> print("no theme")
    }
    if settings["font_size"] == {
        String(text) -> print(text)
        else -> print("not text")
    }
    counts := [Type: Int]{}
    counts[Position] = 2
    p: Position{x: 1, y: 2}
    print(counts[type_of(p)])
}
```

**F: explicit erasure for every trait.** A's mechanism and rules, but every
conversion to a trait value is written `erase<Trait>(value)`, so p03's list
becomes `[Shape]{erase<Shape>(Square{side: 2}), …}`. The settings lines read
`settings["theme"] = erase<Any>(Theme{dark: true})`; the rest is as in A.

A and E share one mechanism. A's only difference from E is that `Any` is
built with an explicit call. A trait bound limits what converts to other
traits, so their implicit conversion is checked; `Any` has no bound, so
implicit conversion would accept every wrong argument. F applies the explicit
rule to every trait, at the cost of rewriting every existing trait-value use.

## The recommended design (A), rule by rule

All of this is **proposed** unless marked. Rules 1 to 3 are D-PRIM-TYPEKEY2's
option A; rules 4 to 17 are D-PRIM-ANY1's option A. Either can be chosen
without the other.

1. **A bare type name is a `Type` value where a `Type` is expected.** That is a
   `Type` parameter, field or result, a `[Type: V]` key, a `[Type]` element, an
   `==` against a `Type`, or a switch pattern. Elsewhere it stays E0636, whose
   fixes are `Rock{…}` for a value and `Type{Rock}` for a type. `type_of(x)`
   takes only a name or field path and is static: it does not evaluate,
   borrow or run effects. On a box it gives the box's type; the payload's type
   comes from the box. Today, p09 is E0636 and p08 is E0102.
2. **A `Type` compares, hashes, keys maps and prints its path.** Identity is the
   compiler's canonical type identity,
   including checked package identity and content, declaration revision and
   generic type/value arguments. Callable identity follows canonical sema
   equality, including labels, zones, access modes and effects; it is not
   reduced to parameter types. The proposed process table retains descriptors
   across unloads. Version alone does not distinguish equal-version packages
   with different checked identities, so a display qualifier is needed too.
3. **A `Type` grants nothing.** No value can be built from a `Type`, and nothing
   casts through one. `reflect(t)` on a written `Type` value is a compile error
   whose fixes are `t.info()` or `reflect(Type)`; a generic `reflect(x)` keeps
   its value meaning even when `T` is `Type`. `t.info()` returns
   `reflect(T)`'s value or an `InfoError` (`NotKept` or `Unloaded`). Type
   records are kept under every D-REFLECT-TYPEINFO1 setting; under `none`,
   `t.info()` is a compile error, and under `requested`, a program that calls
   `t.info()` keeps the info of every type it turns into a `Type` value,
   listed in the build report. A package built for loading keeps info for its
   exported types and the types it makes into `Type` values, with their field
   graphs; privacy is checked by package identity at run time. The loader
   counts references from info, function values and boxes, and releases a
   retired package's code at zero; `Type` values hold only descriptors, which
   are never freed. A hot-reload identity includes the declaration revision and
   its fields' identities, with mutually recursive types hashed as one group.
4. **One mechanism.** `Any` is the empty trait, which every type has, and an
   `Any` value is a trait value of it. It uses the one trait-value carrier,
   checker and runtime. That carrier gains inline storage, type patterns and
   `take` for every trait. The proposed `Square(sq)` type pattern is new;
   p10 proves only that today's enum-style `.Square(sq)` pattern is refused.
5. **`Any(value)` is the only way to make an `Any`.** Nothing converts to `Any`
   implicitly; erasure is visible. An explicit `Any(wrong_value)` can still
   be the wrong payload for an application's protocol. Other traits keep
   their implicit conversion.
6. **What a box may hold.** An owned value meeting the carrier restrictions:
   data, resources, functions and closures, and values with D-OWES1 duties,
   with its type known at construction. A value that holds a loan is refused,
   as storing a loan in a field is today. Two static facts pick one of four
   carrier forms: whether the payload may cross a task, and whether it owes a
   duty. The forms are `Any`, `Any.Send`, `Any.Owes` and `Any.Send.Owes`. A
   form widens implicitly to one that drops `Send` or adds `Owes`; nothing
   narrows except through `take`. So one `[String: Any.Owes]` map holds a
   theme, a file, a callback and an owed Order, and the whole map then owes a
   duty: it must be drained on every success path.
7. **Reading by pattern.** In `if box == { Theme(t) -> … else -> … }`, `t` is a
   read-only loan of the payload for the length of its arm, and the box stays
   where it was. A switch on a box must end in `else`, because the set is
   open. When the set is closed, an enum is the tool, and it is exhaustive
   today (p05). To change a payload, take it, change it and box it again.
8. **Taking the payload.** `box.take<T>()` consumes the box. On a match it gives
   the `T`. On a mismatch it fails with `TakeMismatch<C>`, where `C` is the
   box's own carrier type; its `box` field holds the original box unchanged,
   with the expected and found type paths. It owes a duty exactly when `C`
   does, by D-LIN-CONTAINER1's rule for a `Result` holding one. For plain
   `Any`, `take<Int>() ?? return` drops the error and the box, which runs the
   payload's cleanup. For `Any.Owes`, that line is D-OWES1's unfinished-value
   error, because `return` is a success exit; the fix finishes `err.box` in
   the `??` block, stores it, or propagates with `?`. Propagating hands the
   box on, so `on_fail` does not run, and the caller's contract names
   `TakeMismatch<C>`. Converting that error or returning it from `run` first
   needs the box finished.
9. **Cleanup and duties.** Dropping a box runs its payload's cleanup through
   the descriptor, exactly once, under the same S63 rules that already close a
   resource held in a List payload, on success, error, panic and cancellation
   exits. The Prelude `Close` is `close: fn(&&self) Never!` with no effect row
   (Traits.jet:198-201), so dropping a box needs no effect. `Any.Owes` is
   declared in Core as `#MustFinish(take, fail, on_fail: fail)`, so D-OWES1's
   checker applies unchanged: a successful `take<T>()` hands the typed duty to
   the caller, and `fail()` runs the payload's `on_fail`, or only its cleanup
   when it owes nothing. An error exit runs `fail()`; on a success exit an
   unfinished box is D-OWES1's E0140-family error. A failing `on_fail` on an
   automatic exit is attached as a note and the box counts as finished; an
   explicit `fail()` returns an `OnFailError` (payload error plus type path),
   finished either way. The carrier names `on_fail`'s effects, as in
   `Any.Owes[DB]`. A duty type without `on_fail` is boxed with
   `Any.Owes(order, on_fail: rollback)`, naming one of its listed finishing
   methods that takes only `&&self`. Containers reuse D-OWES1 and
   D-LIN-CONTAINER1 with no second rule: overwrite is refused, `insert_new`
   and `swap` hand the old box back, and a drain loop hands each box over.
10. **Functions and closures.** A pattern must name a function payload's exact
    type, its full signature with marks and effect row, so calling a function
    taken from a box is checked like any other call, effects included. Boxing
    a closure moves it with its captures; a loan capture is refused, a capture
    that cannot cross a task keeps the box out of the `Send` forms, and capture
    cleanup runs on drop. The box adds no authority.
11. **Tags and protected storage.** A box made from a tagged value is tagged on
    its contents: `Any(token)` with `token: #Credential String` has type
    `#Credential Any`, an untagged map refuses it with the ordinary tag error,
    and a pattern must name `#Credential String(text)`, whose binding keeps the
    tag. D-TAG-MARKER1's denials and D-SECRETEDGE1's sinks apply unchanged.
    The payload's type is public unless the box was made inside a branch on a
    secrecy tag; then a type test on it is a branch on that tag. The seed's
    checker does not yet tag a branch by its condition, and A depends on that
    fix, which D-SECRET-CT1 also needs. Under D-SECRET-CT1's fixed-time tag,
    type tests and `take` on a `#Secret Any` compare the public type and bind
    `#Secret T`, and making a box, or an enum whose cleanup depends on its
    variant, inside a `Secret` branch is refused. Under D-MEM-WIPE1 a sensitive
    payload is never inline in ordinary memory: it lives in protected storage,
    wiped when the box drops. That covers Jet-owned storage (scalars, structs,
    fixed arrays, owned list and string buffers); a foreign handle under a
    sensitive tag is refused, as D-MEM-WIPE1 refuses it in a typed field.
    Printing a box shows only `Any(<type path>)`, but confidentiality comes
    from the static tag, not from printing.
12. **Representation.** A box is four machine words: a descriptor pointer and a
    three-word, pointer-aligned buffer, as in Swift's `Any` container. Every
    trait value uses this layout, and a method call loads the trait's witness
    table from the descriptor; `Any`'s witness table is empty.
    A payload is stored inline only when its size fits three words, its
    alignment fits a pointer, and it is not sensitive. A zero-sized payload
    uses no buffer bytes but keeps its descriptor and cleanup. Any other payload
    takes side storage following D-ALLOC-SITE1's contextual allocator contract.
    The existing escape checker must cover both the outer box and the payload's
    own stored graph. Sensitive storage also meets D-MEM-WIPE1.
    Allocations the payload owns itself, such as a `String`'s bytes, remain.
13. **Descriptors only where used.** A descriptor exists for each pair of
    payload type and carrier trait actually boxed. It holds the type's
    identity, size, alignment, cleanup, the trait's witness table and, for the
    `Owes` forms, `on_fail`. Its identity is shared
    with the `Type` record of rule 2. A descriptor is not type info, so it is
    kept under every D-REFLECT-TYPEINFO1 setting. TYPEKEY1 or TYPEKEY2 B/F
    gives `box.key(): reflect.TypeKey`. TYPEKEY2 A gives `box.type: Type`;
    E gives `box.type: reflect.Type`. C/D omit that public projection while
    checked extraction still uses canonical identity internally.
14. **A box is never copied.** `.copy()` on a box is E0211, as for trait values
    today (p14). When the payload's type is copyable, a pattern arm can copy
    the borrowed payload; otherwise take it out.
15. **Erasure never flattens.** `Any(shape)` on a `Shape` trait value boxes the
    trait value itself, so `Shape(s)` matches and `Square(sq)` does not.
    `Any(x)` on a value that is already one of the four forms is an error whose
    fix is widening.
16. **Code lifetime.** A descriptor points into its package's code for cleanup,
    `on_fail` and the witness table, so a live box counts as a reference to
    that package. Unloading keeps the code until the count reaches zero; this
    is the loader count of rule 3, defined here too for TYPEKEY2's other
    options.
17. **Migration.** There are no `Any` callers today (p01), but inline storage
    and descriptor witness tables change every trait carrier's layout, a
    coordinated cutover.

## Every downside, and how the design proposes to remove it

| Downside (from D-PRIM-ANY1, D-PRIM-TYPEKEY1 or the survey) | How A would remove it | What remains | Status |
|---|---|---|---|
| A box allocates per value | Inline three-word buffer for payloads whose size and alignment fit and that are not sensitive (rule 12) | Large, over-aligned and sensitive payloads allocate once | proposed |
| Indirect access through a descriptor | Compare canonical identity; inline storage avoids the side-pointer dereference (rule 12) | Descriptor storage, indirect cleanup and four words for Any; a large payload need not be one load. No measured enum equivalence | proposed |
| Descriptors cost space in every program | One descriptor per type actually boxed (rule 13) | A program that boxes keeps those descriptors under every type-info setting | ratified for reflection; proposed for boxes and types |
| Lost static checks | Explicit construction; no cast through Type; checked patterns or take | An open switch needs else; explicit construction does not validate a caller's intended payload type | proposed |
| Downcast can panic or read garbage | A failed match takes `else`; a failed `take` returns the box in a `TakeMismatch<C>` that owes what `C` owes (rule 8) | Dropping a mismatch of an owed carrier is a compile error; the fix finishes or propagates it | proposed |
| Resources cannot be boxed | The descriptor runs the payload's own S63 cleanup once (rule 9) | None beyond S63's rules | proposed |
| Duties cannot be boxed | The `Owes` forms, `#MustFinish(take, fail, on_fail: fail)` under D-OWES1 (rule 9) | A duty type without `on_fail` names its error finish where it is boxed; a map holding a duty must be drained | proposed |
| Functions cannot be boxed | A function's full signature, marks and effect row are its identity (rules 2 and 10) | Patterns must spell the whole function type | proposed |
| Values that cannot cross a task | Plain `Any` keeps them and is not sendable; the `Send` forms cross (rule 6) | Four forms from two facts; widening is implicit | proposed |
| Loans cannot be boxed | Not removed: a box holding a loan is refused | Generic `fn<T>(x: &T)` covers a call-scoped borrow | proposed |
| Secrets or tags could leak or be forged | The tag is static on the box and its bindings; sensitive payloads use protected storage; branches on a tagged box carry the tag (rule 11) | Depends on the branch-tagging fix D-SECRET-CT1 also needs | proposed |
| An open switch can miss a case | `else` is required on a box; closed sets use enums, which are exhaustive (rule 7, p05) | | today for enums; proposed for boxes |
| Types as values could bypass checks | A `Type` grants nothing (rule 3) | | proposed |
| Type identity by display path is not exact | Canonical identity, not display text (rule 2) | Descriptor lifetime and retention costs | ratified for TypeKey; proposed for Type |

## Contracts closed in the BallotReview5 repair, and what stays open

The repair writes exact contracts for each case BallotReview5 left open:
the four carrier forms and the one owed map (rule 6), the owed mismatch
(rule 8), cleanup effects, `on_fail` failure and duty types without
`on_fail` (rule 9), captures and authority (rule 10), tags under fixed time
and protected storage (rule 11), witness layout (rule 12), nested erasure
(rule 15), code lifetime (rule 16), and TYPEKEY2's reflection split and loaded
packages (rule 3). This report's examples now use `#Credential` where a
leak-only tag fits, matching D-SECRET-CT1's widths rule.

What stays open: these are proposed contracts, not built ones, and no probe
exercises them. The `Any.Owes` checker is D-OWES1's extended to erased
carriers, so its strength is that extension's. The repaired ballots have not
had a fresh adversarial review.

## What remains, with its cost and best mitigation

- **Some payloads still allocate once.** A payload over three words, one
  aligned more strictly than a pointer, or a sensitive one costs one side
  allocation per box. Mitigation: box a handle instead, such as a pool ID,
  which fits inline; a handle brings its own lifetime and lookup rules.
- **A box cannot hold a loan.** Jet has no stored borrow fields (spec,
  "Deliberately absent"), and a stored loan needs a lifetime the box cannot
  carry. Mitigation: a generic `fn<T>(x: &T)` for a borrow that lasts one call,
  and an owned value for storage.
- **A `Type` is not a persistent identifier.** Its identity holds within one
  linked program. Its printed path is for people, and it can change between
  builds. Mitigation: an application that saves type names owns a versioned
  schema name, such as a field on its settings type.
- **A box is never copied.** Mitigation: when the payload's type is copyable,
  copy it from a pattern arm; otherwise take it out, or share the box through
  `Shared<Any>`.
- **Four carrier forms instead of one.** `Any`, `Any.Send`, `Any.Owes` and
  `Any.Send.Owes`, from two facts. Mitigation: forms widen toward
  `Any.Owes`, and each error names the fact that needs a wider form.
- **A map holding one duty owes as a whole.** It must be drained on every
  success path. Mitigation: one drain loop finishes each box by `take` or
  `fail()`.

## Status ledger

- **Today:** enums with exhaustive match (p05), trait values with invisible
  boxing (p03), a type switch on generic parameters while building (p04), `Dyn`
  trees (p02), path-string keys (p07).
- **Ratified, not built:** one-call `reflect(x)` and `reflect(T)` with info kept
  only where requested (D-REFLECT-TYPEINFO1; p06 is E0102), one signature
  schema for callables (D-META-REFLECT2), the opaque `TypeKey`
  (D-PRIM-TYPEKEY1), duties with `on_fail` (D-OWES1), and protected storage
  for sensitive values (D-MEM-WIPE1).
- **Proposed here:** `Type` values and `type_of` (D-PRIM-TYPEKEY2), `Any` with
  its further forms `Any.Send`, `Any.Owes` and `Any.Send.Owes`, inline storage,
  witness tables and type patterns on the trait-value carrier, the duty and
  tag rules for boxes, and descriptors for boxed types (D-PRIM-ANY1).
- **Reversed if A is chosen:** the spec's "no general `Any` top type" line
  becomes "no implicit top type; `Any` is an explicit box".
  `Examples/Types/NoAnyAlternatives.jet` gains a closing section on `Any` for
  the open-set case. If D-PRIM-TYPEKEY2 also selects A, the ratified
  D-PRIM-TYPEKEY1=A is amended by it.
