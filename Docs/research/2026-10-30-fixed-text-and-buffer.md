# One text type, fixed through `::` and edited through `:=` (card #6342)

Date: 2026-10-30. Lane: SurfaceDesign-2. Dev: 4e514f96e1.

The owner asked for a fresh look at strings. Strings should be fixed, and text
should be easy to build, perhaps like Odin's string builder. The owner floated
`Text` as a name. He later said he leans toward one type for simplicity, with
growth explicit and visible.

This note maps today's `String`, measures what it costs against Rust, surveys
peers, and proposes a model and a name. It ends with the migration size, the
`jet fix` rule for each option, and paired perf cells. Two ballots carry the
owner choices: D-TEXT-FIXED1 (the model) and D-TEXT-NAMES1 (the name).

## 1. What `String` is today

### 1.1 The value is already fixed

Every probe below ran with the dev compiler on O0, O1 and O2 and gave the same
result on all three. The probe sources are in
`$JET_SCRATCH_ROOT/lanes/SurfaceDesign/probes/m6342` and `m6342b`, generated by
`gen6342.mjs` and `gen6342b.mjs`.

| probe | code | result |
|---|---|---|
| s01 | `s :: "a"` then `s += "b"` | E0111: made with `::`, so it can't change |
| s02 | `s := ""`, five `s += "{i}"` | `01234` |
| s03 | `s := "ab"`, `t :: s`, `s += "c"` | `abc ab`: the shared text is untouched |
| s10 | `s = ""` then `s += "d"` | `d` |
| s11 | `fn fill(out: &String) { out += "ab" }` | `xab` |
| s12 | `p.name += "b"` on a struct field | `ab` |
| s13 | `xs[0] += "!"` on a list item | E0164: compound assignment can't target an indexed slot |
| s14 | `s += "x"` on a plain parameter | E0111 |
| s17 | `t :: s.copy()` then `s += "c"` | `abc ab` |
| s18 | a lambda that does `s += x` | `ab` |
| s38 | `s = "{s}{i},"` four times | `0,1,2,3,` |
| b16 | `t := s` from a `^String` parameter, then `t += "!"` | `hi!` |

So no operation changes a `String` value that another name holds. `+=` changes
the name, like `n += 1`. The runtime says so directly: text is immutable once
published, and only a sole owner is written in place
(Compiler/JetRuntime/Source/Text.jet:54-58). `jet_rt_string_append` appends in
place only when the owner is unique and not a literal. Otherwise it builds a
fresh text (Text.jet:357-367).

The owner-notes digest of 2026-10-07 answered this question once already. It
said a `::` string is fixed and a `:=` string is the builder, and recommended
one type (Docs/audits/2026-10-07-owner-notes-digest.md:413-436). The owner has
now asked again and leans toward one type, so this note keeps a second type as
a ballot option with its costs stated.

### 1.2 What is missing

| probe | code | result |
|---|---|---|
| s08 | `s.push("c")` | E0311: `push` isn't a method |
| s09 | `s.clear()` | E0311 |
| s16 | `s.insert(1, "b")` | E0311 |
| s15 | `String.with_capacity(64)` | E0107: nothing named `String` exists here |
| b06 | `&s.try_push("c")` in `run` | E2402: can't convert `AllocError` into `Err` |
| s45 | `&s.try_push("c") ?? panic(..)` | internal compiler error, exit 101 |
| s05 | `a + b` on two Strings | E0109 (S8: no `+` on text) |
| s06, s07 | `s[0]`, `s[0] = 'z'` | E0503 |
| s36 | `Bytes.with_capacity(16)` | E2104: `Bytes` is not built yet |
| m6342c | `fn show(t: Text)`, and the same with `StringBuffer` and `StringBuilder` | E0119: there's no type called `Text` (and so on) |

The only editing method is `try_push`. It is declared as a write in
Compiler/JetFoundation/Source/Registry/BuiltinMethods.jet:82-182, and every
other String method is a read. In practice it cannot be called (s45, b05, b06).
D-CORE-IO-BUF1 named `Bytes` as the growable buffer, but `Bytes` does not
build today (s36).

D-STR-DECLINE1=C declined the mutation verbs `clear`, `push`, `pop`, `remove`
and `write` because they "clash with immutable String". D-STRING-EMPTY1=A
chose `s = ""` over a `clear` method. D-EFF-FORMAT-WRITER1=A says "String
remains the one public text type".

### 1.3 Representation and its costs

A heap text is a 32-byte block `[count][data, len, cap]` from
`jet_rt_alloc_8`, and the bytes live in a second allocation
(Text.jet:54-63, 74-77). So every fresh text costs two allocations. Literals
are static headers with cap 0 (Text.jet:67-72).

`len()` counts Unicode scalars (S41, Docs/spec/syntax-decisions.md:1657-1658).
Its body is `receiver.chars().len()`, which builds a list of every character
first (Core/Text/String.jet:15-17).

`slice(a, b)` takes scalar positions. The runtime first counts every scalar of
the whole text, then walks to `a`, then to `b`, then copies the bytes
(Text.jet:686-733, 98-100). D-FOUND-VIEW1=A promised views everywhere, but a
slice is a scan plus a copy.

`trim`, `after` and `before` are zero-copy when the call is bound with `::` to a
local, on a local or parameter (Compiler/JetSema/Source/Sema/Ownership/StringViews.jet:1-8;
spec.md:1375-1396). Its Jet-level type stays `String`. At a return or a field,
`View<str>` states that a value is such a window
(Examples/features/memory/returned_views.jet:4-30), and returning one works
(probe b13). Passing `s.trim()` to a `View<str>` parameter is E0112 (probe
b04); no example uses `View<str>` as a parameter type.

### 1.4 Measured cost against Rust

The machine is shared and its load average was 60 to 95 on 32 cores during the
runs. Wall time was useless, so every kernel ran three times under `perf stat`.
The tables keep the minimum user-space cycles and instructions, in millions.

Jet kernels: `probes/k6342/*.jet` (from `gen6342k.mjs`). Rust peers:
`probes/r6342/kernels.rs`, built with rustc 1.97.1 at `-C opt-level=3`.
Harness: `probes/pstat.sh`. Results: `probes/pstat6342.tsv`.

two columns divide Jet O2 by Rust O3.

| `append_self_interp` | 1,129 / 3,597 | 1,031 / 3,591 | 951 / 3,571 | did not finish | did not finish | did not finish | n/a | n/a |
| `fresh_small` | 1,549 / 7,048 | 1,462 / 6,943 | 1,914 / 6,475 | 2,413 / 6,630 | 317 / 919 | 284 / 948 | 6.04 | 7.05 |
| `len_loop` | 822 / 4,825 | 1,171 / 4,824 | 1,143 / 4,821 | 63 / 189 | 39 / 149 | 39 / 149 | 29.31 | 32.36 |

Reading the table:

- Every kernel that finished printed the same output in Jet and Rust. No
  kernel meets the 1.05 gate (AGENTS.md:149-154) at O2.
- `append_self_interp` writes `s = "{s}{i % 97},"` a million times. Jet costs the same as
  `append_plus_eq`, so it appends in place. The Rust peer, `s = format!("{}{},", s, i % 97)`,
  copies the whole text each step and did not finish within 150 seconds.
- `len_loop` needs 32 times Rust's instructions, because `String.len()` builds
  a `[Char]` list first (Core/Text/String.jet:15-17); Rust counts with
  `chars().count()`. Counting bytes instead,
  `bytes_len_loop` is 9 times Rust, at tiny absolute cost.
- `slice_loop` is the worst row, about 11,000 times Rust's instructions. Each
  slice counts every scalar of the text and then copies (Text.jet:686-733).
- Appending (`append_plus_eq`, 10.66) and building small fresh strings
  (`fresh_small`, 7.05) cost 7 to 11 times Rust. These are the costs the
  one-type design must close with `reserve` and in-place growth.
- `trim_loop` is 10.44 and `split_join` 17.27 times Rust's instructions.
  `share_append` is too small to read: 20 against 1 million instructions.

## 2. Peers

| language | fixed text | growable text | `+=` on fixed text | source |
|---|---|---|---|---|
| Go | `string` (immutable byte slice) | `strings.Builder` | yes, builds a new string | pkg.go.dev/strings#Builder |
| Java | `String` | `StringBuilder` | yes, new string | docs.oracle.com java.lang.StringBuilder |
| C# | `string` | `StringBuilder` | yes, new string | learn.microsoft.com System.Text.StringBuilder |
| Dart | `String` | `StringBuffer` | yes, new string | api.dart.dev dart:core StringBuffer |
| Kotlin | `String` | `StringBuilder`, `buildString {}` | yes, new string | kotlinlang.org |
| Odin | `string` (pointer and length) | `strings.Builder` | no | pkg.odin-lang.org/core/strings |
| Zig | `[]const u8` | `std.ArrayList(u8)` with a writer | no | ziglang.org/documentation/0.15.2 |
| Rust | `&str` (view) | `String` | `String += &str` appends in place | doc.rust-lang.org/std/string |
| Swift | `String` and `Substring` share storage | `var String` grows in place | yes, in place | docs.swift.org Substring |
| Mojo | `StringSlice` (view) | `String` grows in place | yes | mojolang.org/docs/std/collections/string |

Two families exist. Go, Java, C#, Dart and Kotlin pair a fixed `String` with a
separate builder, and `+=` on the fixed type gives the name a new value. Rust,
Swift and Mojo make the main `String` growable and add a view type. Odin and
Zig have a fixed slice and a growable buffer, and no `+=`.

Jet's semantics sit closest to Swift: the value never changes under another
holder, a `:=` name may grow, and a sole owner appends in place, as CPython also
does for `str`. Swift adds in-place editing on `var` strings through copy on
write, which is what option A of D-TEXT-FIXED1 adds to Jet.

## 3. The design

### 3.1 Model (ballot D-TEXT-FIXED1)

Option A, recommended: one `String`, which stays a value. A `::` name never
changes. A `:=` name or a `&String` parameter may grow with `+=`. It may also
be edited in place with `&` calls, as lists are: `&s.insert(at, text)`,
`&s.remove(from, to)`, `&s.truncate(n)` and `&s.reserve(n)`.
`String.with_capacity(n)` and `s.capacity()` join them, and `&s.try_push(x)`
is fixed. Appending stays `+=` and emptying stays `s = ""`, so no `push` or
`clear` is added.

This is Swift's model: one value-type String with copy on write, where a `let`
name never changes and a `var` name may be edited. Jet already chose the memory
side. D-COPY-DEFAULT1=A gives every heap value copy on first write, and drops
the sharing test for values the compiler proves unique. Probe s03 shows the
value rule today: `s := "ab"`, `t :: s`, `s += "c"` prints `abc ab`.

Fixed is checked, not a convention. `s += "b"` on a `::` name is E0111, and
`&xs.push(2)` on a `::` list is E0202 (probe `m6342c/q1_fixed_list_push.jet`).
The new String calls get the same check.

Option B is the two-type design that v1 of the ballot recommended: String keeps
no editing calls, and a separate `StringBuffer` edits in place. It matches Java,
Go, C# and Dart, and keeps D-STR-DECLINE1 as it is. It adds no safety, because
no edit can reach a String another name holds under A either. It adds no speed,
because a buffer runs the same append code as `+=`. It costs a second type,
conversions at every hand-off, and reopens D-EFF-FORMAT-WRITER1 and
D-CORE-IO-BUF1. Option C keeps today's model with no editing calls.

A amends D-STR-DECLINE1, which declined mutation verbs because they "clash with
immutable String". Under A no value changes under another holder, so the reason
no longer applies to these calls. `push` and `clear` stay declined. A also
turns D-STRING-EMPTY1's permission into a rule: `s = ""` on a `:=` String that
nothing else holds keeps its storage on every tier.

### 3.2 Name (ballot D-TEXT-NAMES1)

With one type, the vote is that type's name. Option A, recommended, keeps
`String`. Option B renames it `Text`. If D-TEXT-FIXED1 picks a second type, A
names it `StringBuffer` and B names it `TextBuffer`.

The text type is the most common type in Jet code, so its name should be the one
newcomers already type. Python, Java, Go, C#, Kotlin, Swift, Dart and
JavaScript all call it `String` or `string`. Renaming it touches 81,344
mentions. The earlier idea of `Text` fixed and `String` growable needs two
types, so it falls away with one.

## 5. Compiler criteria (no owner choice)

These hold under every option and need no ballot. Each one names the file to
change and the cell that proves it.

1. One allocation per fresh text: header and bytes together, so `"{a}{b}"`
   costs one `jet_rt_alloc` instead of two (Text.jet:54-63, 74-77). Cell:
   `text/string_fresh`.
2. `len()` without a list: a scalar count that walks the bytes once, with no
   allocation (Core/Text/String.jet:15-17). Cell: `text/len_loop` (new).
3. An all-ASCII flag set when text is built. For ASCII text, `len()` is the
   byte count and scalar positions are byte offsets, so `slice` and `insert`
   positions cost nothing to find. Cells: `text/len_loop`, `text/slice_loop`.
4. `slice` without the full scan: walk only to the end position, never count
   the whole text first (Text.jet:690-733). Cell: `text/slice_loop` (new).
5. Views wherever D-FOUND-VIEW1 promised them: `slice`, `trim`, `after`,
   `before`, `split` and `lines` return zero-copy windows in every read
   position, not only a `::` binding. Storing one still copies, as that
   decision says. Cells: `text/trim_loop` (new), `text/split_join`.
6. `try_push` lowers instead of failing the IR build. Repro: probe s45.
7. Capacity from the allocator's size class, so a String needs no separate
   `cap` word and `+=` still grows geometrically. Cell: `text/self_append`.
8. Under D-TEXT-FIXED1 A, `s = ""` on a sole-owner `:=` String keeps its
   storage on every tier, and each edit call on a value proved unique has no
   sharing test. Cell: `text/edit_rows` (new).

## 6. Paired perf cells

AGENTS.md:171-174 says a surface added for performance needs a paired
two-program cell against the plain spelling it replaces. Ratification waits
until the surface strictly beats the plain form. AGENTS.md:151-154 sets the
Rust gate: Jet/Rust at or below 1.05 is parity, and every other peer must be
beaten outright.

| cell | plain form | surface or peer form | proves |
|---|---|---|---|
| `text/edit_rows` (new) | `line = ""`, `line += "{cell},"`, `line = "> {line}"` per row | `&line.truncate(..)`, `&line.insert(0, "> ")` on a reused `:=` String | in-place edits beat rebuilding text (D-TEXT-FIXED1 A) |
| `text/insert` (new) | `s = "{s.slice(0, k)}x{s.slice(k, n)}"` | `&s.insert(k, "x")` | in-place insert beats two slices and a concat |
| `text/self_append` vs `text/self_append_builder` (exist) | `s = "{s}…"` | list of pieces joined | already paired; add a `String.with_capacity` plus `+=` third arm |
| `text/string_fresh` (exists) | Jet | Rust `String` built per call | criterion 1 |
| `text/len_loop` (new) | Jet `s.len()` | Rust `s.chars().count()` | criteria 2 and 3 |
| `text/slice_loop` (new) | Jet `s.slice(a, b)` | Rust `&s[a..b]` | criteria 3, 4 and 5 |
| `text/trim_loop` (new) | Jet `padded.trim()` | Rust `padded.trim()` | criterion 5 |
| `text/split_join` (exists) | Jet | Rust `split(',').collect().join(";")` | criterion 5 |

Each new cell's Jet source and Rust peer is already written:
`probes/k6342/*.jet` and `probes/r6342/kernels.rs`, one kernel per argument.

## 7. Bugs found

1. `&s.try_push("c") ?? panic("no memory")` is an internal compiler error on
   O0, O1 and O2: "ir.build unlowered: mutating builtin TryStringPush on
   String". Repro: `probes/m6342/s45_amp_method_on_string.jet`.
2. `Bytes.with_capacity(16)` is E2104, "`Bytes` is not built yet", although
   D-CORE-IO-BUF1=A names `Bytes` as the growable buffer. Repro:
   `probes/m6342/s36_bytes_builder.jet`.
3. `s.len()` builds a list of every character to count them
   (Core/Text/String.jet:15-17). See the `len_loop` row in section 1.4.
4. `s.slice(a, b)` counts every scalar of the whole text and then copies
   (Text.jet:686-733), against D-FOUND-VIEW1=A. See the `slice_loop` row.
5. An unknown parameter type gives E0119 and then a second error, E0112
   "`print` doesn't know how to show `Text`", for the same unknown name.
   Repro: `jet check probes/m6342c/p_Text.jet`.
