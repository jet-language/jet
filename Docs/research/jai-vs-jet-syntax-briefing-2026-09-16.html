What Jai actually is

Jai’s bet is not “nice procedure syntax.” It is: the compile-time program is the same language as the runtime program, sharing functions, data, and memory. The compiler is a bytecode interpreter plus an AST/message loop. User code can #run, inspect/modify AST, #insert code, and bake specialized copies.

Blow’s 2026 demo of that model: a compile-time plugin rewrote only real pointer-derefs across roughly 300k LOC, comments and formatting intact, when << deref became .star and << stayed left shift.

The three spellings you named are consequences of “everything interesting is a constant value.”

There is no fn keyword. A procedure is a constant whose type is (int, int) -> int. You can take its address, store it, #run it, or specialize it. :: is not a function keyword; it is the one declaration form.

Control if / while / for may be a bare statement (wiki). So “braces on every one-liner” is stricter than Jai, closer to Go, and only matches Jai for ordinary proc bodies.

Blow in 2015 called -> “superfluous” and floated removing it. It is still there. Treat current glyphs as unstable; the model is stable.

Other latest public facts:

  • Ship plan is not a promise: Order of the Sinking Star first, then engine source and a binary compiler a small number of months later, compiler source eventually.
  • Macros operate on parsed, not-yet-type-checked trees. Easy strongly typed, debuggable Lisp-style rewrites remain a major unresolved semantic question (2024–2026 blocker, with cross-compilation and DLL/context).
  • Compiler is out-of-order / multi-pass. No forward declarations. User-level context-entry order was described as nondeterministic.
  • SOA as a language feature was removed and replaced by generalized #insert. Constructors/destructors, #must, and the C backend are gone.
  • A syntax rewrite is still official plan and may change operators or precedence.

What Jet actually is

Jet already stole Jai’s binding glyphs, then deliberately did not steal Jai’s procedure form.

fn greet(who: String) String -> "hello, {who}"
fn twice(n: Int) Int -> { adjusted :: n + 1; adjusted * 2 }
fn _report(value: Int) { print("report {value}") }
fn load(path: String) String -[IO]> { ... }

double_fn :: double                  // function value via ::
apply_twice((x: Int) -> (x + 1), 5)  // lambda: -> is the body
if n == 0 -> return 7                // same arrow

Ratified late August 2026, cards #2144 / D-SIG-SHAPE1=B / D-CALLABLE-ONE1=A:

  • Return facts sit bare after params.
  • -> is the one body marker in the whole language (functions, lambdas, if, loop, match arms, impl A -> B).
  • Effect ceiling replaces that arrow: -[IO]>. Pure / open-row: -[]> / -[..E]>.
  • :: was retired as a function-body marker so it means only “immutable bind.”
  • Uniformity was defined as two body forms everywhere: -> for one expression, { } for many — not as “always braces.”
  • Named functions already coerce to values (double_fn :: double). name :: fn(...) is not legal; fn is an item/type keyword, not a value constructor. Inference from parser: unhandled fn in value position is E0003.
  • const is retired. Comptime demand is @name :: expr. @ { … } is the documented Jai #run analog for values.
  • D-METAMUTATE1=A rejects Jai-style AST mutation, message loop, and user macros. Power is additive generated modules, read-only core.compiler, and a stdlib DSL whitelist.

Philosophy ranked priorities (from docs/spec/philosophy.md):

  1. Memory and type safety; safe by default, explicit audited unsafe escape.
  2. Beginner experience: useful defaults, little ceremony, errors that explain what / why / how.
  3. Runtime performance; no hidden runtime overhead for convenient syntax.
  4. One mechanism: one semantic path per operation.
  5. Implementation simplicity and compile speed, subordinate to the earlier priorities.

Cross-cutting guards: I7 owner-controlled surface (every user-typable keyword/sigil lives in Syntax.rs); I8 / S14 one canonical spelling, no aliases; greenfield cutover of retired spellings is ordinary error, not dual form.

The three surfaces, with the architecture attached

These are not three independent cosmetics. They are one fork:

Jai:  name :: (params) -> Type { body }
      └ bind ┘ └ type of the value ┘ └ body ┘

Jet:  fn name(params) Type -> body
      └ item ┘        └ facts ┘ └ body / effects ┘

1. Return type after ->

Jai/Rust: -> is a type arrow. Body is braces (or => for lambdas).
Jet: -> is a body arrow. Type is already written. Effects fuse into the same glyph.

Failure contracts in Jet sit in the same post-parameter zone as success types: ?Success !NamedError, fn save(path: String) !IOError with no body arrow and no written unit.

3. myFunc :: fn(...) vs fn myFunc(...)

This is the one that actually touches Jai’s architecture. The spelling is the small part.

What Jai buys with “a procedure is a constant”:

  • One declaration form: values, types, procs.
  • Out-of-order compile: a name is a constant in a pool, not a sequential item.
  • The same proc value is callable at runtime, #run at compile time, specialized with $T, passed as a pointer, or #inserted.
  • No fn keyword to teach; the cost is “why does a function look like PI :: 3?”

What Jet already has:

  • :: / := / = (Jai’s trio, minus Jai’s : Type : / : Type =; Jet forbids name: Type :: — types belong on values, signatures, and fields).
  • Function values: double_fn :: double. Named fns coerce when referenced without a call if parameters have plain read access.
  • Lambdas already bind like Jai: f :: (x: Int) -> x + 1.
  • Named fn greet(...) is a second declaration form (an item). That is the real inconsistency.
  • Historical Jet used :: as a function body marker; it was removed so :: could stay “bind only.” Putting functions on the right-hand side of :: restores that one meaning, which is aligned.

What Jet has rejected that Jai’s :: is for: AST mutation / macros / compiler message loop (D-METAMUTATE1=A). That is the mechanism that made the 300k-LOC .star rewrite a user-space plugin rather than a compiler patch.

Important. Jet cannot get Jai’s payoff from :: without reopening D-METAMUTATE1 or building an equally powerful non-mutating comptime (run the same functions at compile time, specialize, generate modules). Uniform spelling without that is aesthetics plus a simpler mental model — real, but not the Jai architecture.

Inference: the :: token itself is not the architectural cause of compile-time metaprogramming. The coupling is procedure/type/code values being inspectable, executable, specialized, and inserted during compilation.

Cluster 1 — What compile time is allowed to do

This is the root. ::, #run, $T, macros, and “procs are constants” all hang off it. Deep dive is below; summary here.

Jai. Compile-time is the same language. #run executes ordinary procedures in the compiler’s bytecode interpreter. Macros operate on parsed, not-yet-type-checked trees. $T bakes a fresh typed procedure per call site. A user plugin can rewrite 300k LOC. Blow: remove arbitrary compile-time execution and it is a different language. Open hole: easy, typed, debuggable Lisp-style rewrites.

Jet. S26: comptime is value-only. It must not create, parameterize, or select a type, and must not affect dispatch. Type-check first, then a fuel-limited interpreter. Pure Jet is comptime-callable with no annotation. Rejected in that decision: token/AST/attribute macros, custom syntax, comptime types, const generics in v1. D-METAMUTATE1=A: no Jai AST mutation. Power is generated modules, read-only core.compiler, stdlib DSL whitelist. @name :: / @ { } is the #run analog, not the #run power.

LensJaiJet
GamesBake animation tables, generate SOA layouts, rewrite APIs in-tree, specialize render paths per type. This is the product.Fold values and emit generated modules. Cannot mint a type or rewrite the AST of the game. Asset pipelines want the Jai power; Jet says do it as codegen beside the program, not inside it.
Web / GUI / AI / enterpriseUnchecked AST macros are a supply-chain and diagnostic disaster. Blow still has not closed typed macros.Type-checked-first comptime is the all-domain win: agents can repair it, I4 diagnostics exist, I3 sema owns checks.

name :: fn(...) only pays if a procedure value is a compile-time object you can run, specialize, or insert. Under S26 + D-METAMUTATE1, a named function is already a runtime value you can bind. Uniform spelling is then mostly a mental-model/aesthetic win, not Jai’s architecture. Reopening comptime-types / AST macros would make the Jai declaration form load-bearing. That is a strategic language change, not a syntax tweak.

Cluster 2 — Implicit ambient state: context vs -[IO]>

Jai. Every procedure gets a hidden context: allocator, temp allocator, logger, assertion handler, format config, plus #add_context fields. push_context scopes a replacement. #no_context opts out. This is how you don’t pass an allocator through every engine call. DLL/context interaction is still a release blocker.

Jet. Effects are declared on the callable: fn load(...) String -[IO]>. Package effects: { allow, deny } is auditable. Beginner default is implicit fallibility, but the capability is in the signature, not a thread-local struct. No hidden allocator parameter.

Cluster 4 — Closures and hidden allocation

Jai. => lambdas are expression-bodied and do not capture. Closures considered, not current. Rationale: a capture is a hidden allocation and a lifetime, which is poison in a frame loop.

Jet. Lambdas are (x: Int) -> expr and are passed as fn(Int) Int. They are how callbacks, GUI, streams, and apply_twice work. Capture law was not fully pinned in the fact brief; the surface assumes first-class function values.

What the walk implies for the three surfaces (still not a vote)

  1. -> as return type is Jai’s type-of-a-value glyph. Jet’s -> is body-of-a-control. That fork is about whether a procedure is primarily a typed constant or a callable item with a body. Under current Jet comptime law, the item view is the honest one. Under Jai comptime law, the value view is the honest one. Domain lens: the value view is a game-compiler convenience; the item+body view is how every other domain already reads if / fn / lambda.
  2. Mandatory braces is not Jai. Jai requires them on documented procs and rejects them as a universal rule. The honest Jai steal is “proc body is a block because -> was used for types.” The honest Jet steal from Go is “kill optional-brace C,” which Jet already killed via a mandatory body marker.
  3. name :: … is the only surface that could be a mechanism win: one declaration form. The mechanism win is real in Jai because types, procs, and #run results are the same kind of constant. In Jet, types are not :: values, comptime cannot mint types, methods are not values, fn run is an entry. Unifying named function values with :: (already works: double_fn :: double) is a small consistency cleanup. Making the declaration greet :: fn(...) is a medium cutover. Making it Jai greet :: (params) -> T { } is a large cutover that also relocates -> and fights methods/traits/entry.

Strategic / operational / tactical, collapsed

Strategic. Jai optimizes for a systems programmer who will live in compile-time execution and wants zero declaration forms. Jet’s ranked priorities are safety, then beginners, then runtime perf, then one mechanism. “Look like Jai” can win on aesthetics (your bar allows that if non-negligible); it does not automatically win on beginner ceremony or on one-mechanism if it splits ->. The deep Jai idea Jet has not adopted is user-space compiler as same language — and Jet has an explicit rejection of the mutation half. Jai can make game-local hidden control and compile-time mutation the language. Jet cannot if “excellent at everything” is real. The steal is: data-oriented libraries, value comptime, optional explicit allocators, bake-via-generated-modules — not implicit context, not AST macros, not no-closures, not no-methods.

Operational. A greenfield cutover is allowed. The expensive object is not fn vs ::. It is the arrow/effect/body system (functions, lambdas, if, loop, match, -[E]>, function types, fmt, snapshots). name :: fn(...) is a smaller cutover: items become bindings; -> can stay. Mandatory braces are small if -> stays, large if braces become the only body because -> moved. Any Jai mechanism that becomes language law must still be judged per cluster, including the worst required domain. Games can still be excellent via batteries — engine/SoA/allocator libraries, not syntax.

Tactical. Parser already has a migration path from Jai/Rust -> Type. Diagnostics teach the Jet order. Reversing that is a one-cutover jet fmt, same as 21 Aug 2026 — technically routine, semantically a reversal of a measured unification. Latest Jai glyphs are a moving target. Mechanism comparison is the durable work; glyph matching is the fragile work.

Blow’s actual argument (not the meme)

Community Philosophy wiki (modified 2026-07-10, presented as an attempt to represent Jon), plus the 2025 LambdaConf keynote and the 2026 Wookash interview.

The load-bearing quote:

There are many features I can get rid of and it would still be the same programming language. If I got rid of full arbitrary compile time execution, it wouldn't be the same programming language. … My approach is say 'why are you doing that? Let's do everything at compile time. And by everything, I mean everything.'

“Full” is aimed at constexpr / Rust const / D CTFE subsets. He refuses a second, weaker language that runs at compile time. The compile-time program is ordinary Jai: loops, allocators, procedures, file/network, even “run the game while compiling.” #run is bytecode interpretation of that same language.

Related slogan, same philosophy document: it is the programmer’s computer; the language should not arbitrarily prevent legitimate operations merely because they might be misused.

Why he thinks that is acceptable — five claims:

  1. The power already exists, just in the wrong place. Make, CMake, Python codegen, Visual Studio, custom IDL compilers already execute arbitrary programs. Pretending the language is pure shoves the real build into untyped scripts nobody can debug as Jai. “Your program should be a mathematical object that is self defining.” The compiler alone should be enough.
  2. Metaprogramming is only hard because it is a different language. “We are bringing the meta as close as to what you regularly do as possible. So it's just normal stuff that you are used to thinking about.” A serializer generator should be a for loop over struct fields, not a template language.
  3. Safety should be programmable policy, not a mandatory ideology. He does not argue “bugs are good.” He argues the language designer does not know your engine’s actual invariants. Write compile-time checks for your rules (every message has an ID, every asset exists, this pointer type only lives in this scope). Rust-style “the language protects you” is, in his view, why Braid/Witness would have failed if they were 10% harder.
  4. Explicit control, nothing behind your back. RAII, ctors, borrow checking, GC, implicit casts: hidden control flow. Compile-time execution is visible (#run) and therefore more honest than a magic feature for each baking need.
  5. Games are the hard case, and they are on a knife edge. “Both the Braid and the Witness, if they were 10% harder to make, the projects would have failed.” A language that adds friction to data layout, baking, and iteration kills the product. Arbitrary comptime is how you keep the user’s program simple by making the compiler do the repetitive work. He will put complexity in the compiler to buy programmer ergonomics.

What “understand the program” means. Not that the compiler infers intent. User code can ask the compiler structured questions: what fields, what types, what declarations, then generate or fail the build. Code is data. That is closer to Lisp than to #define.

Temperance, in the same philosophy document: keep compile-time execution conservative; it is slower than machine code; don’t use features for their own sake. So even the Jai-shaped view is not “macros everywhere.”

The 2026 caveat — Blow does not currently bless the thing people think he blessed

Wookash, 2026-01-24, State of Jai:

  • Current macros operate on parsed, not-yet-type-checked trees.
  • Easy, strongly typed, debuggable Lisp-style rewrites are “the one major unresolved semantic question.”
  • He questions shipping before that is solved.
  • The .star migration worked because a compile-time plugin could distinguish real deref nodes from << shifts across 300k LOC.

So his public position is not “untyped AST soup is fine.” It is:

Full power is required and it must become as typed and debuggable as ordinary code — and that second half is unfinished.

That is the honest Jonathan. Using 2015–2021 demos as “Jai says mutate anything” skips the part he is stuck on.

Pre-public-beta blockers named in the 2024-09-16 Compiler Q&A: macro system, cross-compilation semantics/robustness, and DLL/context interaction.

Domain score for the comptime cluster only

Games. Blow is right that baking, serializers, SOA-via-#insert, and “change an operator across 300k LOC” are miserable as external tools. Level 5 ($T bake, comptime types) is the game-shaped win. Level 6 is how language evolution happened in his compiler, which is a different job than what a game team does every week.

Web / backend / enterprise. Level 7 is a supply-chain and diagnostic hole (macros before types). Level 2 unrestricted (compile-time network, “works on my machine”) is how you get non-reproducible deploys. Jet’s lockfile is the all-domain win. Level 4 (typed derive / generate a module of JSON codecs) is the web-shaped analog of Jai serializers without mutating the handler the user wrote.

Embedded. Firmware register maps want level 4–5 (generate tables, maybe mint a packed type). They do not want compile-time network or in-place rewrite of the ISR.

Beginners / agents. Levels 0–3 are teachable: “this name is computed now.” Level 4 is teachable if the generated file is real source you can click. Level 6 means the bytes on disk are no longer the program — I4 snapshots lie unless the compiler shows the post-rewrite tree as the source of truth (a second source of truth — I8 fight).

Perf. $T bake is a runtime win (no vtable). Untyped macros are a compile-time cost and a reasoning cost. Jet priority 3 cares about the first; priority 2 and 5 care about the second.

Where Blow is strongest against Jet, and where he is weakest

Strongest. “Don’t make a crippled second language.” Jet’s derive/generate templates plus a closed T.@fields set is a second, smaller language. Every new bake need becomes a new built-in or a new stdlib DSL (#SQL, #HTML whitelist). That is the Makefile problem one layer up: the language team becomes the bottleneck instead of CMake. Blow’s “if it can be user-level, why is it in the compiler?” cuts here.

Weakest, including by his own 2026 standard. Untyped, in-place mutation of the tree the user is reading. He has not made that as thinkable as ordinary code. Jet’s type-check-first + additive generation is closer to the goal he stated than the implementation he has. Also: “Make already runs arbitrary code” is an argument for capability, not for ungated capability. Jet already granted the capability and put a hash on it. That is not paternalistic memory-safety; that is “the build is a mathematical object” — which is his slogan.

Category error to avoid. “Full control is acceptable because the programmer is an adult” is a user claim. Jet’s I1 is a product claim: the default program is memory-safe. You can agree with Blow on comptime-as-same-language and still reject him on hidden aliasing and use-after-free. Those are different clusters. Mixing them makes comptime look like a safety fight when it is a who-is-the-compiler fight.

Controlled AST that could be justified in Jet terms

If “controlled” has to survive I3, I4, I8, I9:

  • After typecheck, never before (opposite of current Jai macros).
  • Additive: insert new items/modules; do not rewrite the function the user is looking at.
  • Typed holes, not strings (D-META-CODE1 already).
  • The generated artifact is inspectable (a real module, not a phantom tree).
  • Same diagnostics as if the user wrote it.
  • Effects on the same tier ladder as @ I/O.
  • No new user-typable syntax (I7).

That is essentially “pressuring level 4–5, still forbidding 6–7.”

The .star example fails that test: it rewrote existing user nodes in place. Jet’s equivalent is jet fmt + teaching diagnostics for a language cutover — a tool, not a user-level macro. Justifying user-level 6 means arguing that libraries, not the language team, need to rewrite call sites. That is a real argument (API migrations). It is also how you get ecosystem dialects. Score it separately; don’t smuggle it in as “Jonathan said full control.”

Consequence for the three surfaces (still parked):

  • name :: proc only becomes architecture at level 5+: a procedure value is something compile time can specialize, insert, or type-from. At Jet’s 0–4, double_fn :: double already is the value story; fn greet vs greet :: fn is declaration cosmetics plus one sema path.
  • -> as a type arrow is the glyph of “this value has a type,” which is how Jai thinks of procedures. Jet’s body-arrow is how you think of items. Comptime law picks which worldview is honest.
  • Mandatory braces are almost unrelated to comptime except: if #insert emits statements, a single body form is easier for generators. Weak coupling. Don’t let codegen aesthetics drive the user-facing one-liner tax.

1. Power ladder

For this grill, how far up the comptime ladder is Jet allowed to be pressured?

  1. Hold Jet 0–4; do not pressure S26. Keep type-check-first value comptime, reflection, and typed generate/derive. No comptime-minted types, no user AST rewrite. :: stays mostly cosmetic.
  2. Recommended. Pressure level 5 (comptime types / bake); keep 6–7 forbidden. Allow comptime to mint/select types and bake copies ($T-like) so serializers, packed layouts, and firmware tables are user-level. Still no in-place rewrite of existing user functions. Matches your split lean.
  3. Pressure 5 plus a constrained post-check level 6. Also allow rewriting existing call sites / nodes after typecheck, inspectable, same diagnostics — API migrations as user code, not only jet fmt.
  4. Leave 7–8 on the table as the full Jai steal. Treat untyped-or-typed macros that rewrite the tree you are reading as in-scope, including Jai-today. Fights I3/I4 unless those invariants move.

2. Blow’s Make argument

Blow: Make already runs arbitrary code, so the compiler should too. Jet already runs code at compile time and hash-locks I/O. What do we do with his argument?

  1. Recommended. Accept “builds are already arbitrary” only with Jet’s effect tiers. Capability yes; ungated side effects no. Jet’s hash-lock / #Impure already is “the program is a mathematical object.”
  2. Accept it fully: compile-time is an ordinary program. #run may do anything Make may do, including network/GUI/game-during-compile, because otherwise you re-create the Makefile split.
  3. Reject it: those tools should stay outside the language. The compiler evaluates pure values. All other build work stays in package.jet / plugins / external tools.
  4. Need more on Jet’s current comptime I/O and lockfile before this call.

3. The .star test

Blow’s 2026 demo rewrote deref nodes in place across 300k LOC. What kind of capability is that for Jet?

  1. Recommended. In-place rewrite of existing user code is a compiler/fmt job, not a language feature. Language cutovers are fmt + diagnostics + one greenfield rewrite. Users generate new modules; they do not rewrite neighbors’ functions.
  2. User-level in-place rewrite is justified if it is typed and inspectable. A typed, after-check, reviewable rewrite API is justified for API migrations and data-layout shifts. It is how you avoid five external tools.
  3. The .star rewrite is evidence mutation is load-bearing. If the plugin cannot distinguish << deref from << shift inside user trees, codegen from the outside is strictly weaker. Mutation is required.
  4. Park until we see whether level 5 + additive generate covers the bake/serializer cases without mutation.
