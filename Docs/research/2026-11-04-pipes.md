# Pipes: what Jet code would gain, and what other languages learned

Date: 2026-11-04. The owner asked whether some Jet code would be easier to
reason about with pipes than with only functions and dot methods. This note
holds the evidence. The design and the options are in
[the pipes proposal](../proposals/2026-11-04-pipes.md).

- The census ran on dev at `0d1ea12f79` (2026-11-04), over 4,908 tracked
  `.jet` files.
- Probes p01 to p15 ran on the admitted compiler built from `a32d3791`
  (`a32d3791334a68dee52cdf98a72d4e35ba2e5eca`). Probes p16 to p20 ran on
  `a32d3791` and on `3993915aeb`, with the same output. The spelling probes
  g01 to g14 ran on `3993915aeb`.
- Probe files and the census scripts are in
  [assets/2026-11-04-pipes](assets/2026-11-04-pipes/).

## 1. Findings

All findings are dated 2026-11-04.

1. Jet has no pipe today. `3 |> double` is a parse error (E0003).
2. Dot chains already read left to right, and the repository has 1,286 of
   them with three or more steps. A pipe must not compete with them.
3. Dots cannot reach most of the flows that read inside out. Outside the
   runtime and generated files:
   - 69% of three-deep nested calls pass the data to a later argument, or
     go through a type function such as `String.from_bytes` or a module
     function such as `json.parse`;
   - 59% of mixed method and function chains do the same.
   Under the one-call-spelling rule, none of those steps can become a method.
4. Today's left-to-right form is a run of named single-use values. Jet has
   no shadowing (E0118), so each step needs a fresh name. The census finds
   1,850 such runs of three or more steps.
5. About half of those runs (910) end a step with `?? return` or another
   fallback. A pipe design must let each step carry its own fallback.
6. A first-argument pipe, as in Elixir or Gleam, fits a minority. Only 37% of
   nested chains and 23% of named runs pass the data first all the way.
7. Hand checks put about a third of the flagged sites as clearly better as a
   pipe. That is roughly 950 sites, or about one per five files.
8. The places where a pipe hurts are real. They include IR builders that
   name each value, constructor trees, raw address arithmetic and existing
   dot chains.
9. Nesting and named steps run in different orders. In `wrap(note("outer"),
   wrap(note("inner"), "x"))`, `outer` prints before `inner`. A pipe runs top
   to bottom, so turning nesting into a pipe can reorder side effects.
10. A library `apply(value, step)` helper cannot infer its result type from
    an untyped lambda. `apply("  hi  ", (s) -> s.trim())` is E0904. Inside the
    lambda, `?? return -1` leaves the lambda, not the function. So a helper
    cannot express the per-step early return that 910 named runs use.
11. `it` is already a reserved keyword for **the current subject**, with two
    users. In `if subject == { … }`, when the subject is a call or a field,
    the arms read it as `it`. In a bindingless loop such as `loop users ->
    .name`, the item is `it`. No program can declare its own `it` (E0003,
    probe p19). On dev at `3993915aeb`, no tracked `.jet` file reads `it` in
    code (0 of 18,019 files). The pattern search's 20 hits are all prose or
    HTML inside strings, checked by hand.
12. Today's rules for a second `it` differ by form (probes p16 to p20):
    - a table inside a table's arm hides the outer subject;
    - a table on `it` itself keeps the outer `it`, because `it` is a plain
      name;
    - a bindingless loop inside a table's arm is E0118, "The name `it` is
      already taken here";
    - a bindingless loop inside another one is E0118 and E0380;
    - a table over a plain name has no `it`; reading it is E0107.
13. One of those rules looks like a bug. Inside a bindingless loop body, a
    table over a computed value such as `.age * 2` gives its arms the loop
    item as `it`, not the table's subject (probe p16, case 4). The spec says
    the arms read the table's subject.
14. E0107 for a stray `it` suggests "Declare it first: `it :: ...`". That
    suggestion is itself an error, E0003, because `it` is a keyword (probes
    p18 and p19).
15. No single ASCII character is free and readable as a pipe. Probes g01 to
    g14 show:
    - a leading `>` silently compiles as a comparison and prints `false`
      (g03);
    - a backtick opens raw text (g05, E0002);
    - `~` still carries teaching errors for retired spellings;
    - a leading `|` already continues an or-pattern in an arm head (g11);
    - backslash is the only free character (g04 and g14, E0001).
16. `|>` and `<|` are both free as new tokens (g13 and g12, E0003 today).
    The word `then` is an ordinary name in 188 code lines, 154 of them
    `.then(…)` method calls. That count comes from one awk pass with
    comments and simple strings removed, so it is approximate.
17. `print(parse("ab")?)` compiles and runs. The syntax decisions record
    calls a bare call-site `?` diagnostic-only. That is a separate
    discrepancy, noted here for whoever owns failure syntax.

## 3. Census

### Method

`census.mjs` lexes every tracked `.jet` file under `Core`, `Compiler`,
`Jetpack`, `Examples` and `Tools`. It removes comments and string bodies, then
walks call expressions. It reports four shapes:

- **dot chain**: three or more method steps in a row, which already read left
  to right;
- **nested**: a prefix call spine three or more calls deep, such as
  `a(b(c(x)))`;
- **mixed**: three or more steps that alternate between prefix calls and
  methods, so the eye jumps both ways;
- **named run**: three or more `name :: …` lines in a row, where each value
  is used once, by the next line only.

Each step that hands data on is tagged by where the data goes: the receiver,
the first argument, a later argument, or an operand such as `x * 8`. Calls to
`print`, `assert`, `Ok`, `Err`, `Val` and similar sinks are transparent.
Size queries such as `len` are skipped as arguments. Files are tagged as
source, test, example or generated. A file is generated when its first 400
characters say "generated" or "do not edit".

The focus view drops `Compiler/JetRuntime`, whose 1,722 address computations
such as `rt_text_word(wrapping(values + at * I64{8}))` are raw memory reads,
and drops generated files.

### Commands

From a scratch directory, with the repository at `$JET`:

```sh
timeout 600 nice -n 19 node census.mjs "$JET" census.json   # 4.4 s
timeout 120 nice -n 19 node it-count.mjs "$JET"             # 2.0 s
```

`census.mjs` writes one record per site to `census.json` and prints the two
tables below. `it-count.mjs` prints every line that reads the keyword `it`
outside comments, then a summary. On `3993915aeb` it printed
`{"files":18019,"code":18,"interp":2}`; all 20 lines are prose or HTML
inside strings that its simple string scanner missed.

### Precision

A detector finds shapes, not readability. Deterministic samples of 25 per
shape were read by hand:

| Shape | Clearly better as a pipe | Marginal | Rate |
|---|---|---|---|
| Nested | 8 | 7 | about 32%, up to 60% with marginal |
| Mixed | 7 | 5 | about 28%, up to 48% with marginal |
| Named run | 7 | — | about 28% |

Common reasons a flagged site was not better as a pipe:

- the names carried meaning, or a value was used again further down;
- the "chain" was a tree of constructors, such as an error built from four
  facts;
- the steps wrote through `&` to shared builders;
- the flow was two steps of address arithmetic.

Estimate: about 165 nested, 230 mixed and 550 named-run sites read better as
a pipe. That is about 950 sites in 4,908 files. With 25 samples per shape,
each rate has a wide margin, roughly ±18 points.

### Limits

- The lexer is not the compiler's parser. Method calls on parenthesised
  expressions and multi-line calls are approximated.
- A named run counts only adjacent lines. Runs broken by an `if` guard are
  missed, so the named-run count is low rather than high.
- "Type or module function" is decided by spelling: a capitalised receiver
  or an imported module alias.

## 4. Prior art

Each entry gives the meaning, the known failure modes and the evidence of use.

### F#, OCaml, Elm

`x |> f` means `f x`. With curried functions, the value lands in the last
parameter, so libraries put the data last.

- OCaml has `|>` in Stdlib since 4.01, as the `%revapply` primitive, plus
  `@@` for right-to-left application.
  <https://ocaml.org/manual/latest/api/Stdlib.html>
- Elm's core library defines `|>` and `<|`, and the style guide leans on them.
  <https://package.elm-lang.org/packages/elm/core/latest/Basics#|>>
- F# 6 (2021) added debug stepping points and breakpoints for each `|>`
  stage. Before that, a pipeline was one opaque step in the debugger.
  <https://devblogs.microsoft.com/dotnet/whats-new-in-fsharp-6/>
- Failure mode: the design depends on currying. Without partial application,
  every stage needs a lambda.

### Elixir

`x |> f(a)` is a macro that rewrites to `f(x, a)`: the value goes first.
<https://hexdocs.pm/elixir/Kernel.html>

- The documentation warns about precedence: `String.graphemes "Hello" |>
  Enum.reverse` pipes into the wrong call without parentheses.
- An anonymous function stage needs `.()`.
- Values often belong elsewhere than the first slot. `then/2` and `tap/2`
  arrived in 1.12.0 for exactly that.
- Libraries put the subject first to suit the pipe.

### JavaScript: Hack pipes versus F# pipes

The TC39 proposal reached Stage 2 at the 2021-08-31 plenary with Hack-style
pipes. <https://github.com/tc39/proposal-pipeline-operator>,
<https://github.com/tc39/notes/blob/main/meetings/2021-08/aug-31.md>.

- F# style failed to advance twice, in 2017 and 2018. In 2021 V8 raised
  memory and speed concerns about it and about partial application.
  <https://raw.githubusercontent.com/tc39/proposal-pipeline-operator/main/HISTORY.md>
- No one in committee thought Elixir style fit JavaScript, because it would
  change what an ordinary call means.
- Hack style writes the value as a topic token: `value |> f(%, 1)`. The topic
  must appear at least once in each stage, and is an error outside a pipe.
- Pipes share the lowest precedence with arrow functions, assignment and
  `yield`. `await %` works inside a stage.
- The topic token is still open. `%` is a placeholder; `@` was preferred in
  2022-03, then excluded. A `Function.pipe` library alternative was refused
  in 2022-07.
- The State of JS 2020 survey ranked the pipe operator fourth among missing
  features.

### Hack (HHVM)

Hack shipped the topic design JavaScript borrowed. `$$` is the topic, and the
right side must use it at least once.
<https://docs.hhvm.com/hack/expressions-and-operators/pipe>

### PHP 8.5

`$x |> strlen(...)` passes the value to a one-argument callable. Accepted and
implemented. <https://wiki.php.net/rfc/pipe-operator-v3>

- Left-associative. Arithmetic groups before the pipe; comparison and `??`
  group after it, so `$x |> f(...) ?? $d` applies `??` to the whole chain.
- It compiles to direct calls with no overhead. Forwarding closures are not
  optimised away, so multi-argument calls cost a closure.
- By-reference parameters are refused.
- Errata on 2025-08-28: an arrow function inside a pipe swallowed the rest of
  the chain, so arrow functions now need parentheses (php-src PR 19533).

### R and magrittr

R 4.1.0 added `|>` as a pure syntax rewrite: `x |> f(y)` becomes `f(x, y)`.
<https://stat.ethz.ch/R-manual/R-devel/library/base/html/pipeOp.html>

- A `_` placeholder may stand for a named argument, used once. It can also
  head an extraction chain, as in `_$coef[[2]]`.
- Evaluation stays lazy, as for any R call.
- magrittr 2.0 rewrote its `%>%` for lazy evaluation and cleaner backtraces,
  because the old pipe filled error traces with its own frames.
  <https://www.tidyverse.org/blog/2020/11/magrittr-2-0-is-here/>

### Gleam

`x |> f(a)` passes `x` first. If the right side is not a call, `x` is its
only argument. A function capture `f(a, _)` places the value elsewhere.
`echo` can sit in a pipe to print a stage.
<https://tour.gleam.run/functions/pipelines/>,
<https://tour.gleam.run/functions/function-captures/>

### Julia

`x |> f` applies a one-argument function, and `∘` composes functions. Multi-
argument stages need anonymous functions.
<https://docs.julialang.org/en/v1/manual/functions/>

### Raku

`@a ==> map(…)` feeds the left value as the last argument. Its precedence is
very loose, so assignment needs parentheses. The documentation describes
future parallel evaluation of feeds.
<https://docs.raku.org/routine/==%3E>

### Shell pipes

`a | b | c` connects processes by byte streams. The stages run at the same
time, and failure in a middle stage is hidden unless `set -o pipefail` is
on. The lesson for a language is to keep failure per stage and visible.

### Rust

Rust has no pipe operator and no accepted RFC.

- A 2018 internals thread on postfix calls to free functions met pushback:
  code that looks like a method call but is not, and unclear evaluation
  order. <https://internals.rust-lang.org/t/idea-operator-for-postfix-calls-to-macros-and-free-functions/7634>
- A 2022 thread was locked with the answer "use a trait".
  <https://internals.rust-lang.org/t/support-the-pipe-operator/17204>
- The `tap` crate gives `.pipe(f)`. Calls with more arguments still need a
  closure. <https://docs.rs/tap/latest/tap/pipe/trait.Pipe.html>
- Rust chose postfix `.await` in 2019, partly so async chains read left to
  right. <https://internals.rust-lang.org/t/a-final-proposal-for-await-syntax/10021>

### D and Nim

Both let any free function be called with a dot: `x.f(a)` means `f(x, a)`.
<https://dlang.org/spec/function.html#pseudo-member>,
<https://nim-lang.org/docs/manual.html#procedures-method-call-syntax>.
Jet considered and refused this, because a function would then have two call
spellings and resolution would depend on imports.

### Kotlin

Scope functions `let`, `run`, `also`, `apply` and `with` take a lambda whose
value is `it` or `this`. `x.let { f(it, 1) }` is Kotlin's pipe.
<https://kotlinlang.org/docs/scope-functions.html>. Kotlin's own guide warns
against nesting them, because `it` then becomes ambiguous.
The proposal avoids that ambiguity for pipes: a pipe cannot open where an
`it` is already visible, which is today's rule for a bindingless loop.

### Direction across languages

F# defines `<|` beside `|>`, Elm's core library defines both, and Raku has
`<==` beside `==>`. Elixir, Gleam, Hack, PHP 8.5, R and the JavaScript
proposal ship only the right push. OCaml pairs `|>` with `@@`, an
application operator, not a mirrored pipe. Where both directions exist, the
left one mostly saves the parentheses around a last argument, which Jet's
call syntax does not need.

## 5. The owner's hunch, tested

The hunch was that a pipe does a different job from functions and dots.

- **What dots mean.** A method belongs to its type. `text.trim()` asks the
  value to do something it knows how to do.
- **What nesting means.** `f(g(x))` says the same as a pipe, but the reader
  starts in the middle.
- **What named steps mean.** `a :: g(x)` then `f(a)` reads in order. The name
  must be invented, and Jet forbids reusing it.
- **What a pipe would mean.** "Take this value through these steps, in this
  order." Each step is an ordinary call. The only new thing is an unnamed
  value that lives for one step.

So a topic pipe adds no new way to call a function, and no new capability.
Everything it writes can be written today, as the probes show. What it adds is
a layout: the order of named steps without the names. In the terms of the
one-mechanism rule, it is a second spelling of a single-use `::` binding.
That rule allows spelling to flex where it helps users. Whether this flex
helps enough is the owner's decision; the census says the need is real but
not universal.

A first-argument pipe is different. It does add a call spelling: `f(a)`
would mean `f(x, a)` after `|>`. That is the objection Jet already raised
against calling free functions with a dot.

## 6. Reproduce

JET_COMPILER_IDENTITY="$(awk 1 $B/IDENTITY)" JET_TOOLCHAIN_ROOT="$ROOT" \
