# Struct of arrays: Jet against Zig's MultiArrayList

Date: 2026-10-30. Card #6314, criteria 5 and 7. Probes live in
`/mnt/jetscratch/lanes/MemDesign/probes/soa2/`. Jet probes ran with
`/mnt/jetscratch/discovery/base/latest/jet` (bd83fe6361) on `--optimize=none`,
`basic` and `full` (o0, o1, o2). Zig probes ran with Zig 0.15.2 in Debug,
ReleaseSafe and ReleaseFast. The host is one Zen 4 machine.

## What each language has

Zig's `std.MultiArrayList(T)` is a library type
(`lib/std/multi_array_list.zig`, 1089 lines). It keeps one allocation with one
array per field, ordered by alignment, largest first (lines 165-200).
`items(.x)` returns an ordinary slice of one field (line 236). `get(i)` copies
a whole element out and `set(i, v)` writes one back (lines 241-250). No pointer
to a whole element exists. Growth allocates a new block, copies every column
with `@memcpy`, and frees the old block (`setCapacity`, lines 489-515). The
capacity grows by half plus a constant (`growCapacity`, line 471).

Jet's ratified surface is `Columns<T>` (D-SOA-SITE1 A), with the field name as
the column: `ps.x` is a read window, `&ps.x` a write window, `~ps.x` a copy
(D-ARRAY-COLUMNS1 A). `Rows<T>` is the add-only table with `Row<T>` handles
(D-COLUMNS1 A). Today only the older marker `#Layout(columnar)` exists.

| Surface | Ratified | Built today |
|---|---|---|
| `Columns<T>` | D-SOA-SITE1 A | No. The name does not resolve. |
| `ps.x` column read window | D-ARRAY-COLUMNS1 A | No. `ps.x.sum()` is E0302 (`ref5_column_sum.jet`). |
| `&ps.x` column write window | D-ARRAY-COLUMNS1 A | No. `nudge(&ps.x, 100.0)` is E0302 (`ref6_column_window.jet`). |
| `~ps.x` column copy | D-ARRAY-COLUMNS1 A | No. `~ps.y` is E0003, "Expected a value, found `~`". |
| `#Layout(columnar)` marker | D-SOA1, to be removed by D-SOA-SITE1 | Accepted, but a no-op at run time. |
| `Rows<T>` field view `t.x` | D-COLUMNS1 A | Yes, as a copy. See below. |

`#Layout(columnar)` changes nothing in the compiled program. The earlier note
`2026-10-30-custom-allocators-and-soa.md` section 3 found the o2 binaries
differ only in line constants. `Rows<T>` stores an ordinary list of structs
(`Core/Collections/Collections.jet:45-75`). Its field view `t.x` is lowered as
a loop that collects a new list (`Compiler/JetSema/Source/Sema/Expressions/Places.jet`,
`sema_expression_rows_view`, near line 574). So each `t.x` allocates and copies.

## A reference to one field of one element

Jet allows `&ps[i].x` on a columnar list, and the write lands in place. Every
case below printed the same output on o0, o1 and o2.

| Probe | Code | Result |
|---|---|---|
| `ref1_field_ref.jet` | `bump(&ps[1].x, 0.5)`, `swap2(&ps[0].x, &ps[0].y)`, `swap2(&ps[0].x, &ps[1].x)` | `2.5`, `10.0 1.0`, `2.5 10.0`; exit 0 |
| `ref8_row_ref.jet` | `settle(&ps[1])` with `fn settle(p: &P)`; `r :: &ps[0]; r.x = 5.0` | `0.0 22.0`, `5.0`, `15.0 22.0`; exit 0 |
| `ref4_rows_ref.jet` | `&t[b].x` on `Rows<T>` | `2.5`, `11.0`; exit 0 |
| `ref2_alias_same.jet` | `swap2(&ps[0].x, &ps[0].x)` | E0204: "`ps[…].x` is being changed in this call, so it can't be used again here" |
| `ref3_across_push.jet` | `grow_and_bump(&ps, &ps[0].x)` | E0204, same message |
| `ref7_local_ref.jet` | `r :: &ps[0].x; &ps.push(..); r = 99.0` | E0220: "`ps` cannot be read while `r` has a live exclusive write window into it" |

The safety rule is Jet's ordinary exclusive write window. It applies to any
place, so it needs nothing special for columns. A reference cannot outlive a
push, and two writes cannot reach the same field at once.

Zig takes a pointer into a column with `&ps.items(.x)[0]`. Probe
`zig/stale.zig` keeps that pointer across 1000 appends and then writes 99
through it. The program prints `x0=1 len=1001` and exits 0 in Debug,
ReleaseSafe and ReleaseFast. The write went to freed memory and was lost.
No Zig mode reports it. Jet rejects the same program while compiling.

## Timings

The workload uses 2,000,000 `Body` structs of eight `Float` fields (64 bytes).
It appends them all, then sums `x` in 20 passes, then adds to `vx` in 5 passes
through a reference (`bump(&ps[i].vx, 0.25)`). Each cell is the minimum of five
runs (`node bench.mjs 5 ...`). Every program printed
`total=39999980000000 check=3500000`.

| Program | Append | Sweep `x` ×20 | Update `vx` ×5 |
|---|---|---|---|
| Zig `ArrayList`, Debug | 220.2 ms | 709.6 ms | 82.8 ms |
| Zig `ArrayList`, ReleaseSafe | 59.7 ms | 80.6 ms | 107.9 ms |
| Zig `ArrayList`, ReleaseFast | 56.5 ms | 69.7 ms | 87.6 ms |
| Zig `MultiArrayList`, Debug | 1216.5 ms | 98.4 ms | 78.7 ms |
| Zig `MultiArrayList`, ReleaseSafe | 232.2 ms | 23.7 ms | 1.4 ms |
| Zig `MultiArrayList`, ReleaseFast | 295.6 ms | 25.1 ms | 2.3 ms |
| Jet plain list, o0 | 204.0 ms | 126.0 ms | 73.9 ms |
| Jet plain list, o1 | 208.1 ms | 102.5 ms | 38.1 ms |
| Jet plain list, o2 | 206.6 ms | 97.6 ms | 30.4 ms |
| Jet `#Layout(columnar)`, o0 | 184.8 ms | 131.5 ms | 66.3 ms |
| Jet `#Layout(columnar)`, o1 | 176.2 ms | 104.3 ms | 30.6 ms |
| Jet `#Layout(columnar)`, o2 | 152.8 ms | 81.0 ms | 25.4 ms |
| Jet `Rows<T>`, o0 | 253.6 ms | 176.1 ms | 86.6 ms |
| Jet `Rows<T>`, o1 | 165.1 ms | 154.4 ms | 83.9 ms |
| Jet `Rows<T>`, o2 | 165.4 ms | 113.7 ms | 36.2 ms |

What the numbers say:

- Zig's column sweep is about three times faster than its own array of
  structs. It reads 16 MB per pass instead of 128 MB.
- Jet's columnar sweep runs at array-of-structs speed, because the marker
  does not change the layout. Jet o2 is 81-98 ms against Zig's 24-25 ms.
- Zig's column update takes 1.4-2.3 ms for five passes. That is faster than
  memory bandwidth allows for five separate passes. LLVM likely merged the
  passes and vectorized them [INFERENCE].
- Zig's `MultiArrayList` append costs four to five times its `ArrayList`
  append. Each append recomputes eight column pointers, and each growth copies
  eight columns. Jet's append (153-208 ms at o2) sits between the two.

## Vector code

Counts come from `objdump -d` on the release binaries.

| Binary | `addpd` (packed double add) | `ymm` register uses |
|---|---|---|
| Jet o2, all three programs | 1 | 0 |
| Zig `MultiArrayList`, ReleaseFast | 100 | 347 |
| Zig `ArrayList`, ReleaseFast | 15 | 219 |

Jet's o2 binaries add one double at a time (`addsd`, about 382 each). Card
#2889 tracks the missing vector path. A strict left-to-right `Float` sum cannot
use vector lanes without changing its rounding. Jet's `xs.sum()` already uses
a fixed eight-lane tree for that reason (D-FRED1 A,
`Compiler/JetIR/Source/BuildRoutes.jet:3231-3235`).

## Owner choices

The comparison raises no new owner choice. Each gap is an implementation gap
under a ratified contract:

- `Columns<T>`, column windows and copies are ratified (D-SOA-SITE1 A,
  D-ARRAY-COLUMNS1 A) and not built.
- Element field references and whole-row references already work and are
  already safe. `Columns<T>` takes over the same list API, so they carry over.
- Layout (one block or one per field), growth and vector code do not change
  what a program means. Card #6314 criterion 6 measures them with paired cells.
