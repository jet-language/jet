## Durable CLI contracts

- **Entry & script execution:** A `.jet` file starting with `#!` is a script.
  `jet run` and `jet dev` compile at O0 and execute the linked image in memory
  without writing a binary to disk; `jet build` compiles at O2 (`--profile dev`
  for fast dev builds).
- **Check scoping:** Checking a user program loads only reachable Core
  declarations; `jet check Core` checks all of `Core/` including uncalled
  functions and Core's own lints.
- **Project jobs:** Package-declared tasks in `package.jet` run through the CLI
  with typed inputs from the command registry.
- **Shared option spellings:** Common flags (`--json`, `--color=auto|always|never`,
  `--profile`, `--target`, `--keep-going`, `--jobs`, `--memory`) keep one
  spelling and meaning across all commands.
- **TTY & determinism:** Color and progress appear only on a TTY. `NO_COLOR` /
  `--color=never` forces plain deterministic ANSI-free output; `FORCE_COLOR` /
  `--color=always` forces color.
- **Published schemas:** `--json` emits versioned, machine-parseable schemas
  defined in `Compiler/JetCLI/`; breaking schema changes require an explicit
  version bump.
- **Remembered flags:** Workspace-local remembered CLI defaults live under
  `.jet/` and never silently override explicit command-line flags.
- **Test isolation:** Each `#Test` and `Output.Check` runs with fresh module
  state — leftover test tasks settle, mutable module globals (`^name` and
  `#Persist ^name`) restore to their starting values, module `Shared{…}`
  holders and declared points reset, and `#Memo` caches clear between
  tests. Shipped `jet run` and `jet build` binaries emit zero test-reset
  overhead.
- **Exit codes:** `0` success, `1` user/check/test/unhandled-error failure, `2`
  CLI usage error, `70` runtime fault/panic, `101` internal compiler error (ICE).
  See `Docs/Spec/architecture.md`.
