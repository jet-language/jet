# Surface research — 2026-07-23

Peer-language mining for Jet's genuinely open surface gaps. Research only, nothing ratified.

**Dedup scope.** Board checked first. Excluded because already tracked or decided: the corelib/HTTP/encoding/typed-data/web/comptime/JIT parity waves (#699–#730 and predecessors), framework lessons #505/#506 (binary patterns, STM, auth, sync, validation, live queries, schedule-as-code), jetdoc #86, debugger #12, notebook #442, package/config model (#587/#609/#610/#653–#656), bootstrapping #678/#679, and every ratified decline (macros, async/await, lifetimes, comprehensions, UFCS, custom operators, where/HKT, structural traits). The five areas below are named deferred gaps or open slots in syntax-decisions.md with no covering card. §5 overlaps card #6 (registry + jet publish UX): feed it there, do not mint a duplicate card.

## 1. Lazy iteration protocol (deferred gap — adapters are eager "until the lazy protocol lands"; `split` eager too)

- **Swift/Kotlin — one explicit lazy marker, eager default** (developer.apple.com/documentation/swift/lazysequenceprotocol; kotlinlang.org/docs/sequences.html). Jet: keep eager-by-default `map`/`filter`; expose laziness as one named entry point (`.lazy()` or `.stream()`) that flips a whole chain and returns the existing `Stream<T>` — laziness is a value you ask for by name, not twin `lazyMap`/`map` methods. Avoid: Kotlin's documented sequence overhead on small collections (don't let `.lazy()` get cargo-culted); Swift's uncached lazy views silently recomputing the closure chain on every access.
- **Rust — dropped lazy chain is a compile diagnostic** (doc.rust-lang.org/std/iter — "iterators are lazy and do nothing unless consumed"). Jet: a built lazy chain with no terminal (`.collect()`/`.each()`/`loop`) is a must-use warning at compile time. Avoid: Rust's own documented confusion where side-effecting `.map()` closures never run because nothing pulled.
- **C#/Java/Python — re-enumeration is the signature bug class of lazy surfaces** (CA1851 analyzer, learn.microsoft.com; Java Stream javadoc "may throw" on reuse; Python generators silently exhaust). Jet: make consumed lazy views move-only/linear — driving the same lazy value twice is a static "value already consumed" error, not an advisory lint (C#), best-effort runtime throw (Java), or silent empty result (Python).
- **Python — one lazy primitive, not two** (docs.python.org itertools). Jet: route the lazy-adapter protocol and lazy string `split` through the same `Stream<T>`/`yield` machinery so the language keeps exactly one lazy concept.

## 2. Tasks/channels surface (S53, ratified but deferred past v1.0 — lessons to bake in before it ships)

- **Trio — spawn only inside a joining scope** (vorpus.org "Notes on structured concurrency"). Jet: `tasks.spawn` legal only lexically inside `g.all`/`g.race`/`g.any` or an explicit `tasks.scope { }` that joins all children on exit, including on panic/cancel. Avoid: Go-style detached spawns leaking tasks and swallowing errors.
- **Kotlin — no detached escape hatch, ever** (elizarov.medium.com on GlobalScope; JetBrains 1.5.0 notes). Jet: never ship a global spawn entry point; Kotlin had to retro-mark `GlobalScope` delicate and could not remove it. Avoid: an early unstructured API becoming an unkillable ecosystem antipattern.
- **Swift — cooperative-only cancellation defeats the scope guarantee** (SE-0304). Jet: reaffirm preemptive cancellation; document every blocking point (channel ops, `task.join()`, `g.*` boundaries) as a guaranteed cancellation point with zero user polling. Avoid: one non-polling task holding a whole scope open.
- **Java Loom — closed join-policy set, no pluggable joiner** (JEP 505; the API churned through 5 preview JEPs). Jet: keep `g.all`/`g.race`/`g.any` as a small closed combinator set. Avoid: a generic "joiner" interface that never converges because every policy looks justified.
- **Go — scope-carried deadlines, not viral tokens** (faiface.github.io context essay; golang/go#28342). Jet: deadlines live on the scope (`g.all(timeout: 5s) { }`), never threaded as a first-argument token through every signature.
- **Erlang/OTP — escalation ceiling** (erlang.org supervision principles). Jet: no configurable restart strategies, but adopt restart-intensity narrowly — a scope that re-fails during cancellation cleanup hard-aborts instead of looping.

## 3. Error context / why-chain (open gap — `?` propagates but nothing records which of 12 `?` sites failed or why)

- **Zig — free propagation traces with zero annotations** (ziglang.org #Error-Return-Traces). Jet: auto-instrument every `?` site in debug/safe builds so an uncaught `Err` prints a "propagated at file:line" chain — the beginner path needs no `.context()` calls. Avoid: Zig strips traces entirely in release; keep a cheap-mode trace or a knob so the chain doesn't vanish exactly when a beginner ships.
- **Go — canonical wrap + chain-walk in std** (go.dev/blog/go1.13-errors). Jet: one built-in `.wrap("context")` (or wrap-sugar on `?`) threading a cause chain, with stdlib is/as helpers — one mechanism, not user conventions. Avoid: Go's documented wrap-noise ("placing order: reserving stock: … : connection refused") — collapse redundant frames in diagnostics.
- **Rust — don't let the ecosystem fork before std ships it** (anyhow vs thiserror; RFC 2965 notes `Error::source` limits). Jet: bake `context(msg)` into `T ? E` itself so app-style and typed-`E` code share one idiom and beginners never pick a library. Avoid: years of anyhow/eyre near-duplicates because std lagged.
- **Swift — typed throws validates `T ? E` as the default; don't add a second typing layer** (SE-0413: untyped throws "remains the better default"). Jet: expert opt-in is a wrap/trace layer on top of `?`, not a parallel throws-typing system. Avoid: over-narrowing `E` just to get a why-chain, locking APIs against error-set evolution.
- **Elixir — anonymous failure is the trap** (`with`/`else` flattening, hexdocs Kernel.SpecialForms). Jet: every auto-context frame carries its own site identity so a 12-`?` chain never collapses into one anonymous failure; never require hand-normalizing error shapes to get a trace.

## 4. User typed-text prefixes (deferred to E4) + S56 typed-reflection hardening (open E3 slot)

- **JS tagged templates — generality without a contract fragments safety** (MDN tagged templates; lit-html/styled-components divergence). Jet: user prefixes must implement one canonical comptime contract (e.g. `derive MyPrefix.Literal { fn escape(...) }`) so every literal funnels through the same typed escaping protocol as built-in `sql"…"`/`html"…"`. Avoid: no trusted safe-string convention, injection safety varying per library.
- **Python PEP 750 — defer combination; holes stay typed values** (peps.python.org/pep-0750). Jet: `prefix"…{expr}…"` desugars to a comptime `Literal{ parts, holes }` (hole = value + static type) handed to the prefix processor — never a pre-joined string. Avoid: PEP 750 explicitly rejected JS's fully-general tag design as too complex; keep one fixed grammar.
- **C# InterpolatedStringHandler — per-hole builder lowering** (learn.microsoft.com interpolated-string-handler). Jet: lower prefix literals to sequential builder calls (`appendLiteral`/`appendHole`) so escaping is enforced per hole at the type level. Avoid: pre-C#10's eager full-string allocation before any handler could intervene.
- **Zig @typeInfo — reflection as comptime-only typed value** (ziglang.org #typeInfo). Jet: S56 answer by construction — `T.reflect()` returns a comptime-only typed value with no runtime representation, so unsafe runtime introspection is unrepresentable. Avoid: any design letting a reflection handle survive to runtime.
- **Swift Mirror — the anti-pattern for S56** (nshipster.com/mirror: string-keyed, read-only, ~3x slow, bridging crashes off-Apple). Jet: per-field typed results, framed as debug/introspection; push "act on a type's shape" onto `derive T.Wire { }` static conformances. Avoid: stringly-typed dynamic reflection as the primary metaprogramming path.
- **C# source generators vs Java annotation processors — additive, deterministic, simulable** (roslyn source-generators.md). Jet: `T.reflect()` stays strictly observational; only `derive` emits code (additive + deterministic). Avoid: Java's processors needing a compiler-sized harness just to test.

## 5. API evolution / deprecation (nothing exists; overlaps card #6 — feed these into its publish-UX design)

- **Elm — registry computes the version bump from the API diff and refuses mismatched publishes** (elm diff; elm-lang.org/issues/868). Jet: jetpack registry runs the semantic-index API diff on publish and hard-rejects a wrong bump; `jetpack diff <pkg> <v1> <v2>` exposes the same diff pre-publish. Avoid: overselling — signature diffs are a floor, behavioral breaks still slip through.
- **Rust `#[deprecated]` + editions RFC 2052** (doc.rust-lang.org attributes/diagnostics; rust-lang.github.io/rfcs/2052). Jet: `@Deprecated("use x instead", since: "1.4.0")` in the `@Rule` family with use-site warnings and codemod auto-fix when the note names a replacement; epochs opt-in per package, tooling-migrated, syntax/lint-level only, cross-epoch code still links into one program. Avoid: rustc never validates `since` (validate against registry versions so metadata can't rot); editions that let behavior — not just syntax — diverge.
- **Swift @available — take the lifecycle, drop the platform matrix** (SE availability model; 6.4's anyAppleOS shorthand added purely to fight repetition). Jet: three-state lifecycle available → deprecated (warn) → removed (error, triggers migration codemod), single version axis only. Avoid: Swift's per-platform annotation burden.
- **Go — no stdlib exemption, no big-bang major** (go.dev/blog/compat; apidiff; generics landed compatibly in 1.18, "Go 2" abandoned). Jet: stdlib subject to the same computed-diff enforcement as user packages; epoch = migration mechanism, never a breaking-rewrite vehicle. Avoid: apidiff's own admitted blind spots — enumerate what the diff tool can't see rather than implying exhaustiveness.
- **cargo-semver-checks — first-party from day one** (github.com/obi1kenobi/cargo-semver-checks). Jet: the semantic index already exists; ship `jetpack semver-check` as a first-party default-on publish gate instead of waiting a decade for a third-party bolt-on. Avoid: Rust's years of silent ecosystem semver breakage before opt-in tooling appeared.
