# Mixed-repository adoption

This guide is the human companion to the executable matrix in
`tests/polyglot_systems.rs`. It describes the current, reachable Jet-as-host
workflow: a Jet package calls a checked C, C++, JVM, JavaScript, or Python
boundary while the foreign source stays in the same repository.

Native Jet Library export is shipped for C and C++ hosts. The generated static
or shared artifact, C header, and `.jetlib` stamp are produced by the Library
build and the C/C++ host proof lives in `tests/library_outputs.rs`. JVM,
JavaScript, and Python guest export is not part of that native Library surface.
Hermetic foreign build entry points need #1344.

## Repository shape

Keep the host source, Jet entry, and generated bridge cache in one package:

```text
package.jet
run.jet
counter.h / counter.c       # C
counter.hpp / counter.cpp   # C++
Counter.java                # JVM
ops.d.ts / ops.mjs          # JavaScript
ops.py                     # Python
.jet/bindings/<language>/   # generated, local build artifacts
```

The cache is a build product. Do not hand-edit it as a repair. A stale
descriptor or link record must fail closed, then be regenerated by the matching
`inspect bind` command.

The executable matrix is Unix-gated. It needs `cc`, `ar`, `clang++`, `nm`,
`strip`, `javac`, `javap`, `node`, and `python3`; a missing tool fails the
proof. The matrix invokes the selected host tools directly. It has no host-tool
fallback claim.

## Daily loop

Run these commands from the package root. The same loop is used for every
language after its bind step:

```sh
jet check run.jet
jet build --profile=debug run.jet
jet test --coverage --profile=debug run.jet
jet run --profile=debug run.jet
jet run --profile=release run.jet
jet perf run run.jet --profile=debug --out .jet/profile.jettrace
jet perf view .jet/profile.jettrace --json
jet debug run.jet
```

`jet test --coverage` reports function and branch coverage for the checked Jet
surface. `jet perf` writes the versioned `jet.trace` v1 envelope and keeps the
Jet source identity in the trace. `jet debug` uses the Jet source debugger for
pure Jet code. A program with a foreign call is intentionally routed to the
native debugger backend; the current source map stops at the Jet/native
boundary. The tools keep the Jet location and mark unavailable foreign native
frames or address ranges as unavailable. They do not guess a foreign location
from a name or from stripped bytes.

## Bind commands

| Host surface | Bind command | Jet import | Current boundary |
| --- | --- | --- | --- |
| C | `jet inspect bind counter.h --pkg counter` | `use "counter.h" as counter` | direct checked C ABI |
| C++ | `jet inspect bind cpp counter.hpp --target <triple> --clang <absolute-clang++> --ar <absolute-ar> --pkg counter --namespace acme -I . -L . -l counter_impl -l pthread` | `use cpp.counter as cpp` | clang-generated C++ shim |
| JVM | `JAVA_HOME=<jdk> jet inspect bind java Counter.java --pkg counter` | `use java.counter as counter` | embedded JNI bridge |
| JavaScript | `jet inspect bind js ops.d.ts --runtime ops.mjs --pkg ops` | `use js.ops as ops` | supervised Node scalar sidecar |
| Python | `jet inspect bind py ops.py --pkg ops` | `use py.ops as ops` | supervised CPython scalar sidecar |

For C, declare the implementation directory and the thread library in the
package dependencies, for example:

```text
deps: .{ counter: c@".", pthread: c@system }
```

Every matrix binder writes `jet-ffi-bridge-provenance-v1` with a versioned
identity. The identity includes the exact source bytes used by the binder; JS
also includes the declaration and runtime files, and C/C++ include exact local
archive bytes when the package declares local link inputs. C, C++, JVM,
JavaScript, and Python therefore expose the same queryable schema while keeping
their language-specific descriptor and transport fields. Re-run the relevant
binder after a foreign edit or local archive rebuild.

## Hostile states covered by the matrix

The integration test keeps these checks close to the normal loop:

- C and C++ host functions execute on worker threads; C also crosses a Jet
  task boundary and C++ calls a Jet callback.
- Java, JavaScript, Python, and C++ failures become checked fallback results;
  foreign exception text is not copied into the user transcript.
- C, C++, JavaScript, and Python generated descriptors are corrupted and must
  produce E3208 before a stale binding is used. The binder then regenerates the
  cache and the run recovers.
- C++ link metadata is changed to another target and must produce E3201 rather
  than link a plausible but wrong ABI. Rebinding restores the run.
- A changed local C/C++ archive changes the binding identity and fails with
  E3208 before the native link. The C/C++ link seam inventories the generated
  binding's required symbols with the provisioned `nm`; missing symbols fail
  closed instead of becoming plausible linker or profiler locations.
- Host archives are stripped of debug data, then rebound against the exact new
  bytes; the release-profile run still completes. The trace continues to
  identify Jet source functions and never exposes generated `__jet_` frames.
- A malformed new C/JavaScript/Python binding fails with E3208 and publishes no
  cache; repairing the declaration and rerunning the binder is the recovery
  path.

The existing `tests/debug.rs`, `tests/jet_perf_trace*.rs`,
`tests/ffi_callbacks_tasks.rs`, and the binder suites cover the adjacent attach
denial, process exit, corrupt trace, callback panic, async task, and native
debugger cases. The #1348 matrix does not duplicate those lower-level proofs.

## Boundary limits

#1344 remains separate. This matrix compiles its C/C++ fixture with the
selected host compiler, then invokes existing Jet bind, check, test, run,
debug, and perf surfaces. It does not claim a hermetic `jet cc` or `jet c++`
recipe.

The native Library host boundary is intentionally explicit: C and C++ hosts
receive the generated ABI and `.jetlib` metadata, while the current JVM,
JavaScript, and Python binders are Jet-as-host call-in adapters. Debugger
stepping, profiler samples, and coverage retain the Jet source identity across
that boundary and disclose unavailable foreign native detail when the existing
tool cannot prove it. This is an attribution boundary, not a name-based
fallback.

Every passing row proves a real foreign-to-Jet bind-in path, checked errors,
archive/source invalidation, recovery, test coverage, and Jet trace identity.
