# Ratified-law map for the foundations ballot slate (worker brief)

The orchestrator is about to write 10-13 Tower ballots proposing primitives that the probe wave found missing. A ballot may not re-open a ratified decision without saying so, and it may not propose what is already ratified (that becomes an implementation card instead). Your job: for each area below, find every ratified decision, invariant, spec section, and shipped surface that governs it, and say precisely what is ratified, what is shipped, and what is genuinely undecided.

Sources of truth, in order: `docs/spec/syntax-decisions.md` (decision IDs `D-*`, search by keyword), `crates/jet-foundation/src/Syntax.rs` (every user-typeable keyword/sigil with its decision ID), `docs/spec/spec.md`, `docs/spec/architecture.md`, `docs/spec/safety.md`, `docs/spec/stdlib-api-laws.md`, `docs/spec/philosophy.md` (non-goals), `docs/reference/core-library.md`, and the Tower decision store via `node plugins/tower/tower.mjs decision show <ID> --json` (read-only; also `decision list --json`). `examples/features/**` shows what is shipped. Read-only: never edit the repo, never build, never write Tower.

For each area return:
- `ratified`: list of `{ id, oneLine, source (file:line or tower) }` — the rulings that bind this area, in the words of the ruling (quote key phrases).
- `shipped`: what exists today with the file or example that proves it.
- `undecided`: the specific questions the probe gaps raise that NO ruling answers (these are the ballot's questions).
- `conflicts`: any probe gap that a ruling already forbids or already grants (so the ballot must not propose it, or it becomes a card).

Write `~/.cache/jet-luna/dx3/_law/<area>.md` per area and `~/.cache/jet-luna/dx3/_law/summary.json`: `{ "<area>": { "ratified": [...], "shipped": [...], "undecided": [...], "conflicts": [...] } }`. Final message under 15 lines. Time box 45 minutes; breadth over depth; quote, do not paraphrase, ruling text.

## Areas

1. `realtime` — fixed-rate callbacks (audio/control loops), ISR binding, nanosecond/absolute-period waits (`time.sleep` truncation to ms: crates/jet-codegen/src/Prelude/Core/TimeSleep.rs:53-68 per probe), atomics/lock-free shared state and how `!Mem.Alloc`/`!Time` effects interact with `Shared`/channels, CPU-work deadline enforcement vs `#Context` wait-point deadlines (E3003), WCET evidence. Keywords: realtime, deadline, #Context, Mem.Alloc, atomic, Shared, interrupt, ISR, WCET, audio.
2. `ffi` — opaque C handle binding (`jet inspect bind` E3208 on opaque pointer types), `#Close`, D-FFI-CAP1, D-FFI-UNIFY1, `extern c` / `extern rust`, transitive native link declaration (`c@system`, `@nixpkgs:` attrs, E3210), FFI authority (E1803 `allow: [FFI]`), C++ binder, `*Int` across the boundary (E3202). Keywords: FFI, extern, bind, handle, Close, link, nixpkgs, authority.
3. `capabilities` — authority model: `authority.holds`, effect grants, resource-scoped grants like `FS.Read:<path>`, plugin sandbox target (E1258 "A sandbox can't use any effect", E1260 scalar-only exports, D-PLUGIN1, D-DEP-WASM1), `plugin.load` no-follow root, host imports for guests, WIT/ABI versioning (E1257).
