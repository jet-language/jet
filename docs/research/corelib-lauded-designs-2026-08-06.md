# Lauded stdlib designs: what to copy, what to avoid

Research for the Jet CoreLib redesign, 2026-08-06. Method: for each stdlib domain, find the implementation practitioners most consistently praise, extract the concrete design moves behind the praise, and collect notorious failures with root causes. Every claim carries a source URL.

Per owner directive, each verdict and rule carries a **segment lens**: how the design serves absolute beginners, intro-course students, hobbyists writing one-off scripts, migrants from other languages, medium-business teams, and enterprise maintenance. A rule makes the final list only if it serves the full spectrum or names its segment.

---

## Part 1 — Per-domain verdicts

### 1.1 Naming and API surface: Swift API Design Guidelines

**Verdict: best in class.** Swift's guidelines are the most-cited naming doctrine in industry. Core rules ([swift.org](https://www.swift.org/documentation/api-design-guidelines/)):

- **Clarity at the point of use** beats clarity at the declaration. Methods are declared once, read thousands of times.
- **Argument labels make calls read as sentences**: `x.removeBoxes(havingLength: 12)`, `view.dismiss(animated: false)`. Omit the label only when arguments are indistinguishable (`min(a, b)`) or the call is a value-preserving conversion (`Int64(someUInt32)`).
- **Name by side effect.** No side effect → noun phrase (`x.distance(to: y)`, `x.sorted()`). Side effect → imperative verb (`x.sort()`, `x.append(y)`). Mutating/nonmutating pairs are systematic: `sort`/`sorted`, `formUnion`/`union`.
- **Default arguments beat method families.** One `compare(_:options:range:locale:)` with defaults "surpasses four separate overloads in usability."
- Protocols describing a capability end in `-able`/`-ing` (`Equatable`); protocols describing what a thing is are nouns (`Collection`).

SwiftUI extends this into **progressive disclosure as an explicit design method**: identify the simple case, give it intelligent defaults so it specifies only what it needs, then let complexity appear only when requested ([Apple WWDC22, "The craft of SwiftUI API design: Progressive disclosure"](https://developer.apple.com/videos/play/wwdc2022/10059/); [WWDC16 session 403](https://asciiwwdc.com/2016/sessions/403)).

**Segment lens.** Beginners and students: call sites read as English, so example code self-documents; no overload lists to navigate. Hobbyists: defaults mean the two-argument call just works. Migrants: the mutating/nonmutating naming convention transfers knowledge across the whole library once learned. Medium/enterprise: side-effect naming is a code-review aid — a reviewer sees `sort()` vs `sorted()` and knows mutation without opening the declaration. Serves the full spectrum.

### 1.2 Error handling: Rust Result/Option + `?`

**Verdict: best in class**, with Go as the instructive counterpoint. Rust's `Result<T, E>`/`Option<T>` make failure part of the signature: "when you see a function's return type, you know exactly what can go wrong — no hidden exceptions" ([dev.to](https://dev.to/nithinbharathwaj/rust-error-handling-how-option-and-result-types-build-bulletproof-software-1i7i)). The compiler forces confrontation of the error case; whole bug classes disappear ([reintech](https://reintech.io/blog/rust-error-handling-best-practices-result-option-beyond)). The `?` operator is the load-bearing ergonomic: propagate-or-unwrap in one character, so the happy path reads linearly while every fallible point stays visible ([dasroot.net](https://dasroot.net/posts/2026/01/rust-error-handling-result-option-question-operator/)).

Go proves that typed errors **without** a propagation operator fail the ergonomics test: `if err != nil` boilerplate "drowns out the rest of the code," three lines per fallible call, and is the top recurring complaint in Go's own developer surveys ([go.dev blog, "[On|No] syntactic support for error handling"](https://go.dev/blog/error-syntax); [jesseduffield.com](https://jesseduffield.com/Gos-Shortcomings-1/)). Go's defense — every failure point named at the line where it fails ([dev.to](https://dev.to/gabrielanhaia/exceptions-made-you-sloppy-gos-if-err-nil-fixes-that-35j2)) — is exactly what `?` preserves without the boilerplate. The Go team ultimately declined all syntax proposals, freezing the pain in place.

**Segment lens.** Beginners: typed errors are safer than exceptions (no invisible control flow) but raw `Result` plumbing is ceremony; the beginner tier needs `?`-grade or better sugar plus readable error messages, or beginners will `unwrap()` everything. Rust's own steep-curve reputation shows what happens when the safe path costs too much up front ([BigGo](https://biggo.com/news/202502181925_rust-learning-curve-debate); [corrode.dev](https://corrode.dev/blog/flattening-rusts-learning-curve/)). Hobbyists: `?` keeps scripts short. Migrants from exception languages: the signature tells them what throws — a strict improvement. Enterprise: exhaustive error handling at compile time is precisely the maintainability property large codebases want; Go chose explicitness for the same enterprise reason and practitioners accept the trade at scale ([go.dev SPLASH talk](https://go.dev/talks/2012/splash.article)). Serves the full spectrum if the sugar is beginner-grade.

### 1.3 Collections and iteration: Rust Iterator / C# LINQ / Elixir Enum / Ruby Enumerable / Kotlin

**Verdict: shared crown; four designs converge on the same lessons.**

- **C# LINQ** pioneered one uniform, lazily-composed query vocabulary over every data source. Deferred execution — "a query is a description of work, not work already done" — is what makes queries composable and reusable ([devleader.ca](https://www.devleader.ca/2026/05/15/linq-deferred-execution-in-c-when-queries-execute-and-multiple-enumeration-pitfalls); [Cheney/Wadler, "The essence of language-integrated query"](https://homepages.inf.ed.ac.uk/wadler/papers/essence-of-linq/essence-of-linq.pdf)). The trap it also teaches: deferred execution causes silent multiple-enumeration bugs — laziness must be visible.
- **Elixir** built the entire stdlib around `|>`: every `Enum` function takes the collection first so pipelines compose by convention, and the tutorial-level idiom is `data |> Enum.map(...) |> Enum.filter(...)` ([elixirschool](https://elixirschool.com/en/lessons/basics/pipe_operator); [hexdocs](https://hexdocs.pm/elixir/enumerable-and-streams.html)). Eager `Enum` and lazy `Stream` are separate, same-shaped modules — laziness is an explicit opt-in, not a hidden property.
- **Ruby Enumerable** shows the power of a protocol: implement `each`, mix in `Enumerable`, receive ~50 methods free ([sitepoint](https://www.sitepoint.com/guide-ruby-collections-iii-enumerable-enumerator/); [rubyguides](https://rubyguides.dev/tutorials/ruby-enumerable/)). One tiny contract funds an enormous consistent surface.
- **Rust Iterator** does the same with lazy adapters plus zero-cost compilation; **Kotlin** replays it with extension functions over collections (eager) and sequences (lazy), using default parameters to avoid overload explosions ([kotlinlang.org](https://kotlinlang.org/docs/functions.html); [kotlinlang stdlib](https://kotlinlang.org/api/core/kotlin-stdlib/)).

Common design moves earning the praise: one shared vocabulary (`map`/`filter`/`reduce`) across every container; a single small protocol funding the whole surface; left-to-right dataflow at the call site; eager/lazy as an explicit, same-shaped choice.

**Segment lens.** Beginners/students: `list.map(f)` chains read top-to-bottom and are teachable on day one; Ruby and Elixir tutorials lead with them. Hobbyists: one-liners for everyday data munging. Migrants: `map`/`filter`/`reduce` names are now a cross-language lingua franca — matching them transfers knowledge in. Medium/enterprise: LINQ's uniform vocabulary means one skill covers lists, databases, and XML; the multiple-enumeration trap is the enterprise-scale warning to make laziness visible. Serves the full spectrum.

### 1.4 Filesystem paths: Python pathlib (over os.path)

**Verdict: best in class, and the clearest before/after lesson in stdlib history.** `os.path` is stringly-typed: paths are bare strings, every operation is a free function, calls nest inside-out, and the module mixes path algebra with unrelated OS jobs ([rednafi](https://rednafi.com/python/pathlib/)). `pathlib` made the path a type: `/` joins segments, methods chain, platform separators are automatic, and high-frequency compound operations collapse to one call (`p.read_text()` vs open/read/close) ([Trey Hunner, "Why you should be using pathlib"](https://treyhunner.com/2018/12/why-you-should-be-using-pathlib/); [docs.python.org](https://docs.python.org/3/library/pathlib.html)). The deeper lesson: Python shipped the stringly-typed version first and now carries both forever — the duplication itself is the anti-pattern (see Part 3).

**Segment lens.** Beginners: `Path.home() / "notes.txt"` is readable without knowing what a separator is; `read_text()` removes the file-handle concept from the first lesson. Hobbyists: most scripts are path+file work; compound convenience methods are the whole win. Migrants: object paths match Java's java.nio and C#'s FileInfo expectations. Enterprise: a Path type ends the "is this variable a path or a URL or a fragment?" review question — typed domain values audit better than strings. Serves the full spectrum.

### 1.5 HTTP: python-requests (over urllib)

**Verdict: best in class as a case study in defaults.** Python's built-in urllib "provides most of the HTTP capabilities you need, but the API is thoroughly broken — an enormous amount of work (even method overrides) for the simplest of tasks" (requests' own README, quoted at [codemia](https://codemia.io/knowledge-hub/path/what_are_the_differences_between_the_urllib_urllib2_urllib3_and_requests_module)). requests wrapped the same engine with human-shaped verbs (`requests.get(url)`), automatic JSON decoding, sessions, sane timeout/redirect handling — and became the canonical proof that "for humans" defaults beat exposed plumbing ([zenrows](https://www.zenrows.com/blog/urllib-vs-urllib3-vs-requests/); [Real Python](https://realpython.com/urllib-request/)). The stdlib lesson: when the stdlib offering is hostile, the ecosystem routes around it and the stdlib module becomes dead weight. A new language should ship the requests-grade API *as* the stdlib, with the low-level layer as the expert opt-down.

**Segment lens.** Beginners/students: `get(url).json()` is a first-week exercise; urllib is not teachable. Hobbyists: this is the single most common script task. Migrants: every ecosystem now has a requests clone (Go resty, JS fetch/axios); the shape is expected. Enterprise: sessions, connection pooling, and timeout policy still need expert control — requests keeps them available, which is why it also survived in production. Serves the full spectrum.

### 1.6 I/O abstraction: Go io.Reader/io.Writer

**Verdict: best in class.** One-method structural interfaces (`Read([]byte) (int, error)`) that any type satisfies implicitly. Consequences practitioners cite: libraries interoperate without importing each other, so no coupling; one function parameterized by `io.Reader` works on files, sockets, buffers, gzip streams; the `io` package wires readers and writers into transformation pipelines ([fredrikaverpil](https://fredrikaverpil.github.io/blog/2025/12/28/gos-secret-weapon-the-standard-library-interfaces/); [victoriametrics](https://victoriametrics.com/blog/go-io-reader-writer/)). "Small interfaces compose" is the whole design.

**Segment lens.** Beginners rarely touch the interface directly — they call `os.ReadFile` — and that is correct layering: convenience functions on top, streams underneath. Migrants: the pattern maps to every stream abstraction they know. Medium/enterprise: this is primarily an at-scale win — the interface seam is what lets teams swap storage backends, add compression, and test with buffers. Segment note: the *interface* serves experts and teams; the spectrum is served only if whole-value conveniences (`read the file`) sit above it.

### 1.7 String formatting: Python f-strings

**Verdict: best in class.** Third attempt (`%`, `.format()`, then PEP 498) finally matched how people think: the expression sits inside the string at the point where its value appears, checked at compile time ([PEP 498](https://peps.python.org/pep-0498/); [Real Python](https://realpython.com/python-f-strings/)). Prior APIs were "error prone, inflexible, or cumbersome" — positional mismatch bugs with `%`, verbosity with `.format()`. Adoption was immediate and total. Lesson: interpolation is a language feature, not a library function; a format mini-language layered on top serves the expert tier.

**Segment lens.** Beginners: interpolation is lesson-one material and f-strings need zero API knowledge. Hobbyists: print-debugging (`f"{x=}"`) is a first-class convenience. Migrants: JS templates, Kotlin `"$x"`, C# `$"{x}"` — interpolation is now universal; lacking it reads as archaic. Enterprise: compile-time expression checking beats runtime format strings for correctness. Serves the full spectrum.

### 1.8 Date/time: java.time (JSR-310) and JS Temporal

**Verdict: java.time is the reference design; Temporal is the modern restatement.** Both were written by people who spent years living with the failures (Stephen Colebourne after Joda-Time; the Temporal champions after Date). Shared principles:

- **Immutability everywhere.** Mutable Calendar/Date caused shared-state bugs; both replacements are pure values ([mscharhag](https://www.mscharhag.com/java/java-8-date-time-api); [Bloomberg Temporal post](https://bloomberg.github.io/js-blog/post/temporal/)).
- **Separate types per concept**: machine instant vs calendar date vs zoned datetime vs duration. Temporal: `Instant`, `PlainDate`, `ZonedDateTime` — "you don't run calculations on un-needed data." java.time: `Instant`, `LocalDate`, `ZonedDateTime`, `Duration`/`Period`.
- **Time zones explicit**, never ambient. Date's silent local-time conversion caused constant off-by-one bugs ([Bloomberg](https://bloomberg.github.io/js-blog/post/temporal/)).
- **Learn from your prototype's flaws**: JSR-310 deliberately did *not* adopt Joda-Time wholesale because Joda's pluggable Chronology leaked (a "month" getter could return 13); the JDK version fixed the known design bugs instead of enshrining them ([amitph](https://www.amitph.com/jsr-310-part-2-joda-time-api/); [the-main-thread](https://www.the-main-thread.com/p/joda-time-java-dst-bugs-migrate-java-time-quarkus)).

**Segment lens.** Beginners: distinct types prevent the classic student bug (comparing a local date to an instant); but the beginner tier needs a blessed simple entry ("today", "now") or the type taxonomy overwhelms. Hobbyists: parsing/formatting defaults must handle ISO-8601 with zero ceremony. Migrants: java.time's vocabulary is now the cross-language standard (C# NodaTime, Temporal copy it). Enterprise: DST-transition correctness and immutability are audit-critical; this domain is where enterprises bleed real money. Serves the full spectrum with a beginner-tier entry point.

### 1.9 Defaults and parameters: Kotlin named/default params + Rails convention-over-configuration

**Verdict: Kotlin for the mechanism, Rails for the philosophy.** Kotlin's default parameter values eliminate overload families outright; named arguments make long calls self-documenting at the call site ([kotlinlang.org](https://kotlinlang.org/docs/functions.html)). Rails' convention-over-configuration is the philosophy at framework scale: the developer specifies only the unconventional; sensible defaults cover the rest, which "reduces decision fatigue, speeds development, and ensures consistency across projects" ([Wikipedia](https://en.wikipedia.org/wiki/Convention_over_configuration); [avohq](https://avohq.io/glossary/convention-over-configuration)).

**Segment lens.** Beginners: defaults are what make the two-argument call possible. Hobbyists: convention over configuration is why a Rails/Sinatra script fits on one screen. Migrants from Java: default params replace builder-pattern ceremony. Enterprise: consistency-across-projects is the enterprise sell — a new hire knows where everything lives. Caveat named: heavy convention ("magic") can obscure control flow for enterprise debugging; the expert path must expose what the default did. Serves the full spectrum with that caveat.

## Part 2 — Candidate first-principles rules for a new CoreLib

Each rule: evidence, worked example, segment note. Jet-flavored pseudocode in examples.

**R1. Optimize the call site, not the declaration.** Every character at the point of use must earn its place; APIs are read far more than declared. Evidence: Swift's foundational principle ([swift.org](https://www.swift.org/documentation/api-design-guidelines/)). Example: `grid.move(rook, to: d4)` not `grid.performPieceMovementOperation(piece: rook, destinationSquare: d4)`. Full spectrum.

**R2. The common case takes zero configuration; every default must be overridable.** Evidence: requests vs urllib ([codemia](https://codemia.io/knowledge-hub/path/what_are_the_differences_between_the_urllib_urllib2_urllib3_and_requests_module)), Rails CoC ([Wikipedia](https://en.wikipedia.org/wiki/Convention_over_configuration)), SwiftUI progressive disclosure ([WWDC22](https://developer.apple.com/videos/play/wwdc2022/10059/)). Example: `http.get(url)` with sane timeout/redirect/TLS defaults; `http.get(url, timeout: 30.seconds, redirects: .none)` for control. Full spectrum.

**R3. Default arguments, never overload families.** One function with defaults beats N overloads: smaller docs, one thing to learn. Evidence: Swift guidelines ("surpasses four separate overloads") ([swift.org](https://www.swift.org/documentation/api-design-guidelines/)); Kotlin ([kotlinlang.org](https://kotlinlang.org/docs/functions.html)). Example: `text.compare(other, ignoring: .case, locale: user.locale)` — one declaration. Full spectrum.

**R4. Named options are enums, never booleans.** `parse(input, .lenient)` is readable and extensible; `parse(input, true)` is neither. Evidence: Microsoft's own guidelines update ([learn.microsoft.com](https://learn.microsoft.com/en-us/archive/blogs/brada/design-guidelines-update-enums-vs-boolean-arguments)); GitHub's boolean-that-needed-a-third-state case ([medium/Oryeshko](https://inzhener.medium.com/use-strings-not-bools-8edbf1887904)). Example: `round(32, .down)` not `round(32, false)`. Full spectrum — beginners read call sites too.

**R5. Domain values get types, not strings.** Paths, URLs, durations, colors are types with algebra, not strings with helper functions. Evidence: pathlib vs os.path ([treyhunner](https://treyhunner.com/2018/12/why-you-should-be-using-pathlib/)); stringly-typed anti-pattern literature ([hanselman](https://www.hanselman.com/blog/stringly-typed-vs-strongly-typed); [lesinskis](https://www.lesinskis.com/stringly-typed-functions.html)). Example: `config_dir / "app.toml"` joins correctly on every OS; `dir + "/app.toml"` is a bug factory. Full spectrum.

**R6. Errors live in the signature; propagation costs one character.** Typed Result + a `?`-grade operator. Evidence: Rust praise ([dasroot](https://dasroot.net/posts/2026/01/rust-error-handling-result-option-question-operator/)) and Go's boilerplate backlash as the control group ([go.dev](https://go.dev/blog/error-syntax)). Example: `let text = file.read_text()?` — visible failure point, no three-line ritual. Full spectrum, provided beginner-tier error messages are product-grade (Jet I4).

**R7. Name by side effect; mutating/nonmutating pairs are systematic.** Evidence: Swift's `sort`/`sorted`, `union`/`formUnion` ([swift.org](https://www.swift.org/documentation/api-design-guidelines/)); JS Date's mutating setters as the failure case ([Bloomberg](https://bloomberg.github.io/js-blog/post/temporal/)). Example: `list.sort()` mutates, `list.sorted()` returns new — everywhere, no exceptions. Full spectrum; especially an enterprise code-review aid.

**R8. One iteration vocabulary across every container.** `map`/`filter`/`reduce`/`sorted`/`count` work identically on lists, sets, maps, streams, files-of-lines. Evidence: Ruby Enumerable ([rubyguides](https://rubyguides.dev/tutorials/ruby-enumerable/)), LINQ uniformity ([Wadler](https://homepages.inf.ed.ac.uk/wadler/papers/essence-of-linq/essence-of-linq.pdf)), Elixir Enum ([hexdocs](https://hexdocs.pm/elixir/enumerable-and-streams.html)). Full spectrum; migrants get free transfer since these names are the cross-language standard.

**R9. One small protocol funds the whole surface.** Implement one method (`each`/`next`), inherit the entire iteration library. Evidence: Ruby's `each` + Enumerable mixin ([sitepoint](https://www.sitepoint.com/guide-ruby-collections-iii-enumerable-enumerator/)); Rust's `next()` + Iterator adapters. Segment: mechanism serves library authors (expert tier); its *effect* — uniform methods on every type — serves everyone.

**R10. Dataflow reads left-to-right, top-to-bottom.** Chaining or pipes, never inside-out nesting. Evidence: Elixir `|>` ([elixirschool](https://elixirschool.com/en/lessons/basics/pipe_operator)); pathlib chaining vs os.path nesting ([rednafi](https://rednafi.com/python/pathlib/)). Example: `orders.filter(open).map(total).sum()` vs `sum(map(total, filter(open, orders)))`. Full spectrum.

**R11. Laziness is explicit and same-shaped, never silent.** Eager by default; lazy behind a visible switch with identical vocabulary. Evidence: LINQ's multiple-enumeration pitfalls from invisible deferral ([devleader](https://www.devleader.ca/2026/05/15/linq-deferred-execution-in-c-when-queries-execute-and-multiple-enumeration-pitfalls)); Elixir's Enum/Stream split and Kotlin's collections/sequences split as the fix ([hexdocs](https://hexdocs.pm/elixir/enumerable-and-streams.html); [kotlinlang](https://kotlinlang.org/api/core/kotlin-stdlib/)). Example: `items.lazy.map(f).first(10)`. Beginner-protective; expert-controllable.

**R12. Layer whole-value convenience over streaming primitives.** `read the file` in one call on top; Reader/Writer seam underneath. Evidence: Go's io interfaces praised for the seam ([fredrikaverpil](https://fredrikaverpil.github.io/blog/2025/12/28/gos-secret-weapon-the-standard-library-interfaces/)); pathlib's `read_text()` praised for the shortcut ([treyhunner](https://treyhunner.com/2018/12/why-you-should-be-using-pathlib/)). Segment: convenience layer serves beginners/hobbyists; the seam serves teams and library authors. Both are required; either alone fails half the spectrum.

**R13. Interpolation is language-level; formatting control is layered.** Evidence: f-strings' third-time-lucky history ([PEP 498](https://peps.python.org/pep-0498/)). Example: `"Hello {name}, you have {count} messages"` beginner tier; format spec mini-language expert tier. Full spectrum.

**R14. Immutable values by default in Core types.** Dates, times, strings, options: values, not mutable handles. Evidence: mutable Date/Calendar as the canonical failure ([mscharhag](https://www.mscharhag.com/java/java-8-date-time-api)); Temporal's first principle ([Bloomberg](https://bloomberg.github.io/js-blog/post/temporal/)). Full spectrum; also the memory-model-friendly choice.

**R15. Distinct types for distinct time concepts; zones always explicit.** Instant vs plain date vs zoned datetime vs duration. Evidence: java.time and Temporal convergence ([mscharhag](https://www.mscharhag.com/java/java-8-date-time-api); [Bloomberg](https://bloomberg.github.io/js-blog/post/temporal/)). Beginner tier gets `Date.today()` / `Clock.now()` blessed entries; the taxonomy protects everyone above.

**R16. Consistent naming grammar across the whole library, enforced.** One casing, one word order, one parameter order (subject first). Evidence: PHP's haystack/needle chaos as the negative proof — its own RFC catalog concedes the damage ([php.net RFC](https://wiki.php.net/rfc/consistent_function_names); [phpopendocs](https://phpopendocs.com/rfc_codex/standardise_core_library)); Quorum/Stefik studies showing syntax choices measurably change novice accuracy ([ACM TOCE](https://dl.acm.org/doi/10.1145/2534973)). Full spectrum; beginners feel it most.

**R17. Failure-aware lookups return Option, never sentinel values.** No `-1`, no null, no "check errno." Evidence: Rust Option praise ([reintech](https://reintech.io/blog/rust-error-handling-best-practices-result-option-beyond)); stringly/sentinel bugs literature ([devcards](https://devcards.io/stringly-typed)). Example: `text.find("x") → Option<Index>`. Full spectrum.

**R18. Zero-ceremony entry point.** A program's first line is the program, not an incantation. Evidence: Java's `public static void main` pedagogy damage — "sorcerous incantation," fixed only in Java 21–25 via JEP 512 ([openjdk](https://openjdk.org/jeps/512); [happycoders](https://www.happycoders.eu/java/main-method/)); Python's intro-CS win driven by exactly this property ([CACM](https://cacm.acm.org/blogcacm/python-is-now-the-most-popular-introductory-teaching-language-at-top-u-s-universities/)). Segment: primarily beginners/students/hobbyists; harmless to enterprise.

**R19. Design APIs to compose pieces, not enumerate possibilities.** Small orthogonal parts over mega-functions with 12 parameters. Evidence: SwiftUI's stated principle ([WWDC22](https://developer.apple.com/videos/play/wwdc2022/10059/)); Go io pipelines ([victoriametrics](https://victoriametrics.com/blog/go-io-reader-writer/)). Segment: expert/team-scale benefit; beginners consume the composed presets.

**R20. When you replace an API, replace it — don't accumulate.** One blessed way; the superseded form is deleted or clearly demoted. Evidence: Python's permanent os.path/pathlib and `%`/`.format()`/f-string triplication as the cost of accumulation ([digibeatrix](https://www.digibeatrix.com/python/en/file-operations-en/python-path-os-path-pathlib-guide-en/)); JSR-310 deleting Joda's flaws rather than adopting them ([amitph](https://www.amitph.com/jsr-310-part-2-joda-time-api/)). Full spectrum; matches Jet's greenfield rule. Enterprise migrants need the migration story named, not the old API kept.

**R21. The stdlib ships the "for humans" tier itself.** If the stdlib is hostile, the ecosystem routes around it and the stdlib becomes dead weight (urllib), or fragments (JS dates before Temporal, Moment.js et al.). Evidence: requests' dominance over urllib ([zenrows](https://www.zenrows.com/blog/urllib-vs-urllib3-vs-requests/)). Full spectrum.

**R22. Every failure message is a teaching product.** Novice accuracy is measurably a function of surface choices; the compiler/runtime message is part of the API. Evidence: Stefik's empirical program ([ACM TOCE](https://dl.acm.org/doi/10.1145/2534973)); Rust's diagnostic investment being the thing that makes its difficulty survivable ([corrode](https://corrode.dev/blog/flattening-rusts-learning-curve/)). Full spectrum; aligns with Jet I4.

## Part 3 — Anti-patterns and root causes

**A1. JavaScript Date.** Copied from Java's already-deprecated java.util.Date in a 10-day sprint: zero-based months next to one-based days, mutating setters, silent local-time conversion, per-browser parsing ([Bloomberg](https://bloomberg.github.io/js-blog/post/temporal/); [freecodecamp](https://www.freecodecamp.org/news/how-javascripts-temporal-proposal-will-change-datetime-functions/)). Root cause: **shipping a copied design without review, then freezing it via web compatibility.** It took nine years of committee work (Temporal) to fix.

**A2. Java Date/Calendar.** Mutable, stateful, one type conflating instant and calendar date; so bad the ecosystem adopted a third-party replacement (Joda-Time) for a decade ([mscharhag](https://www.mscharhag.com/java/java-8-date-time-api)). Root cause: **mutable state in value-like types plus conflated concepts.** Fixed only by a ground-up immutable redesign (JSR-310).

**A3. PHP naming.** `strlen` vs `str_replace` vs `strtolower` vs `ucfirst`; `strpos($haystack, $needle)` but `array_search($needle, $haystack)` ([php.net RFC](https://wiki.php.net/rfc/consistent_function_names); [medium/AKALIN](https://medium.com/@makalin/phps-quirky-function-naming-a-chaotic-symphony-of-pragmatism-229497d674a0)). Root cause: **accretion without a naming authority** — contributors mirrored whatever C or Perl function they were wrapping. Result: permanent documentation dependence; repair RFCs judged too breaking to ship.

**A4. Python os.path duplication.** The stringly-typed original survives beside pathlib forever; every tutorial must explain both; the module also mixes unrelated OS jobs ([rednafi](https://rednafi.com/python/pathlib/)). Root cause: **replacement without removal** — backwards compatibility turned an upgrade into a permanent fork of idioms. (Same pattern: `%` / `.format()` / f-strings.)

**A5. Node callback hell.** Error-first callbacks nested per async step; readability collapsed at three levels deep; the platform needed two successive paradigm migrations (Promises, then async/await) to recover ([toptal](https://www.toptal.com/developers/javascript/asynchronous-javascript-async-await-tutorial); [risingstack](https://blog.risingstack.com/node-js-async-best-practices-avoiding-callback-hell-node-js-at-scale/)). Root cause: **encoding control flow in user-space convention instead of language-level sequencing**; also re-taught the R6 lesson — error handling bolted onto every call site by convention does not scale.

**A6. Go `if err != nil`.** Correct semantics (visible failure points) with missing ergonomics; top survey complaint; the team ultimately declared the syntax discussion closed without a fix ([go.dev](https://go.dev/blog/error-syntax); [jesseduffield](https://jesseduffield.com/Gos-Shortcomings-1/)). Root cause: **refusing the sugar for a pattern the language forces you to write constantly.** Frequency times ceremony equals resentment.

**A7. urllib/urllib2.** Capable engine, hostile surface: method overrides to send a custom verb, manual encoding, no session concept ([codemia](https://codemia.io/knowledge-hub/path/what_are_the_differences_between_the_urllib_urllib2_urllib3_and_requests_module)). Root cause: **API shaped by the protocol's internals, not the caller's task.** The ecosystem routed around it permanently.

**A8. Java entry-point ceremony.** `public static void main(String[] args)` forced students to memorize five unexplained concepts before line one; a named factor in Java losing intro CS to Python; Java itself capitulated with JEP 512 in 2025 ([openjdk](https://openjdk.org/jeps/512); [Stanford course change](https://computinged.wordpress.com/2017/04/21/cs-department-updates-introductory-courses-java-is-gone/)). Root cause: **exposing the machine's needs (class model, static dispatch) at the human's entry point.**

**A9. Stringly-typed options and boolean traps.** `open(path, "rb+")`, `myFunc(32, false)`: valid-typed but meaningless values pass silently; call sites unreadable; extension impossible without new parameters ([hanselman](https://www.hanselman.com/blog/stringly-typed-vs-strongly-typed); [learn.microsoft.com](https://learn.microsoft.com/en-us/archive/blogs/brada/design-guidelines-update-enums-vs-boolean-arguments)). Root cause: **using a carrier type (string/bool) where a domain type (enum/option set) was owed.**

**A10. Joda-Time's leaky pluggability.** Beloved replacement library whose own author rejected it for the JDK: pluggable Chronology meant `getMonthOfYear()` could return 13, breaking every caller's assumption ([amitph](https://www.amitph.com/jsr-310-part-2-joda-time-api/)). Root cause: **flexibility that silently widens a core invariant.** Extension points must not change the meaning of the basic accessors.

## Part 4 — Segment evidence (education and enterprise)

**Why Python won intro CS.** Eight of the top 10 US CS departments teach intro in Python; the cited properties are syntactic simplicity, implicit typing/memory management, and the ability to write a real program immediately ([CACM](https://cacm.acm.org/blogcacm/python-is-now-the-most-popular-introductory-teaching-language-at-top-u-s-universities/); [InfoWorld](https://www.infoworld.com/article/2608130/python-bumps-off-java-as-top-learning-language.html)). Stanford's CS department dropped Java from intro courses in 2017 ([computinged](https://computinged.wordpress.com/2017/04/21/cs-department-updates-introductory-courses-java-is-gone/)). The transferable properties are API properties, not just syntax: zero-ceremony entry (R18), whole-value conveniences (R12), readable call sites (R1).

**Measured novice accuracy.** Stefik & Siebert: novices using C-style syntax (Perl, Java) were no more accurate than novices using a language with *randomly generated* keywords; languages that deviated toward readable keywords (Quorum, Python, Ruby) measurably beat the placebo ([ACM TOCE](https://dl.acm.org/doi/10.1145/2534973); [neverworkintheory](https://neverworkintheory.org/2014/01/29/stefik-siebert-syntax.html)). Surface choices are empirically testable; "intuitive" is measurable.

**Enterprise lens.** Go was explicitly "designed by and for people who write, read, debug and maintain large software systems"; its simplicity doctrine is about codebases surviving team churn ([Rob Pike, SPLASH 2012](https://go.dev/talks/2012/splash.article)). The enterprise-relevant rules above: R7 (review-legible mutation), R11 (no silent laziness bugs), R14/R15 (audit-critical time correctness), R16 (uniform grammar survives churn), R20 (no idiom forks). Rust shows the ceiling: its compile-time guarantees are loved *in production* even by people who cursed the learning curve ([codingplainenglish](https://codingplainenglish.medium.com/everyone-complains-about-rusts-learning-curve-until-they-use-it-in-production-e7fa793f7714)) — evidence that safety rules need not be traded away for approachability if the diagnostics and sugar carry beginners through (R6, R22).

**Migrants.** The strongest migration aids found: shared cross-language vocabulary (R8 — map/filter/reduce; R15 — java.time's type names now copied by C# and JS) and predictable naming grammar (R7, R16). The strongest migration blockers: idiom forks (A4) and naming chaos (A3).
