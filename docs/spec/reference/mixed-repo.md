# Mixed-repository adoption

A mixed repository keeps Jet sources and a foreign host in one package while the
Jet program calls a checked C, C++, JVM, JavaScript, or Python boundary. This
guide is for maintainers wiring that repository and for reviewers reading the
provenance of generated bridges. The executable workflow is in
[`tests/polyglot_systems.rs`](../../../tests/polyglot_systems.rs); native
Library output is checked by
[`tests/library_outputs.rs`](../../../tests/library_outputs.rs).

## Repository shape

Keep the host source, Jet entry, and generated bridge cache in one package:

```text
package.jet
run.jet
counter.h / counter.c       # C
counter.hpp / counter.cpp   # C++
Counter.java                # JVM
ops.d.ts / ops.mjs          # JavaScript
ops.py                     # Python
.jet/bindings/<language>/   # generated local build artifacts
```

The cache is a build product. Do not hand-edit it as a repair. A stale
descriptor or link record must fail closed and then be regenerated by the
matching `inspect bind` command. The matrix invokes selected host tools directly
and does not claim a hidden host-tool fallback. Its Unix fixture requires
`cc`, `ar`, `clang++`, `nm`, `strip`, `javac`, `javap`, `node`, and `python3`.

## Daily loop

Run these commands from the package root after the relevant bind step:

```sh
jet check run.jet
jet build --profile=debug run.jet
jet test --coverage --profile=debug run.jet
jet run --profile=debug run.jet
jet perf run run.jet --profile=debug --out .jet/profile.jettrace
jet perf view .jet/profile.jettrace --json
jet debug run.jet
```

`jet test --coverage` reports function and branch coverage for the checked Jet
surface. `jet perf` writes the versioned `jet.trace` v1 envelope and retains Jet
source identity. `jet debug` uses the Jet source debugger for pure Jet code. A
program with a foreign call is routed to the native debugger backend; the
source map stops at the Jet/native boundary. The tools retain the Jet location
and mark foreign frames or address ranges unavailable when they cannot prove a
mapping. They do not guess a foreign location from a name or stripped bytes.

The release-profile run is available when the host fixture needs the optimized
boundary:

```sh
jet run --profile=release run.jet
```

## Bind commands

The bind command is selected by the foreign source surface:

| Host surface | Bind command | Jet import | Boundary |
| --- | --- | --- | --- |
| C | `jet inspect bind counter.h --pkg counter` | `use "counter.h" as counter` | checked C ABI |
| C++ | `jet inspect bind cpp counter.hpp --target <triple> --clang <absolute-clang++> --ar <absolute-ar> --pkg counter --namespace acme -I . -L . -l counter_impl -l pthread` | `use cpp.counter as cpp` | clang-generated C++ shim |
| JVM | `JAVA_HOME=<jdk> jet inspect bind java Counter.java --pkg counter` | `use java.counter as counter` | embedded JNI bridge |
| JavaScript | `jet inspect bind js ops.d.ts --runtime ops.mjs --pkg ops` | `use js.ops as ops` | supervised Node scalar sidecar |
| Python | `jet inspect bind py ops.py --pkg ops` | `use py.ops as ops` | supervised CPython scalar sidecar |

For C, declare local implementation and thread-library inputs in the package:

```text
deps: { counter: c@".", pthread: c@system }
```

The generated bridge is not a source of undeclared link inputs. The C/C++
Library export boundary and its `.jetlib` metadata are separate from the
Jet-as-host bind-in adapters for JVM, JavaScript, and Python.

## Provenance and invalidation

Every matrix binder writes `jet-ffi-bridge-provenance-v1` with a versioned
identity. The identity includes the exact source bytes used by the binder.
JavaScript also includes declaration and runtime files; C/C++ include exact
local archive bytes when the package declares local link inputs. The languages
share a queryable schema while retaining language-specific descriptor and
transport fields.

Re-run the relevant binder after a foreign edit or local archive rebuild. A
stale descriptor or changed link metadata must fail before execution or native
linking. Rebinding publishes a new identity; it does not mutate the old
identity in place.

## Checked failure paths

The integration matrix keeps these cases close to the normal loop:

- C and C++ host functions execute on worker threads; C also crosses a Jet task
  boundary and C++ calls a Jet callback.
- Java, JavaScript, Python, and C++ failures become checked fallback results;
  foreign exception text is not copied into the user transcript.
- Corrupt C, C++, JavaScript, or Python descriptors produce E3208 before a
  stale binding is used. Rebinding regenerates the cache.
- C++ link metadata changed to another target produces E3201 rather than a
  plausible but wrong ABI.
- A changed local C/C++ archive changes the binding identity and fails with
  E3208 before the native link. Required symbols are inventoried with the
  provisioned `nm`; missing symbols fail closed.
- Stripped host debug data is treated as a new byte identity. The release run
  can complete while the trace continues to identify Jet source functions and
  does not expose generated `__jet_` frames.
- A malformed new C/JavaScript/Python binding produces E3208 and publishes no
  cache; repairing the declaration and rerunning the binder is the recovery
  path.

The adjacent debugger, perf-trace, callback-task, and binder suites cover
attach denial, process exit, corrupt trace, callback panic, async task, and
native-debugger cases without changing this repository shape.

## Boundary limits

The mixed-repository matrix compiles its C/C++ fixture with the selected host
compiler, then invokes Jet bind, check, test, run, debug, and perf surfaces. It
does not define a hermetic `jet cc` or `jet c++` recipe. Use the dedicated
[foreign build host](foreign-build-hosts.md) contract when CMake, Make, Gradle,
Bazel, or MSBuild owns the top-level build.

The native Library host boundary is explicit: C and C++ hosts receive the
generated ABI and `.jetlib` metadata, while JVM, JavaScript, and Python binders
are Jet-as-host call-in adapters. Debugger stepping, profiler samples, and
coverage retain Jet source identity across that boundary and disclose
unavailable foreign native detail when the tool cannot prove it. This is an
attribution boundary, not a name-based fallback.
