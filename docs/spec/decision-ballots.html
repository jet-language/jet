1K · JSON typed decode (D-JSON1) — glaze-inspired

D-JSON1— you asked me to translate C++’s glaze into Jet

What glaze does well: (1) pure reflection — an ordinary struct serializes with zero annotations, computed at compile time; (2) opt-in customization — to rename/skip a field you specialize glz::meta<T>, and only the keys you name change, the rest stay automatic; (3) automatic enums; (4) it’s blazing fast because it maps straight onto struct memory. The Jet question is the decode surface, in increasing “magic”:

A — explicit derive (most cohesive with what’s ratified):

struct Profile { name: String; score: Int; derive Serialize; }   // S55, one opt-in line
val p = json.decode<Profile>(text)?;   // typed; field mismatch → JSONError w/ field name

Pro: explicit, consistent with S55 (“Serialize is a deliberate opt-in; a wire format is a commitment”). Con: one line per type.

B — glaze-style pure reflection (most magic):

struct Profile { name: String; score: Int; }   // no derive
val p = json.decode<Profile>(text)?;            // works anyway

Pro: zero ceremony, matches “feels like magic”. Con: contradicts S55 (silent public wire format = footgun); choosing B means amending S55 for JSON.

C — A as default + glaze-style partial overrides (recommended):

struct Profile {
    name: String; score: Int; internal_id: String;
    derive Serialize {
        rename score -> "user_score";   // only this key changes
        skip internal_id;               // never written/read
    }
}

The faithful glaze translation that respects S55: explicit opt-in, one generic call to decode (S33), great field-level errors via the rich Error (S80), automatic enums, and the partial-override escape hatch glaze’s glz::meta is famous for.

Recommend C. Unknown-key policy already decided (D-JSON2 = ignore by default, opt-in strict). Pick A / B / C.

  1. Capability is Error (a trait); the concrete carrier gets a new name (e.g. Fault/Failure). impl FileError: Error { … }; -> T ? boxes “some Error” (consistent with S48). Most Rust-like. I’d bring you a naming menu for the carrier. (rec)

D-OWN1 — your performance question answered (“how is cloning all the time good for performance?”). It isn’t — and the lint is how we stop it. L0201 flags every clone Jet inserts so you can see the cost and remove it (pass ownership with take, or borrow).
