## D-PROVE-SEM1=A — Default jet prove execution semantics

Common producer law: TARGET may be one `.jet` file, package directory, or workspace directory. Resolution and lexicographic file order reuse `jet test`. Front-end checks run first. Per file, doctests run in source order, then the existing compiled test harness runs `#Test` declarations in declaration order. Parameterized `#Test fn` uses the existing seeded property generator and shrinker; plain `#Test` is unit evidence. Failed `require` or `require_eq` inside the test harness is a caught assertion: that test fails, later harness tests continue, final exit is at least 1. `panic(...)`, bounds/key stops, and failed `@Pre`/`@Post` contracts are uncaught runtime stops. They retain E3001/E3005, terminate that child with 70, mark declarations trapped in that child skipped with `prior_runtime_panic`, and the controller continues independent later files and budgets. A reached contract attaches to the producer invocation that called it; an unreached clause remains declared/not_observed. Deterministic budgets reuse the build/package producer; statistical budgets reuse the benchmark profile and pinned baseline producer. Order is front end, doctests, unit/property harness, deterministic budgets, statistical budgets. Front-end failure marks execution evidence skipped/prior_frontend_failure. Exit precedence after valid invocation is 101 ICE, then 70 if any child had an uncaught runtime stop, then 1 for user/static/caught-assertion/budget/policy failure, then 0. Exit 2 is malformed CLI before any report. No raw rustc message, generated-Rust path, backtrace, or type name may enter any view.

Every option produces the same semantic ProofReport envelope. Required fields are `schemaVersion`, `evidencePolicy`, `target`, `tool`, `result`, `exitCode`, `summaries`, `evidence`, and `diagnostics`. `target={kind:file|package|workspace,root,members:[{path,sha256}],inputSha256}`. `tool={jet,proofProducer,targetTriple}`. `result=pass|pass_incomplete|fail`. Every summaries member is required: `frontEnd={selected,proved,failed,skipped}`; `doctest` and `unit` each `{selected,passed,failed,skipped}`; `property={selected,passed,failed,skipped,generatedCases,shrunkFailures}`; `contract={selected,declared,observed,passed,failed,notObserved,skipped}`; `deterministicBudget` and `statisticalBudget` each `{selected,met,failed,skipped,unavailable}`. Evidence items require `{id,producer,kind,state,outcome,count,source,attachment,reason,property,contract,budget,diagnosticIndexes}`. `kind=front_end|doctest|unit|property|contract|deterministic_budget|statistical_budget`; `state=declared|checked|executed|zero|unavailable|skipped`; `outcome=proved|passed|failed|observed|not_observed|met|unavailable|not_run`; absent typed payloads are null. Property payload is `{effectiveSeed,caseIndex,generatedCases,shrinkTrace:[{name,value}],source:{path,line,column},toolchain:{jet,targetTriple}}`. Contract payload is `{marker:Pre|Post,site:{path,line,column},observation:reached_pass|reached_fail|not_reached}`. Budget payload is `{profile,kind:deterministic|statistical,observations,baselineId,limit,actual,unit}` with unknown values null.

Diagnostics are a required typed union which preserves product output, not merely a code. Every variant has `{type,code,severity,message,origin,span,caret,notes,frames,context,safeLocals}`. `type=front_end|producer|runtime`; `severity=error|warning`; `origin={stage,producer}`; span is null or `{path,startLine,startColumn,endLine,endColumn,sourceLine}`; caret is null or `{startColumn,width}`; notes is ordered text. Front-end and producer diagnostics such as E0965/E2901 preserve their exact What message, Why and Fix as ordered notes, source span, source line, and caret; frames/context/safeLocals are empty. Runtime E3001/E3005 preserve the Jet message, Jet source span/caret, ordered Jet frames, source context lines, and D-OBS2 safe locals `{name,type,value,redacted}`; they contain no rustc material. Evidence references diagnostics by zero-based `diagnosticIndexes`.

Every summary is derived from evidence, never independently counted. For frontEnd, doctest, unit, and property, `selected = proved|passed + failed + skipped` using the fields appropriate to that kind. Property `generatedCases` is the sum of evidence property.generatedCases and `shrunkFailures` counts failed property evidence with a nonempty shrinkTrace. Contract summary is `{selected,declared,observed,passed,failed,notObserved,skipped}` with `selected=declared=passed+failed+notObserved+skipped` and `observed=passed+failed`; each count derives from contract observation evidence. Each budget summary satisfies `selected=met+failed+skipped+unavailable`; all five counts derive from budget evidence. A report violating an equation is invalid. `zero` is successful discovery with count 0 and is complete. `unavailable` means an applicable producer could not start or lacked input; reason is `missing_baseline|missing_tool|unsupported_target|producer_start_failed`; state and outcome are both `unavailable`, matching D-JPROOF1. `skipped` is deliberate non-execution; reason is `prior_frontend_failure|prior_runtime_panic|not_executed_by_mode|fail_fast_policy`. Existing E0613/E2901/E3001/E3005/E0965 copy passes through unchanged. This decision allocates E2940 with registry-ready copy: What `required proof evidence is unavailable`; Why `the complete_required policy needs {producer}, but {reason}`; Fix `{producer-specific imperative action}`. Render example: `Error [E2940]: required proof evidence is unavailable` / `Why: the complete_required policy needs statistical budget checkout-p95, but no matching baseline exists` / `Fix: run jet bench src/payments.jet on the pinned profile to record the baseline`. It ships only after diagnostics registry, exact UI snapshot, `jet explain`, generated reference, and coverage satisfy I4.

One in-memory ProofReport drives terminal semantics and `--json` prints that exact ProofReport object, with no artifact metadata wrapper. D-JPROOF1 alone chooses `.jproof` serialization, path, identity, privacy, overwrite, and delivery metadata. Its artifact envelope embeds the byte-for-byte same semantic object as required member `proofReport`; artifact metadata is its sibling, never merged into or substituted for ProofReport. This ballot requires D-JPROOF1 to embed the exact ProofReport for pass, incomplete, caught assertion, producer failure, E3001, and E3005 before exit 0/1/70; it alleges no artifact path or wire schema. Usage 2, pre-identity load failure 1, and ICE 101 produce no valid artifact. No option invokes replay or a solver. `proved` is reserved for a fact universally discharged by the existing front end. Tests, sampled properties, doctests, reached contracts, and budgets say passed, failed, observed, or met.

## D-JPROOF1=A — .jproof evidence artifact contract

D-PROVE-SEM1 owns the sole semantic object: exact `ProofReport={schemaVersion,evidencePolicy,target,tool,result,exitCode,summaries,evidence,diagnostics}`. `.jproof` embeds that complete object under logical member `proofReport`; no parallel fact, evidence, outcome, diagnostic, count, or producer schema exists in this decision. The logical version-1 envelope has exactly six required members: `schema:"jet.jproof"`, `version:1`, 64-lowercase-hex `report_id`, `artifact:{path}`, `privacy:{absolute_paths,argv,environment,full_source,producer_transcripts,safe_locals}`, and the complete `proofReport`. Artifact metadata is only `schema`, `version`, `report_id`, `artifact`, and `privacy`. `jet prove --json` prints the A-canonical ProofReport plus one LF, not the artifact envelope, in every option. Human output projects that same object. D-PROVE-SEM1 decides semantic states, summaries, diagnostics, exits, and when reports exist; this decision only persists the object.

Version 1 target identity is exactly ProofReport.target. `kind` is file/package/workspace; `root` is the normalized project-relative selected root; `members[{path,sha256}]` is the complete sorted normal-loader input closure: Jet sources/imports, effective package/workspace manifests, lock data, generated sources, and build inputs that affect checked TIR. Each path is project-relative and unique; generated/logical inputs receive their stable project-relative loader identity. Members sort by exact UTF-8 path bytes. `inputSha256` is SHA-256 of each member's A-canonical JSON plus LF, concatenated in member order. Tool identity remains ProofReport.tool. Nothing outside ProofReport is allowed to alter target or producer meaning.

`report_id` is lowercase SHA-256 of the exact A-canonical ProofReport bytes plus one LF. It excludes all envelope metadata because none is semantic; path, privacy declaration, serialization option, and later signatures cannot change semantic identity. Readers recompute target.inputSha256 and report_id before trusting the artifact. The emitted artifact's separate SHA-256 covers every canonical artifact byte and is the boundary a later signing decision would sign, excluding only a future envelope `signatures` member/record; this ballot adds no signing or trust command.

Privacy happens before persistence, inside the D-PROVE-SEM1 report producer. The envelope cannot redact or add semantics without breaking report_id. It records the applied policy: absolute paths, argv, environment, full source, and producer transcripts omitted; D-OBS2 governs safe-local redaction already present in ProofReport. Project-relative paths, source spans/lines, semantic diagnostic messages, property counterexamples/shrink values, budget values, and any unredacted safe local present in ProofReport are disclosed. Users must treat `.jproof` as sensitive evidence. No unratified include-source, encryption, destination, overwrite, or inspection flag is introduced.

A-canonical JSON means UTF-8, no BOM, no insignificant whitespace, exactly one LF after a complete JSON value, object keys sorted by Unicode scalar value recursively, arrays kept in ProofReport order, and integers in shortest decimal; floats and negative zero are forbidden. Schema/extension keys must be NFC. User/source strings and paths preserve exact Unicode scalars. Escape quote/backslash as `\"`/`\\`; use `\b|\t|\n|\f|\r` and lowercase `\u00xx` for other controls; emit all other scalars as UTF-8, including U+2028/U+2029, and never escape `/`. Duplicate keys after key normalization fail. Version-1 readers retain unknown envelope and ProofReport members as complete JSON values, include them in canonical hashes/order, and losslessly re-emit them; unknown enums fail unsupported. Unknown major version fails E3613.

Artifact lifecycle is common except final-path policy. Jet canonicalizes the project, takes an exclusive mode-0600 project proof lock, creates new artifact directories mode 0700, and resolves every parent/final component no-follow. Absolute/`..` escape, symlink, non-directory parent, or non-regular final is E3614. A same-directory random temp is opened exclusive/no-follow mode 0600, fully written, file-fsynced, atomically committed without replacement, then parent-dir-fsynced before success. Unsupported primitives fail before writing. Failure removes only the owned temp. Crash leftovers are cleaned under lock only after reserved-name and regular/no-link validation. Cooperative runs serialize; exclusive temp plus no-replace prevents an uncooperative creator from being overwritten. No partial final artifact is observable.

E3611-E3614 are disjoint from sibling replay diagnostics and reserved here: corrupt/hash/canonical failure; wrong target; unsupported artifact version; unsafe path. Each exits 1. Malformed CLI remains 2, runtime stop 70, ICE 101. They must enter diagnostics.md, exact UI snapshots, `jet explain`, generated references, and coverage before shipping under I4.

## D-JREPLAY1=A — General replay capture invocation and .jreplay law

Common law for A, B, and C follows. D-PROVE-REPLAY1 consumption stays exactly `jet prove <target> --replay <artifact>`; no option creates `jet replay`, changes `jet run`, or adds auxiliary out/encrypt/key/case flags. Each option chooses one complete capture invocation. Capture grammar is closed and parseable. Flag models use exactly `jet prove TARGET --capture` or `jet prove TARGET --capture=ARTIFACT`, and sensitive counterparts replace the flag with `--capture-sensitive`; TARGET is the sole positional before the flag, ARTIFACT exists only after `=`, and a spaced artifact argument is usage error 2. Subcommand models use exactly `jet prove capture TARGET` or `jet prove capture TARGET ARTIFACT`, with sensitive counterpart `capture-sensitive`; TARGET is first positional and optional ARTIFACT second, while a third positional is usage error 2. `--` is not accepted by capture forms. Relative artifacts are project-relative; absolute artifacts follow common explicit-path law.\n\nTarget selection reuses current `jet run TARGET` resolution without a replay-only selector. A `.jet` file is one runnable unit when current run resolution accepts its file entry, otherwise capture reports that existing diagnostic. A package directory selects its manifest's current default runnable target; a workspace directory enumerates current runnable member defaults in lexicographic package-name/path order. Package/workspace capture requires exactly one resolved runnable target after current selection; zero or multiple fail E3624 before build or program effects and list exact package, target, and entry paths. One invocation produces one run and at most one artifact. Capture first resolves target, checks source, computes the full reachable effect/native graph, validates ordinary invocation authority, privacy mode, cardinality, target support, and output destination, then builds. Capture never grants an effect: every ambient operation still needs its normal lexical gate and existing `--allow-*` invocation policy. FFI, native callbacks, dynamic loading, tasks/concurrency, wall-driven scheduling, Fs, Env, Exec, Db, Gpu, and any opaque call graph fail E3625 during preflight; Jet must prove absence before starting the child, never discover them after partial effects. Replay grants zero ambient effects and opens no clock, RNG, stdin, terminal, DNS, socket, file, environment, subprocess, FFI, task, or GPU boundary. It only reads the artifact and build inputs, injects records, and verifies requests/outcome; any attempted unrecorded ambient boundary is E3623.

The canonical bytes are: 8-byte ASCII magic `JREPLAY\0`; little-endian u16 major and minor; little-endian u32 canonical-header length; canonical-header bytes; zero or more frames; footer. Version 1.0 header is UTF-8 JSON with no BOM, ASCII field names sorted by byte value, no whitespace, no duplicate keys, strings escaped with JSON's shortest valid escape, integers as minimal base-10 JSON integers, no floats, and no null for required fields. User text is preserved as exact Unicode scalar values and never normalized; unpaired surrogates and invalid UTF-8 fail E3622. Schema paths are UTF-8 project-relative forward-slash paths with no empty, `.`, `..`, absolute, NUL, or symlink component; a non-UTF-8 project path is unsupported E3625. Binary values use unpadded base64url; signed/unsigned 64-bit values that exceed exact JSON integer range use lowercase fixed-width hexadecimal strings; floats use exact lowercase IEEE-754 bit-pattern hexadecimal strings, preserving NaN payload and signed zero. Required header fields are `schema`, `version`, `artifact_id`, `producer`, `identity`, `capture`, `privacy_salt`, `limits`, and `run`; unknown required fields/record kinds fail E3620. Unknown optional fields are permitted only under sorted `extensions` maps, are hashed, preserved by copy/export, and ignored by an older same-major reader. Binary prefix major/minor must equal header version major/minor byte-for-byte; disagreement is corrupt E3622. Same major with understood required vocabulary is accepted; newer major fails E3620 without guessing.
