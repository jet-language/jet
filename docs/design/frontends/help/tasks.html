jet ? help · tasks

Goal-first explorer. The home screen lists things you want to do, not commands; pick one and get a short recipe of real commands, each runnable.

Core loop: say what you want to do, get the exact commands to do it.

1 Home — outcomes, phrased as verbs. No prior knowledge of command names required.
jet ? · tasks (alt-screen)
jet ? what do you want to do?
┌───────────────────────────────────────────────────────────┐
 run a file and rebuild on save                             
│ start a web app                                            │
│ add a dependency                                           │
│ run and watch the tests                                    │
│ format the whole project                                   │
│ understand an error message                                │
└───────────────────────────────────────────────────────────┘
type to filter · ↑↓ move · ⏎ open recipe · Esc close

A beginner who doesn't know run from build starts here. Goals map to outcomes; the recipe supplies the vocabulary (tealdeer's task-first framing).

2 Open a goal — a numbered recipe of real commands (order matters here), each step selectable.
jet ? · tasks (alt-screen)
jet ? · run a file and rebuild on save
┌───────────────────────────────────────────────────────────┐
│ 1  start it, watching for changes                        │
      jet run --watch src/main.jet                          
│                                                           │
│ 2  in another shell, rerun tests on every save           │
│      jet test --watch                                     │
│                                                           │
│ Every save rebuilds and reruns. Ctrl-C stops the watcher.  │
└───────────────────────────────────────────────────────────┘
↑↓ step · ⏎ prefill shell · ← goals · Esc close

The recipe is the answer, not a link to docs. Numbered because the steps are an ordered sequence; each line is a runnable command with the placeholder ready to edit (navi recipes).

3 Enter on a step — overlay closes, that command is on the shell line, cursor on the placeholder.
jet env · web-api
web-api ❯ jet run --watch src/main.jet

Same payoff as the palette: help hands you the command, you decide when to run it. The placeholder is preselected so you type the real path over it.

4 A goal can be "understand an error" — the recipe leads with the verbatim diagnostic (I4), then the steps to act on it.
jet ? · tasks (alt-screen)
jet ? · understand an error message
┌───────────────────────────────────────────────────────────┐
│ You ran something and saw:                                │
│ Error [E0112]: `show` wants Int (a whole number) for     │
│ argument 1, but this is String (text)                     │
│  Fix: use Int (a whole number) here                      │
│                                                           │
│ 1  read the Fix line — it names the change to make        │
│ 2  see every E0112 case:  jet ? E0112                    │
│ 3  jump to the spot:  tests/ui/arg_type_mismatch.jet:5    │
└───────────────────────────────────────────────────────────┘
↑↓ step · ⏎ prefill shell · ← goals · Esc close

The diagnostic text is verbatim; the recipe around it is task copy telling you what to do with it. The error is a starting point, not a dead end.

Steps stay numbered, the selected command leads with >. Recipe structure is text and box-drawing — a piped goal reads the same.

Shared TUI palette — cyan headings / runnable commands · magenta step numbers / selection · red inside a rendered diagnostic (verbatim) · bright-black frames + prose.
