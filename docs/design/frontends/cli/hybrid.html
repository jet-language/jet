Consequence-scaled output

One output model, three depths chosen by consequence. Trivial ops print a quiet ledger; long builds pin a live region that promotes finished lines into that ledger; mutations gate on a plan first, then apply through the same region-into-ledger flow. The scrollback is always the permanent record.

ledger is the spine — every finished line freezes into scrollback and never moves. live is what a long op looks like while it works: a pinned region that redraws in place and promotes each done item up as a permanent ledger line, then collapses to a summary. plan guards anything consequential — a full diff and one [y/N] before the region-and-ledger apply runs. Same record underneath all three.
tier 1 · trivial
Read-only or small (add a package, enter a shell) → quiet ledger, as today.
tier 2 · long
Big build → live region while working, finished items promote into the ledger.
tier 3 · mutating
System change (switch, gc) → plan → confirm → apply via region + ledger.
jetpack addTier 1. Two small packages — a quiet ledger, no ceremony.

           ✓ ripgrep  14.1.0  built 6s
           ✓ fd       9.0.0   cached

A quick, safe op does not earn a plan gate or a progress region — it just appends done lines. Scroll up in an hour, the record is intact.

One aggregate counter (31/42) beats 42 log lines. Finished items push up above the region as permanent ledger rows; the live area itself never scrolls.
…settledRegion collapses into one summary ledger line — the region was the record all along.
zsh — myproj80×24
  jetpack  build
           ✓ ripgrep  14.1.0  built 6s
           ✓ linux    6.10.1  built 1m18s
  jetpack  build ready · 42 units in 1m18s  ✓
When work ends the region is erased and its last state written as permanent lines — no leftover bar, no double report. The scrollback reads like the plain ledger.
jetos switchTier 3. A system change plans first — full diff, ask once, nothing touched yet.
zsh — myproj80×24
  jetos  switch

  Plan  generation 42 → 43 · 1 add, 1 change, 1 remove

    + firefox       —        → 129.0
    ~ linux         6.9.7    → 6.10.1
    - obsolete-lib  1.2.0    → —

  Download 240 MB · closure +18 MB · rebuild boot + current

  Apply? [y/N]
Only mutations reach for the gate. The +/~/- diff and closure delta let you decide from the plan; the [y/N] default-no means a reflexive Enter is safe. --yes skips the gate for scripts.
…appliedAnswer y; apply runs through the live region, each ✓ promoted up and tied to a plan line.
zsh — myproj80×24
  Apply? [y/N] y

  jetos  applying · generation 42 → 43
           ✓ firefox       129.0     (plan: +)
           ✓ linux         6.10.1    (plan: ~)
           ✓ obsolete-lib  removed   (plan: -)
live region · redraws in place
  activating 3/3 · boot + current       00:04
  ████████████████████████  switching
The plan sets expectations; apply is the region-into-ledger flow from tier 2, each done line tagged back to the plan symbol it fulfils. On settle: jetos now on generation 43 ✓.
jetpack gcTier 3, destructive. A delete you can preview beats one you can only regret.
zsh — myproj80×24
  jetpack  gc

  Plan  remove 12 unused · reclaim 1.8 GB

    - ripgrep  13.0.0   240 MB
    - node     20.11.0  610 MB
    … 10 more

  Apply? [y/N]
Same plan→confirm→apply shape as switch — consequence, not command name, decides the tier. On y, the removals stream through the live region into the ledger.
build failureE0102Any tier stops at the failing line; the region is erased first, then the verbatim diagnostic prints (I4).
zsh — myproj80×24
  jetpack  build

Error [E0102]: nothing named `nonexistent_function_xyz` exists here
  --> tests/ui/comptime_if_unknown_fn_dropped.jet:8:9
    |
  8 |         nonexistent_function_xyz()
    |         ^^^^^^^^^^^^^^^^^^^^^^^^
 Why: only functions that have been defined (or built in, like `print` / `input`) can be called
 Fix: define it first (fn nonexistent_function_xyz() { ... }), or call one that exists
The live region must clear before an error, or the diagnostic would print into a bar mid-rewrite. Erase region → print block → stop. On a mutation, apply is transactional: a failed line abandons the plan and nothing changed.
