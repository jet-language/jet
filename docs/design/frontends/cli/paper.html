Family B · Paper

jetpack, jetos
and jet env

Light-first and calm — the counter-position to every dark dev tool. Generous whitespace, hairline structure, and type doing the hierarchy work. A fading rule leads the eye from each label to its value.

accent flare ok error wash hairline
Flow 01 · resolve → fetch → build
jetpack add nixpkgs:ripgrep
~/myproj — jetpack
$ jetpack add nixpkgs:ripgrep

  jetpack  resolving 1 request
  jetpack  Resolved 4 packages in 312ms
            ✓ ripgrep   14.1.1   built 8s
            ✓ pcre2     10.44    cached
            ✓ oniguruma 6.9.9    cached
  jetpack  added ripgrep to env.jet ✓

uv transplant: the compact Resolved N packages in Xms line in place of a resolver log. On a light ground the ✓ ledger reads like a printed receipt; the version and state columns align to invisible tab stops. Spinner (Braille) shows only while a package realizes, then clears.

Flow 02 · shell entry / exit · env rule
jet env (enter, then exit)
~/myproj — jet env
$ jet env

  myproj ─────────╌╌╌ · temporary shell · exit to leave

myproj $ which ripgrep
/hangar/store/rp-14.1.1/bin/rg
myproj $ exit

  left myproj ──────╌╌╌ · back to your shell

Signature — fading hairline: the env rule is drawn as a rule that starts solid and thins to nothing, leading from the env label into its status. Same words as Output.rs rule(); in a truecolor terminal the fade is real, and off-TTY it degrades to dash density ───╌╌.

Flow 03 · build → generation diff → atomic switch
jetos switch
halcyon — jetos
$ jetos switch

  jetos  building generation
  jetos  generation 42 → 43

  changes ─────────────────────────────────────╌╌
    + hello           2.12.1
    ↑ ripgrep         14.1.0 → 14.1.1
    ↓ nodejs          22.5.0 → 20.15.1
    − obsolete-tool   1.0.0

  4 changed · +1 −1 ↑1 ↓1 · closure 2.1 GiB (+34 MiB)

  jetos  switch to generation 43? [Y/n] y
  jetos  activated generation 43 ✓

nh transplant: the generation diff — + − ↑ ↓ with a closure-size delta footer. Paper keeps the palette sparse: additions/upgrades in accent-and-green, the single downgrade and the size delta in flare orange (the only warm accent on the page). A fading hairline underlines the changes header.

Flow 04 · hangar disk report
jetpack gc
~/ — jetpack gc
$ jetpack gc

  jetpack  hangar disk report

    generations  ──────╌╌ · 12 kept · 8 reclaimable
    store paths  ──────╌╌ · 1,204 live · 318 dead
    reclaimable  ──────╌╌ · 4.7 GiB

  jetpack  remove 318 dead paths + 8 generations? [y/N] y
  jetpack  freed 4.7 GiB ✓

Each metric row uses the fading hairline to lead label → figure, so the eye tracks straight across. The reclaimable size is the one figure in flare — the number worth acting on — turning green once freed. hangar is the shipped store name.

Flow 05 · build failure · --shell-on-fail
jetpack add nixpkgs:openssl ✗
~/myproj — jetpack
$ jetpack add nixpkgs:openssl

  jetpack  building openssl 3.3.1
  jetpack  build failed  ✗

  error: openssl 3.3.1 failed to build
    the build stopped at the `configure` step (exit 1).
    fix: run `jetpack add openssl --shell-on-fail` to drop into
         the build sandbox and retry the step by hand.

The error() / fix: block from Output.rs, words untouched (I2: a build failure is the package's fault, never rustc). On the light ground the single red line is loud enough without a band; the --shell-on-fail hint is the concrete next step.
