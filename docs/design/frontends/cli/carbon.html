uv transplant: the one-line Resolved N packages in Xms summary replaces a scrolling resolver log. Then the existing ✓ name version state ledger from Output.rs lands each realized package as an aligned row — built 8s vs cached read at a glance. The Braille spinner collapses into the row on finish.

Flow 02 · shell entry / exit · env rule
jet env  (enter, then exit)
~/myproj — jet env
$ jet env

  ── myproj ─ temporary shell · exit to leave ────────────

myproj $ which ripgrep
/hangar/store/rp-14.1.1/bin/rg
myproj $ exit

  ── left myproj ─ back to your shell ──────────────

The existing rule() line is kept verbatim in words — it is the one marker of crossing into a jetpack env. Carbon tints only the label bold-accent; the fill stays quiet gray, so it survives NO_COLOR as pure layout. The rule prints on both sides of the crossing.

Flow 03 · build → generation diff → atomic switch
jetos switch
halcyon — jetos
GEN ● 42→43BUILD ● OKCLOSURE ● +34MSWITCH ● pending
$ jetos switch

  jetos  building generation
          ▸ realised 1240 / 1240 derivations
  jetos  generation 42 → 43

  changes
    + hello           2.12.1
    ↑ ripgrep         14.1.0 → 14.1.1
    ↓ nodejs          22.5.0 → 20.15.1
    − obsolete-tool   1.0.0

    4 changed · +1 −1 ↑1 ↓1 · closure 2.1 GiB (+34 MiB)

  jetos  switch to generation 43? [Y/n] y
  jetos  activated generation 43 ✓

nh transplant: the generation diff table — + add, − remove, ↑ upgrade, ↓ downgrade, with a closure-size delta footer. Carbon maps the four verbs to four colors (green add / red remove / amber up / magenta down) so the diff is scannable without reading versions. The summary line is the whole switch in one row.

Flow 04 · hangar disk report
jetpack gc
~/ — jetpack gc
$ jetpack gc

  jetpack  hangar disk report

    generations   12 kept · 8 reclaimable
    store paths   1,204 live · 318 dead
    reclaimable   4.7 GiB

  jetpack  remove 318 dead paths + 8 generations? [y/N] y
  jetpack  freed 4.7 GiB ✓

A two-column figure (kept vs reclaimable) instead of a wall of paths. The reclaimable size is the headline value in amber — the one number worth acting on — echoed green after the sweep. hangar is the shipped store name.

Flow 05 · build failure · --shell-on-fail
jetpack add nixpkgs:openssl  ✗
~/myproj — jetpack
HANGAR ● OKBUILD ● FAILSTEP ● configureJOBS ● 0
$ jetpack add nixpkgs:openssl

  jetpack  ▸ building openssl 3.3.1
  jetpack  build failed  ✗

  error: openssl 3.3.1 failed to build
    the build stopped at the `configure` step (exit 1).
    fix: run `jetpack add openssl --shell-on-fail` to drop into
         the build sandbox and retry the step by hand.

The error() / fix: block from Output.rs, words untouched (I2: a build failure is the package's fault, never rustc). Error red used exactly once; the status band flips BUILD ● FAIL so the state is legible even scrolled past. The --shell-on-fail hint is the concrete next step.
