jetpack · jetos · jet env

Dark, bold, energetic — with discipline. Exactly one hot highlight per screen marks the thing that is live: the running task, the target, the number worth acting on. Everything else stays cold and quiet, so the eye goes straight to what matters.

Flow 01 · resolve → fetch → build
jetpack add nixpkgs:ripgrep
~/myproj — jetpack
$ jetpack add nixpkgs:ripgrep

  jetpack  resolving 1 request
  jetpack  Resolved 4 packages in 312ms
            ⠹ building ripgrep 14.1.1 …
            ✓ pcre2      10.44    cached
            ✓ oniguruma  6.9.9    cached
  jetpack  added ripgrep to env.jet ✓

uv transplant: the Resolved N packages in Xms summary. The one live thing — the package building right now — carries the hot→hot2 glow (a truecolor gradient on the running row, 16-color hot fallback otherwise). Cached rows stay cold gray. When it finishes, the glow moves or dies.

Flow 02 · shell entry / exit · env rule
jet env (enter, then exit)
~/myproj — jet env
$ jet env

   myproj ─ temporary shell · exit to leave ────────

myproj $ which ripgrep
/hangar/store/rp-14.1.1/bin/rg
myproj $ exit

  ── left myproj ─ back to your shell ─────────────────

Inside an env, the env label is the live context — so it gets the glow on entry. On exit the heat is gone (you are back in a plain shell), so the leaving rule is fully cold: the absence of the glow is the signal that you have crossed back out. Words unchanged from rule().

Flow 03 · build → generation diff → atomic switch
jetos switch
halcyon — jetos
$ jetos switch

  jetos  building generation
  jetos  generation 42 → 43

  changes
    + hello           2.12.1
    ↑ ripgrep         14.1.0 → 14.1.1
    ↓ nodejs          22.5.0 → 20.15.1
    − obsolete-tool   1.0.0

  4 changed · +1 −1 ↑1 ↓1 · closure 2.1 GiB (+34 MiB)

  jetos  switch to generation 43? [Y/n] y
  jetos  activated generation 43 ✓

nh transplant: the + − ↑ ↓ generation diff with a closure-delta footer. Pulse's discipline shows here — the whole diff renders in cold cool/gray, and only the target generation 43 (the thing you are switching to, then confirming, then activating) carries the glow. One hot thread runs through the flow.

Flow 04 · hangar disk report
jetpack gc
~/ — jetpack gc
$ jetpack gc

  jetpack  hangar disk report

    generations   12 kept · 8 reclaimable
    store paths   1,204 live · 318 dead
    reclaimable   4.7 GiB

  jetpack  remove 318 dead paths + 8 generations? [y/N] y
  jetpack  freed 4.7 GiB ✓

The report is cold context; the single glowing figure is the reclaimable size — the one number the command exists to surface. After the sweep it settles to a calm green confirmation. hangar is the shipped store name.

Flow 05 · build failure · --shell-on-fail
jetpack add nixpkgs:openssl ✗
~/myproj — jetpack
$ jetpack add nixpkgs:openssl

  jetpack  building openssl 3.3.1
  jetpack  build failed  ✗

  error: openssl 3.3.1 failed to build
    the build stopped at the `configure` step (exit 1).
    fix: run `jetpack add openssl --shell-on-fail` to drop into
         the build sandbox and retry the step by hand.

On failure the heat leaves the gradient entirely and moves to the error line — red, once. Discipline means a screen is never glowing and erroring at the same time: it is either running (glow) or broken (red), never both. The error()/fix: words are from Output.rs, untouched (I2).
