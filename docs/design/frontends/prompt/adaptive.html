jet env prompt · adaptive

Event-driven. A bare chevron when the shell is clean; a live spinner line while a job runs; one inserted line — phrased as the next action — only when something fails.

Core loop: the prompt speaks only when something changed.

1 Clean shell — a bare chevron. No segments, no version, nothing to read.
jet env · web-api
❯

When everything's fine there's nothing to say, so it says nothing. The env name only appears if you're somewhere unexpected.

2 A job is running — one live line with a Braille spinner and progress, updated in place.
jet env · web-api
❯ jet test
⠹ running tests · 6/12 · 0.2s

The spinner line exists only for the life of the job — it's not a permanent status region. Live progress, then gone.

3 Job finished clean — the spinner line collapses, the command's own output stays, the prompt returns bare.
jet env · web-api
❯ jet test
12 passed
❯

Success adds no prompt line — the passing count is the command's output, not the prompt's. Silence is the signal that all is well.

4 On failure — one line is inserted, phrased as the next action, with a command you can run right now.
jet env · web-api
❯ jet test
11 passed · 1 failed
→ 1 test failed. Rerun just it: jet test url_parse
❯

The difference from a status prompt: this line is a verb, not a gauge. It names what to do next and hands you the exact command. It disappears the moment you run anything.

5 A build error — the verbatim diagnostic (I4) prints; the inserted action line points at it without restating it.
jet env · web-api
❯ jet run
Error [E0112]: `show` wants Int (a whole number) for argument 1, but this is String (text)
  --> tests/ui/arg_type_mismatch.jet:5:10
    |
  5 |     show("hi")
    |          ^^^^
 Why: every argument must match its parameter's type
 Fix: use Int (a whole number) here
→ 1 problem in tests/ui/arg_type_mismatch.jet. Fix it, then: jet run
❯

The diagnostic owns the words (verbatim, snapshot-pinned); the action line owns the next step. No overlap, no color-coded gauge — just what happened and what to do.

6 NO_COLOR=1 / non-TTY — spinner is a Braille glyph (still visible); the action arrow is ASCII, wording unchanged.
jet env · web-api · NO_COLOR
❯ jet test
⠹ running tests · 6/12 · 0.2s
❯ jet test
11 passed · 1 failed
-> 1 test failed. Rerun just it: jet test url_parse
❯ _

The action line's leading glyph degrades → to ->; the spinner keeps animating (Braille frames). Nothing carried by color alone.

Shared TUI palette — cyan prompt/spinner/command · green pass · red fail/action · bright-black progress detail. Yellow/magenta held back — this prompt shows almost nothing at rest.
Std-only ANSI (I6): Braille spinner frames, in-place line rewrite (CR + clear), SGR color. Reduced motion freezes the spinner to a static ⠹.
