jet env prompt · hybrid

One curated prompt. Silent by default; it speaks a single line only when something changes, and you can pull a glance or opt into a status strip.

Core loop: the prompt stays silent until something changes — then it shows exactly one line — while ^G pulls a status glance on demand and a per-env flag can pin an always-on strip.

adaptive is the foundation — bare chevron when clean, one live spinner line while running, one inserted next-action line on failure.
minimal lends the ^G glance: pull a dim one-line status any time, pushed at you never.
segments lends two things — a finished command collapses to a transient receipt, and its always-on info line survives only as an opt-in per-env config flag, not the default.

Silence is the resting state. The env name surfaces only when you are somewhere unexpected; a healthy shell says nothing.

The spinner exists only for the life of the job, then the whole prompt collapses to command … result · time — the receipt from segments, applied to adaptive's transient history. Success adds no standing line.

3 On failure — the receipt shows the miss, and one inserted line names the next action with a runnable command.
jet env · web-api
❯ jet test                                      ✗ 11/12 · 0.3s
11 passed · 1 failed
→ 1 test failed. Rerun just it: jet test url_parse
❯

The inserted line is a verb, not a gauge — it hands you the exact command and disappears the moment you run anything. That is adaptive's signature, kept intact.

4 Pull a glance — ^G reveals one dim status line on demand; it collapses on the next command.
jet env · web-api
❯            ← press ^G to glance
        build ok · 0.4s     test 12/12 · 8ms ago
❯

Status is pulled, never pushed. If you want to know where things stand while the prompt is quiet, ask once — the shell does not narrate at you. This is minimal's whole expanded surface, folded into the silent prompt.

The diagnostic owns the words; the action line owns the next step. No overlap, no color-coded gauge — just what happened and what to do.

env.jet — opt-in, not the default. The strip only appears if a team turns it on:
  prompt: { strip: on } # always-on segments · env · version · build · test · git

The always-on line is a preference, never the shipped behavior — the default prompt stays at zero lines of standing noise. One canonical prompt (I8), with an expert switch, not two rival prompts.

Every state is a word first: the receipt reads ✓ 12/12 / ✗ 11/12, the action arrow degrades to ASCII, the spinner keeps its Braille frames. Nothing is carried by color alone.

Shared TUI palette — cyan prompt/spinner/command · green pass/receipt · yellow dirty (strip only) · red fail/action · bright-black progress/scaffolding.
Std-only ANSI (I6): Braille spinner frames, in-place line rewrite (CR + clear), one transient reveal line, SGR color. Reduced motion freezes the spinner to a static ⠹. Budget: ≤2 lines at rest (0 by default, 2 only with the opt-in strip).
