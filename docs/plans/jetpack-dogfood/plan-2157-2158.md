`packages.json.br` is a useful seed for attrpaths and version metadata. It is
not a per-system coverage report or a substitute for evaluation. Hydra `job` usually looks like
`<attrpath>.<system>`, but the producer must not make that string split the
attrpath authority. Job naming can contain nested attrs and aliases. Exact
off-device Nix evaluation must supply the record identity.

The producer must also not use `.narinfo` `Deriver` as the selected derivation.
For the sample below, Hydra reports
`/nix/store/har68bdn10m05zxkvn680q37bdq0bpdx-ripgrep-15.2.0.drv`, while the
cache reports
`iv6j10qg3d5j5m2nija24gzvph451r7a-ripgrep-15.2.0.drv`. Both records point to
the same output. The index must record the derivation selected by exact pinned
evaluation.

### Producer join and differential check

The producer must use this order for each immutable channel revision and each
supported system:

1. Read the revision, release time, Hydra evaluation ID, `packages.json.br`,
   and `store-paths.xz` from one immutable release directory.
2. Reject the run if the release revision and Hydra evaluation input revision
   differ.
3. Run the same `packages-info.nix` enumeration off-device with `pkgs`
   imported explicitly for the target system. Use that result as the coverage
   universe. Use published `packages.json.br` and Hydra jobs as cross-checks.
4. Evaluate each attrpath with the exact revision and system in a clean
   off-device Nix store. Get `drvPath`, package version, and every named output.
5. Use Hydra build records only to avoid needless builds and to confirm channel
   membership. Do not infer an attrpath only from `job`.
6. Require each indexed output path to occur in `store-paths.xz` and to have a
   valid upstream `.narinfo`. Exclude a record if any selected output lacks
   cache admission data.
7. Run an independent `nix build --no-link --json` for every candidate after
   index generation, in deterministic batches of 256 attrs and with a fresh
   evaluator process. Compare `drvPath` and the complete sorted output map
   byte-for-byte with the candidate record. This is intentionally expensive
   build infrastructure; sampling does not close the criterion.
8. Stop publication on any mismatch. Publish the mismatch report with the
   failed producer run, not in the signed index.

The differential check must use a second invocation and fresh evaluator state.
Comparing two projections of one Hydra response does not meet criterion 1.

### Size evidence and bound

The fetched `store-paths.xz` has 306,392 lines. It is 7,929,940 bytes compressed
and 22,154,544 bytes uncompressed:

```text
$ xz -dc store-paths.xz | wc -l

```

The nearby immutable release
`nixpkgs-26.11pre1051111.d482ef84049d` publishes a 10,115,393-byte
`packages.json.br` and a 7,822,844-byte `store-paths.xz`; see its
[release manifest](https://releases.nixos.org/nixpkgs/nixpkgs-26.11pre1051111.d482ef84049d/).

A stream-only stress encoding turned all 306,392 channel closure paths into
full synthetic index records. This is more records than one supported system
can select from the channel. It repeated each path in `drvPath` and `outputs`.
The result was 106,300,524 bytes before compression and 11,391,506 bytes with
`zstd -19`.

Set a hard client and producer limit of 33,554,432 compressed bytes per
revision and system. Reject larger files before decompression. Also set a
268,435,456-byte decoded limit and a 400,000-record limit. These are format
bounds, not expected sizes. The producer must print actual compressed bytes,
decoded bytes, record count, output count, and coverage counts for every
published system.

This evidence supports whole-index refresh. Do not add deltas for card #2157.
Publish one content-addressed `index-v1/<revision>/<system>/<sha256>.json.zst`
target. Retain every published target permanently: the publisher cannot know
which revisions appear in user locks. The signed mutable manifest lists the
every published revision/system target and marks the 12 newest revisions per
system discoverable; older entries remain resolvable by exact revision. Keep
the prior accepted manifest and target locally for recovery after a bad but
validly signed release.

Do not put a freshness expiry in the immutable index. That would permanently
reject an old locked revision. Publish a separate signed channel manifest. It
names every retained `(revision, system, index SHA-256, compressed length,
decoded length)` target. Give the manifest a monotonic generation, issue time,
and seven-day expiry. Refresh and re-sign this small manifest without changing
an index. The client remembers the highest accepted generation and rejects an
older generation. A current manifest can keep an old locked revision usable.
After manifest expiry, the client can use an already realized offline closure,
but it must not resolve a new package from an index.

### Deterministic record and coverage shape

Use canonical UTF-8 JSON before deterministic zstd compression. The signed
payload has this shape:

```json
{
  "schema": 1,
  "channel": "nixpkgs-unstable",
  "revision": "c8f90650c15282fa8656a041bfbbd2403997a9a7",
  "system": "x86_64-linux",
  "released_unix": 0,
  "records": [
    {
      "attrpath": ["ripgrep"],
      "version": "15.2.0",
      "drvPath": "/nix/store/har68bdn10m05zxkvn680q37bdq0bpdx-ripgrep-15.2.0.drv",
      "outputs": [
        {
          "name": "out",
          "storePath": "/nix/store/axp6zlky4x2v3jwcbq24a2cz25hzlw9b-ripgrep-15.2.0"
        }
      ]
    }
  ],
  "coverage": {
    "indexed": [["ripgrep"]],
    "notIndexed": [
      {"attrpath": ["example"], "reason": "evaluation-failed"}
    ]
  }
}
```

The real release time must come from the immutable release metadata. The
example uses zero only as a placeholder. Freshness times belong only in the
signed channel manifest.

Store attrpaths as arrays of exact attribute-name segments. This makes an attr
named `a.b` distinct from the nested path `a.b`; the producer must never split
Hydra `job` text to recover segments. Before encoding, sort records
lexicographically by the raw UTF-8 bytes of each attrpath segment. Sort outputs
by `name`. Sort both coverage lists by attrpath segments, then `reason`. Reject duplicate
`(revision, system, attrpath)` keys, duplicate output names, duplicate output
paths under different names, empty output sets, and any record that conflicts
with another record for the same key. Encode object keys in the literal schema
order above. Use integers only. Use no producer clock, host path, Hydra build
ID, request order, map iteration order, or compression thread count in the
payload. Compress with one fixed zstd level, one thread, checksum enabled, and
content size enabled.

Coverage reasons form a closed set:
`evaluation-failed`, `unsupported-value`, `unsupported-system`,
`no-channel-build`, `missing-narinfo`, `missing-version`,
`missing-primary-output`, and `policy-excluded`. The report must list every
attr from the off-device per-system inventory in exactly one of `indexed` or
`notIndexed`. A differential mismatch aborts publication and therefore never
becomes a signed coverage reason. Overlays, user Nix config, custom flakes,
custom package sets, and repo-local derivations are out of scope. The report
must say so directly.

### Signing constraint

The final plan must not claim that `TrustRoot` already supplies a deployable
public signature. `crates/jetpack/src/TrustRoot.rs:16-18` says its role metadata
uses HMAC-SHA256 in the current slice. Clients cannot hold that signing secret.
The same file already has deterministic target, snapshot, timestamp, expiry,
and rollback checks at `TrustRoot.rs:824-870,1215-1625`, but its signing key
type must not be reused unchanged.

Use Ed25519 for the Jet index and channel-manifest signatures. `jetpack` already depends on
`ed25519-dalek` (`crates/jetpack/Cargo.toml:17-30`) and already verifies an
Ed25519 cache receipt (`crates/jetpack/src/Store.rs:2822-2843`). This requires no
new dependency. Pin the Jet index public key in the client. Sign the canonical
uncompressed index bytes plus a fixed domain prefix such as
`jet-nixpkgs-index-v1\n`. Ed25519 is deterministic, so the signature is stable
for stable bytes. The detached signature names only the key ID and algorithm.
The signed channel manifest binds the SHA-256, both lengths, immutable target
URL, generation, and expiry. The client must verify the current manifest, the
target digest, and the index signature before it parses records.

## Card #2157 — signed nixpkgs channel index pipeline

### Settled product policy

- V1 supported systems are exactly `x86_64-linux`, `aarch64-linux`,
  `x86_64-darwin`, and `aarch64-darwin`. Publish a separate index and coverage
  partition for each. Adding a system is a manifest-policy change, not an
  implicit acceptance of any string found in Hydra.
- V1 channel names are exactly `nixpkgs-unstable` (the measured audit channel)
  and `nixos-unstable` (the repository's `default` source at `env.jet:8`). Keep
  them distinct even if they temporarily resolve to the same revision. An
  index key uses the declared channel name plus the exact 40-hex lock revision;
  it never aliases one channel name to the other.
- Unit of publication: one whole immutable index per
  `(channel, revision, system)`. There are no deltas in v1.
- Refresh trigger: poll channel `git-revision` once per day; do nothing when it
  is unchanged. Generate every supported system for a new revision and publish
  the signed manifest only after all selected systems pass.
- Target path:
  `index-v1/<revision>/<system>/<sha256-of-compressed-bytes>.json.zst`.
  Publish its detached signature at the same path plus `.sig.json`. Never
  overwrite or delete either object.
- Discovery: a separate mutable signed channel manifest lists every published
  revision/system target and marks the newest 12 revisions per system
  `discoverable: true`. Older targets remain listed with `discoverable: false`
  so a cold exact lock remains resolvable. Its generation is monotonic, its
  issued time comes from the publisher clock, and it expires seven days after
  issue. It binds target URL, signature-sidecar URL, compressed SHA-256,
  compressed length, decoded length, record count, and index-signature
  SHA-256.
- Retention: immutable targets remain addressable permanently. A publisher
  cannot know every user lock. Clients keep the accepted manifest, the current
  locked target, and the immediately prior accepted manifest/target. Ordinary
  local GC may remove other unreferenced cached indexes; it must never remove a
  Hangar closure or lock receipt merely because index metadata was collected.
- Rollback: persist the highest accepted manifest generation. Reject a lower
  generation, and reject an equal generation with different canonical bytes.
  A bad but valid new manifest does not authorize falling back silently; the
  operator must publish a higher-generation manifest that reselects a known
  good immutable target.
- Expiry: immutable indexes have no expiry. A stale manifest blocks a new cold
  resolution with E1348. It does not invalidate a closure already admitted to
  Hangar; offline reuse uses the connected Store receipt and does not contact
  the index.
- Bounds per target: 33,554,432 compressed bytes, 268,435,456 decoded bytes,
  and 400,000 records. Reject before allocating past a bound. The measured
  stress file was 11,391,506 zstd bytes for 306,392 synthetic records; these
  bounds leave margin without accepting an unbounded document.
- Coverage universe: the exact per-system off-device `packages-info.nix`
  enumeration. Every attr is in exactly one of `indexed` or `notIndexed`.
  Overlays, overrides, user Nix config, custom flakes/package sets, local
  inputs, and impure evaluation are outside both the index and its denominator.

### Canonical formats

The index is canonical compact UTF-8 JSON, with no BOM, insignificant
whitespace, or final newline. Encode object keys in the literal order shown in
the evidence schema; encode arrays in the sorted order specified there. Use
JSON integers, not floating-point numbers. Reject duplicate JSON keys before
normalization. Attrpaths are arrays of segments. Output maps are arrays sorted
by output name so encoder map order cannot leak. Set `released_unix` to the
matched Hydra evaluation's `timestamp`; never use the producer clock.

The producer constructs a complete typed value, validates it, sorts it, and
then calls one `encode_index` function. It compresses with zstd level 19, one
thread, checksum enabled, and content-size enabled. Fixed input bytes must yield
identical compressed bytes. The producer signs
`b"jet-nixpkgs-index-v1\n" + canonical_uncompressed_index_bytes` with Ed25519.
The detached index signature contains only schema, key ID, algorithm
`ed25519`, and base64 signature.

The channel manifest uses the same canonical JSON rules. Sign
`b"jet-nixpkgs-channel-manifest-v1\n" + canonical_manifest_bytes`. The
manifest signature covers generation, issue/expiry times, every target digest
and length, and its own key ID. The client verifies the manifest signature and
rollback/expiry first, checks the compressed target length and SHA-256 before
decompression, checks decoded length, verifies the index signature, then
parses and validates records. Parsing data before these bounds may be used only
to stream bytes, never to select a package.

Reject with E1348 for: unknown key or algorithm; bad signature or digest;
expired manifest; rollback or freeze; channel/revision/system disagreement;
duplicate JSON keys; duplicate record key; duplicate output name; one store
path assigned to two output names; a conflicting record for one key; malformed
Nix path; empty version; missing outputs; or missing `out` and `bin`. Reject
with E1349 when a valid index explicitly lists the requested attr under
`notIndexed` or does not list it at all. The E1349 diagnostic prints the exact
attr segments, channel, revision, system, and coverage reason. It says overlays
and custom flakes need native evaluation and are not index inputs. E1271
remains the error for an unlocked/moving channel. E1276 remains the error when
offline mode would need a manifest or target fetch.

### Settled realization flow

For a locked nixpkgs ref, the cold online path is exactly:


`ClosureGraph::transitive_references`; #2158 must test equality with the full
`AdmittedNixClosure.objects` digest set, not merely assert a non-empty vector.
