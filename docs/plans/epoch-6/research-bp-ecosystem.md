# UE 5.x Blueprint Ecosystem Inventory (beyond in-graph canvas)

Sources: dev.epicgames.com UE 5.7/5.8 docs (primary), Epic Learning tutorials, unrealdirective.com, cbgamedev.com, forums.unrealengine.com, strayspark.studio, gpuopen.com, uhiyama-lab.com. 14 sources total.

## 1. Editor window anatomy

- **My Blueprint panel** — tree of Graphs / Functions / Macros / Variables / Event Dispatchers, plus "Add New" quick-create buttons for each kind. Interaction: click item to select (populates Details + opens graph), drag item onto a graph to spawn getter/setter/call node, right-click for context menu (rename/delete/find refs/new enum asset), search bar filters by name/comment across whole panel. Category/subcategory grouping via `Category|SubCategory` string on each item; drag between categories to reassign (order within My Blueprint tab is independent of Class Defaults order — a known UX wart).
- **Details panel** — fully context-sensitive: shows totally different field sets for a variable (name/type/default/category/tooltip/instance-editable/expose-on-spawn/replication/…) vs a function (inputs/outputs/access specifier/pure/const/call-in-editor) vs a graph node (per-node properties) vs a component. Search bar to filter properties, collapsible categories. Often blank for nodes with no exposed properties — expected, not a bug.
- **Palette panel** — full list of every available function/variable/macro/event, independent of graph context (unlike right-click context menu which IS context-filtered). Fully searchable, has a **Favorites** sub-list (right-click any palette entry → Add to Favorites) with its own live-filter search box, plus a **Class Filter** to scope the palette to nodes compatible with one class. Drag-drop from palette onto graph to place node.
- **Compile button + Compiler Results panel** — toolbar compile button changes icon/color on state (default / success / warning-yellow / error-red overlay). Compiler Results panel (Window menu, or auto-opens on error/warning) lists each diagnostic as a clickable hyperlink jumping straight to offending node; shows total compile time in ms on success; has a Clear button. This is UE's answer to "diagnostics list" — closest analog to an IDE Problems panel.
- **Toolbar** — Compile, Save, Find in Blueprint (this asset), Class Settings, Class Defaults, Debug object picker (pick a live instance to debug), Play-in-editor shortcuts flow into breakpoints.

## 2. Class-level features

- **Variables w/ metadata** — beyond type/default: Instance Editable (exposes on placed-instance Details panel, toggled via eye icon; yellow=public-no-tooltip, green=public-with-tooltip, closed=private), Expose on Spawn (adds as pin on SpawnActor node), Tooltip (shown on hover in graph/palette), Category (drives My Blueprint + Palette grouping), Replication (None/Replicated/RepNotify), Config, Transient, SaveGame, Advanced Display, Deprecated, Blueprint Read Only, Multi-line text, Slider/clamp range for numerics, 3D widget toggle for vectors. All driven by UPROPERTY-equivalent metadata specifiers surfaced as Details-panel checkboxes — no raw text editing needed by BP authors.
- **Functions** — Access Specifier (Public/Protected/Private), Pure (no exec pins, promises no side effects — visually a node with no white exec line), Const (C++-sourced, forces pure-in-BP), Call In Editor (adds a button in Details panel to invoke the function from the editor without PIE — huge for tooling/level-design iteration), Category, Keywords (search aliases), Compact Node Title, description/tooltip.
- **Event Dispatchers** — BP-side multicast delegate declaration (name + payload params) shown in My Blueprint; graph nodes to Call, Bind Event to, Unbind, Assign (auto-creates a bound custom event). Cross-actor pub/sub without hard references.
- **Interfaces panel** (Class Settings → Interfaces) — Implemented Interfaces dropdown to add; inherited interfaces auto-list (read-only, greyed, inherited from parent BP or C++); X button to remove an added (non-inherited) one. Implementing an interface function surfaces it under "Interfaces" in My Blueprint with an Implement Event/Function toggle.
- **Inheritance / overrides browser** — right-click empty graph → search parent class's overridable events/functions by name; selecting spawns an override node stub. "Add Call to Parent Function/Event" context option on any override node to chain to super behavior (opt-in, not automatic — a common footgun for new users who forget it). Parent variables/components reachable via right-click search too.
- **Class Defaults tab** — grid of every variable's default value for this class (distinct from a live instance's per-instance overrides in the level Details panel); this is where designers tune starting values.
- **Class Settings** — parent class picker (also drives Reparent), Blueprint Options (namespace, deprecation, etc.), Interfaces, Compiler settings, Replication, Component/Actor-specific toggles (e.g. Placeable, Show in curated lists), documentation link, category for content-browser filtering.

## 3. Multi-blueprint ecosystem

- **Blueprint Function Libraries** — UBlueprintFunctionLibrary-derived assets holding only static, stateless utility functions; callable from any BP without an object reference. Editor UI is the normal BP editor minus Components/Event Graph.
- **Blueprint Macro Libraries** — container asset of reusable node-graph "macros" (multi-exec-pin, expand-at-compile, tunnel-node in/out). Editor opens with simplified UI (no default graph until you add one); macros auto-inline into every calling BP at that BP's compile time, so the library itself never needs compiling. Distinct from functions: macros are pasted graph structure (can have multiple exec outputs, e.g. custom ForEachLoop), functions are called (single entry/exit, own stack frame).
- **Blueprint Namespaces** — perf/organization feature: normally opening any BP eagerly loads ALL function/macro libraries project-wide; assigning a namespace (Class Settings → Blueprint Options → Namespace, e.g. "Game.AI") stops that blanket load. Namespaces must be explicitly imported (per-BP, via Editor Preferences/Project Settings global auto-import list, or implicitly when you pick an unloaded type) to be visible in that BP's context menu/palette. Big-project editor responsiveness lever + soft access-control (unimported = invisible in menus).
- **Find in Blueprints** — project-wide, indexed search across ALL blueprint assets (not just current graph) for node text/pin names/comments/function-call-sites/variable refs; used heavily for "who calls this function" / "who references this asset" impact analysis before refactors. Indexing runs in background; can force full reindex.
- **Blueprint Diff tool** — right-click 2 assets in Content Browser → Diff Selected, or Revision Control → Diff Against Depot / History → Diff Selected. 3-panel UI: left = color-coded flat list of changed items (red=removed, green=added, cyan=modified, gray=moved), two right panels show each version's graph read-only with matching highlight per selected list item; navigation arrows step through diffs sequentially. Blueprint-asset-type only (doesn't diff Widget BP hierarchy/animation bindings in detail) — cited limitation.
- **Reparenting** — File → Reparent Blueprint (or Class Settings parent picker), swap parent class; inherited components/variables from old parent are dropped, can crash on name collisions with newly-inherited members from new parent (documented rough edge).
- **Merge tool** — 3-way visual merge (base/mine/theirs) built on same diff UI, invoked from source-control conflict resolution; production teams still report merge conflicts on binary .uasset BPs as a top pain point requiring "one person owns this BP at a time" discipline or scene-splitting to avoid collisions.

## 4. Production workflows

- **Compile-on-save is NOT automatic** — BP must be explicitly compiled (button or auto-triggers on certain edits); saving a BP with unresolved errors is allowed but flagged; stale-compile state is a recurring source of "works in editor, breaks in packaged build" bugs teams guard against with commit-hooks / CI compiling all BPs headless.
- **Error/warning bubbles** — inline on the offending node in-graph (red/yellow halo + icon) in addition to the Compiler Results list entry; hovering the bubble shows the message without opening the results panel.
- **BP → C++ conversion** — no more automatic Nativization (deprecated 4.27, removed 5.0). Current guidance: profile first (stat game / stat tickgroups / Unreal Insights), hybrid pattern = C++ base class holding hot logic (e.g. Tick) + BP subclass reparented onto it for designer-tunable behavior; convert one hot function at a time, not whole BP; treated as an optimization-phase task, not a default step.
- **Performance profiling of BPs** — no single "Blueprint Profiler" tool; workflow is `stat game` (game-thread breakdown incl. BP/tick/AI/anim/physics), `stat tickgroups`, and Unreal Insights for timeline/flame-graph view of BP VM cost vs native. BP execution runs in a bytecode VM — inherently slower than compiled C++, motivating the hybrid pattern above.
- **Blueprint size/stats limits teams hit** — no hard engine-enforced cap, but community-documented pain points: BPs with 30-40+ nodes for logic doable in a few lines of C++ ("spaghetti"); large Event Graphs slow to open/compile; deep BP inheritance chains slow editor load and compile cascades; binary .uasset format defeats textual diff/merge outside UE's own tool, driving the "avoid huge monolithic BPs, prefer function/macro libraries + composition" best practice.

## 5. Onboarding

- **Templates** — project creation flow offers Game category templates (First Person, Third Person, Top-Down, Vehicle, etc.) each pre-wired with input, a starter pawn/character BP, and basic mechanics — a working, inspectable BP graph from minute one, not a blank canvas.
- **Content Examples sample project** (via Fab/Epic Games Launcher) — numbered "stand" levels each demonstrating one engine feature interactively; dedicated Blueprints_Overview map walks Components, Construction Script vs Event Graph, variables, math, flow control nodes.
- **Context-sensitive help** — Ctrl+Alt+hover on a node surfaces extended info tooltip (not universal, works on many built-in nodes); right-click node → "View Documentation" deep-links to the matching docs page when available.
- **Node tooltips** — every node shows name + short description on hover in both graph and the action-menu/palette (author-set via node metadata: heading + body text, heading only visible pre-placement in the menu).
- **Quick Start Guide** docs + large third-party tutorial ecosystem (Epic Learning courses, YouTube, Udemy) fill gaps beyond in-editor help — signals in-editor onboarding alone is considered insufficient even by Epic (external Learning portal is a first-class, linked surface).

## Why BP scales to production (or doesn't) — cross-cutting themes

Scales well: function/macro libraries + namespaces for large-team code organization; Find-in-Blueprints for safe refactors; diff/merge tooling purpose-built for the visual format (plain git diff is useless on .uasset); Class Settings/Interfaces give real OOP-style contracts; Call-In-Editor + Details-panel exposure gives non-programmers safe tunable surfaces.

Scales poorly: no enforced modularity limit → spaghetti BPs; binary asset format → real merge conflicts, "lock the file" team discipline; BP VM overhead → hot paths must be hand-migrated to C++ with no automatic path since Nativization's removal; compile-on-demand (not on-save) → stale-BP bugs slipping to packaged builds; namespace/import system is an opt-in perf fix most teams don't adopt until it hurts.
