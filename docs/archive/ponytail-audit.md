# Jet ponytail audit

Date: 2026-07-15

Scope: the Jet language, compiler, execution backends, Core/stdlib, developer tools, and Jet-owned package tooling. Excluded: Jetpack, JetOS, and their model/evaluator crates. This is a static overengineering audit, not a correctness, security, performance, or feature-gap review. Line estimates are conservative; the timezone-data count is exact.

Jet is not treated as an application that should outsource its compiler or standard library. First-party implementations, explicit semantic passes, target backends, and broad Core coverage are product requirements. Findings below cut duplicated, unreachable, or superseded machinery without narrowing Jet's domain goals.

Implementation status (2026-07-15): findings 1, 3, 5–9, and 11–16 are implemented. Findings 2, 4, and 10 were withdrawn after implementation tracing or adversarial review showed that the proposed replacement adds machinery, hides required distinctions, or breaks a public compatibility contract.

## Findings

1. `delete:` Remove `corelib/tzdb/posix` and `corelib/tzdb/right` (1,202 regular files, 16,091 lines); `JetZone::named` strips either prefix before every lookup, then reads the top-level dataset, so neither subtree is reachable, and the POSIX metadata files are byte-identical to the top-level copies. Keep the top-level bundled fallback. [`corelib/tzdb`](../corelib/tzdb) [`Core.rs:878`](../crates/jet-codegen/src/Prelude/Core.rs#L878)
2. `withdrawn:` The scheduler copies are not one interchangeable body. Emitted AOT code owns wait/typed-deadline boundaries, observation, and raw Unix/UDP readiness; the compiled JIT runtime owns different deadline/test adapters and module boundaries. Sharing them requires macros, source rewriting, or visibility reshaping and risks R12 drift. [`scheduler.rs`](../crates/jet-codegen/src/scheduler.rs) [`scheduler/io.rs`](../crates/jet-codegen/src/scheduler/io.rs) [`Prelude/Scheduler.rs`](../crates/jet-codegen/src/Prelude/Scheduler.rs)

Build a one-module bundle for the REPL and route error conversions through `check_func_body_bundle`. About 1,080 lines. ## Deliberate complexity retained

- Compiler seam crates, the typed executable TIR, and separate AOT/JIT consumers are architecture requirements, not single-implementation abstraction bloat.
- Core's Unicode, XML, text, encoding, crypto, network, time, graphics, and systems implementations are first-party product surface under the zero-external-crate compiler rule and the all-domain language goal.
- Separate AOT and JIT consumers remain required by R12; their scheduler implementations retain backend-specific ownership, observation, deadline, and readiness boundaries.
- Diagnostics, UI snapshots, examples, and goldens are user-facing contracts and executable specification, not deletable test ceremony.
- Cranelift and `ureq` are ratified bootstrap dependencies with explicit native-replacement obligations; this audit found no dependency that can be removed now without deleting capability.
