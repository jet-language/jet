## Traps that cost this session real time

- **`libtest prints failure bodies only at the END of a run`**, and the remaining
  SIGABRT truncates that section. A full-suite log will NOT contain the body you
  need. Re-run the specific test with `--test-threads=1 --nocapture --exact`.
- **The run cache lives at `~/.cache/jet/run`, not in-tree.** Running the same
  example twice measures a WARM hit. Probing an example repeatedly and blaming the
  newest commit is a mistake I made; clear that directory first.
- **`/tmp` is a 31G RAM-backed tmpfs** and hit 100% during this session. Never put
  a cargo target dir or a multi-GB log there.
- **Corpus batteries assert on the FIRST diverging stem**, so a nonexistent example
  is indistinguishable from a failing one. A stem that never existed in git history
  (`tooling/data_line`) took a whole battery down for ten days.
- **A suspiciously fast green on a test that spawns subprocesses means an early
  return, not speed.** Card #1216's criterion was recorded met with `ok 0.07s` for a
  test that spawns six Cranelift child processes; two live defects hid behind it.
