# Repo hygiene against established language trees

**Status.** Findings. Cleanup waits on card #2979 and open ballot D-REPO-HYGIENE1. This audit still does not implement the tree.
**Snapshot.** Git `HEAD` `5382a5b20` on `master`, 2026-09-07. Jet is pre-release. The live compiler still printed `Jet 1.0.0` because `Cargo.toml` carries that version.
**Shape.** Compare Jet’s published tree to Go, rustc, Zig, Odin, CPython, and LLVM/Clang on organization, maintenance, and the stranger’s first files.

The HTML companion is `docs/audits/repo-hygiene-audit-2026-09-07.html`.

## Thesis

Jet already has the hard professional machinery: executable examples, diagnostic snapshots, a work ledger, a flake, and real CI. A stranger opening GitHub still meets an agent workshop, session logs, a failed gate dump, fifteen documentation folders, and a rogue 1.0 version stamp. Jet is pre-release. Nobody shipped 1.0.

## Method

- Published truth is `git ls-tree HEAD`, not this dirty working tree.
- Peer layouts from their current public roots (Go, rustc, Zig, Odin, CPython, LLVM).
- Live probe: `scripts/agent/jet-env ./target/debug/jet version`.
- Standing lens applied to repo shape, not language syntax.

This checkout has hundreds of unstaged documentation deletions and extra untracked compiler files. Those are not GitHub. They are local dirt on top of an unfinished cutover.

## Published tree that looks like slop

Counted from `HEAD`, not from the working tree.

1. **Session logs committed.** `.claude/` holds 112 `.log` files plus diffs and patches (`gate_run.log`, `golden_delta.diff`, `cancel_drain_attempt.patch`, …). Go and rustc would treat this as an incident. `.gitignore` does not ignore `.claude/*.log`.
2. **Failed gate dump at repo root.** `jit-aot-parity-report/` is 60 tracked files at the root of a language repo. CI already uploads this as an artifact. It does not belong next to `LICENSE`.
3. **Fifteen documentation tops on GitHub.** `HEAD:docs` still has `agents`, `archive`, `audits`, `ballots`, `continuity`, `design`, `infra`, `plans`, `proposals`, `reference`, `research`, `sidequests`, `spec`, plus loose `first-hour.md` and `diagnostic-recovery.md`. The four-category law (`spec`, `audits`, `research`, `proposals`) is true only in this working tree. 882 documentation paths are deleted locally and not committed.
4. **Visitor files that language repos keep and Jet lacks.** No `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG`, `CODEOWNERS`, `.github/ISSUE_TEMPLATE`, pull-request template, `rustfmt.toml`, `.editorconfig`, or `.gitattributes`. A vulnerability-reporting note exists at `adoption/compliance/security-policy.md`. It names no address. `docs/spec/contributing/security-closure.md` is an internal scan, not disclosure.
5. **Format is gated; the config is still thin.** CI job `rust-lint` runs `cargo fmt --all -- --check` and a curated Clippy (deny correctness/suspicious, allow style). There is no `rustfmt.toml`. `clippy.toml` only bans process/network types for the Nix evaluator. PascalCase modules compile under `#![allow(non_snake_case)]`, so file names never go through rustfmt.
6. **Mixed file naming in the implementation.** Owner decision: PascalCase Rust modules with `#![allow(non_snake_case)]`. Top-level `Source/*.rs` is 60 PascalCase files plus `main.rs` and `lib.rs`. Across `crates/` the mix is 591 PascalCase vs 335 snake_case. Mixed naming inside one compiler looks accidental even when PascalCase is intended.
7. **Tests are strong and still messy at the top.** `tests/ui/` is the rustc-like corpus (2,476 files). 389 `tests/*.rs` files sit at the tests root. rustc splits `tests/ui`, `tests/run-make`, `tests/codegen`. Go colocates `*_test.go`. A flat root that large is hard to navigate.
8. **Generated site bytes in git.** `site/dist/` is 905 tracked files. Root `dist/index.html` is a second generated drop. Publishing a site is fine; a language root that also carries a full generated font pack is noisy.
9. **Tracked machine state under `.jet/`.** Proofs, a fuzz seed, a perf trace, `secrets-audit`, `secrets-plan`. Some may be fixtures. Together they read as cache.
10. **Rogue 1.0.0 stamp.** `Cargo.toml`, `flake.nix`, and `jet version` print 1.0.0. The release policy says 1.0 is feature-complete. Jet is pre-release. Those sentences are the same class of slop.

None of this is “AI wrote a function with extra comments.” This is agent-workshop residue in the published product tree.

## What the peers get right, and what to avoid copying

**How Jet beats them on a level field (repo, not syntax).** Jet can keep Tower, `AGENTS.md`, `llms.text`, and example goldens — those are agent-optimal and Go cannot grow them without becoming a different project — *and* still present a Go-like front door. That combination is the win. rustc’s `x.py` bootstrap and GCC’s historical layout are complexity Jet should not import.

**What to avoid.**

| Mistake | Evidence | Jet exposure |
|---|---|---|
| Commit session output | Jet `HEAD:.claude/*.log` | live, high |
| Leave failed CI dumps at root | `jit-aot-parity-report/` | live, high |
| Stamp 1.0 on a pre-release | `Cargo.toml`, `flake.nix`, `jet version`, and the release-policy “feature-complete” sentence | live, high |
| Claim a thin host that is not thin | README vs `Source/main.rs` | live, medium |
| Cosmetically rename working roots | CPython `Include/`/`Objects/` never fully healed | do not rename `Source/` or `crates/` for looks |
| Bootstrap maze | rustc `x.py` | do not add a second build novel |
| Wiki-only contributing | Zig’s contributing lives off-repo | Jet already has contributing notes; they are not at the door |
| Average two doc trees | this checkout’s four-folder WT vs fifteen-folder `HEAD` | live, high |

**AI-driven development (five quantities).**

- Verdict fidelity: language-side is strong (sema, UI snapshots). Repo-side has `cargo fmt --check` and curated Clippy in CI.
- Verdict latency: a 7,450-line command file and a mixed crate naming scheme slow every agent edit.
- Verdict actionability: diagnostics are the product. Repo errors are not (no CONTRIBUTING, no CODEOWNERS).
- Context economy: `llms.text` helps. 112 logs, 905 site dist files, and 736 files under `docs/research` on GitHub hurt.
- Repair determinism: greenfield cutover is the right rule. It is not applied to the published docs tree yet.

**Surfaces.**

- Covered with proof: `jet fmt` for Jet source; CI `cargo fmt --check` and curated Clippy; example goldens; UI snapshots; `lane-check.sh` typecheck; flake check in CI.
- Worth checking: whether `site/dist` is the intended GitHub Pages input; which `.jet/` files are fixtures.
- Missing: `CONTRIBUTING.md`, root `SECURITY.md`, log ignore rules, a pre-release version stamp, committed four-folder docs tree. A `rustfmt.toml` that states PascalCase identity. The adoption bundle already has a reporting note; GitHub does not.

## What comes next (not done in this run)

The published end state is card #2979, ballot D-REPO-HYGIENE1. The owner picks A, B, or C from that ballot. Implementation starts only after ratification.

Order is a real sequence: the stranger’s door first, then stop shipping junk, then make GitHub match the docs law, then tell the truth about the command host.

1. Put `CONTRIBUTING.md` and `SECURITY.md` at the root. Point them at the contributing notes and the adoption reporting note. Add a short code-of-conduct pointer. Do not treat the internal security-closure scan as a disclosure channel.
2. Ignore and untrack session logs. Move failed parity dumps out of the GitHub root (CI artifacts already hold them).
3. Commit a complete four-category docs cutover, or stop claiming it. Do not commit the current 882 deletions blindly: this tree is dirty and consumers may still point at old paths.
4. Strip the rogue 1.0.0 stamps. Jet is pre-release. `Cargo.toml`, `flake.nix`, `jet version`, and the release-policy “feature-complete” sentence should not say 1.0 until the owner ships it.
5. Document PascalCase as identity so rustfmt and reviewers do not treat it as slop. Do not mix new snake_case modules beside it. Keep the existing fmt/clippy CI job.
6. Split the command host when ready. Until then, stop calling it thin.

Do not rename `Source/`, `crates/`, or `corelib/` for cosmetics. That is the CPython trap.

## Strongest unverified assumption

The 882 local documentation deletions are the approved four-category cleanup, complete with every consumer migrated. They may instead be a partial working-tree edit on a dirty compiler checkout. This report does not bless committing them.
