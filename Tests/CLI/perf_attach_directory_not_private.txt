Error: Jet.PerfDirectoryNotPrivate: Jet won't profile through `<work>/open/jet`: other users can open it
 Why: A flight-recorded program publishes its ring in that directory and takes attach requests from it, so whoever else can reach it could read the program's profile or turn its zones on.
 Fix: Remove `<work>/open/jet`, or set `XDG_RUNTIME_DIR` to a directory only you can open; then start the program again with `jet run --observe` and attach
More: jet-lang.dev/e/Jet.PerfDirectoryNotPrivate
