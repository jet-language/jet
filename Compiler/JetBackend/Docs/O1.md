# Jet backend optimization levels: O1 and O2

Status: design for RUST-EXIT stream S4 (brief U3), owner directive #24 (Jet's own backend builds everything at
O0/O1/O2; LLVM only as an optional, unshipped backend). D-BACKEND-OWN1=A is in force. ExecArch2's proved-rule-table
design is not ratified and is not built here: this is a conventional, measured scalar optimizer.

## Tiers and invariants

| Level | Used by (AGENTS.md I9) | Pipeline |
|---|---|---|
| O0 | `jet run`, `jet dev`, compile-time code | lower → select (no LIR passes) |
| O1 | `jet build` | lower → O1 LIR passes → select |
| O2 | `--release` | lower → O1 + O2 LIR passes → select |

- One meaning on every level (I9): every pass is a semantics-preserving rewrite of LIR (`LIR/LIR.jet` defines the
  operators exactly). Passes never call into or re-encode the runtime; runtime calls, drops and stores stay in order.
- Optimized LIR must lint. `x64_compile_module` lints its input, so an optimizer bug refuses the build with
  `LIR lint: ...` instead of producing wrong code (wrong is worse than refused).
- No undefined-behavior latitude: integer words are 64-bit two's complement; a constant fold that would need
  wrapping is not done; Float operations are never folded or reassociated (signed zeros, NaN payloads); division
  and shift semantics follow the machine instructions the selector emits.
- Instruction selection and register allocation improvements apply at every level (they are code generation, not
  optional passes); LIR passes are what O1/O2 add.
- MIR-level optimization is already done before lowering on both paths: the Jet host's driver runs
  `optimize_mir_program` (`Compiler/JetDriver/Source/Driver/Pipeline.jet`, `optimize` phase) and the golden
  harness's MIR is dumped after the Rust half's `optimize_mir_program` (`crates/jet-codegen/src/Codegen/TIR/mir.rs`,
  `JET_DUMP_MIR`). The O1 work below is therefore all at LIR and machine level.

Entry point: `lir_optimize_module(program, level)` (`Source/Opt/Opt.jet`). Callers: `Tests/GoldenLower.jet`
(`opt-level.txt`, `JET_LOWER_OPT=<n>` in `run-goldens.mjs`) and, once O1 is proven, the Jet host's
`jet_cli_build_native` (`build` → O1, `run` → O0).

## Pass list

IDs are the work items Main hands out. "Done" means written on `native/o1`, not yet proven.

### O1 (LIR, per function unless noted)

| ID | Pass | File | State |
|---|---|---|---|
| P1 | Simplify: move/copy propagation, constant folding (word ops, compares, Overflows), integer identities, sign-test of `Or(x, c≥0)` (the exact-Int inline test with a constant operand), branch folding, unreachable-block removal, empty-block threading, straight-line block merging, dead code and dead block parameters, dense renumbering | `Opt/Simplify.jet` | done |
| P2 | Strength reduction: `Mul` by 2^k → `Shl`; signed `Div`/`Rem` by 2^k → shift sequence with the truncation fix-up; `UDiv`/`URem` by 2^k → `UShr`/`And` | `Opt/Strength.jet` | open |
| P3 | Exact-Int inline facts: on the true edge of an inline test (`Compare(Ge, x ~| (x << 1), 0)`) `x` is inline in every block that edge dominates; later inline tests of `x` there fold to true; constants are inline facts | `Opt/Facts.jet` | open |
| P4 | Inlining (module): callees of at most N instructions (start N=40), non-recursive, called directly; Return → jump to a continuation block; callee StackSlots stay per inlined site; budget per caller | `Opt/Inline.jet` | open |
| P5 | Direct calls for known code pointers: `Call(Value(v))` where `v` is a `FunctionAddress` (closures, `fn` values) → `Call(Function)`; then P4 can inline it | `Opt/Inline.jet` | open |
| P6 | Local value numbering / CSE of pure instructions (Binary, Compare, PointerAdd, DataAddress, FunctionAddress, Convert) scoped by the dominator tree; Loads only between two instructions with no Call/Store/Drop | `Opt/CSE.jet` | open |

### Code generation (every level)

| ID | Change | Files | State |
|---|---|---|---|
| G1 | Const results take no register: `X64Loc.Imm`; imm32 forms of add/sub/and/or/xor/cmp, `imul r, r, imm`, shifts by an immediate count (no rcx save/restore) | `X64/RegAlloc.jet`, `X64/Select.jet`, `X64/Encoder.jet` | done |
| G2 | A result may take the register of an operand that dies at its instruction (operand positions Select reads before writing); edge-partner, entry-parameter and call-argument register hints | `X64/RegAlloc.jet`, `X64/Select.jet` | done |
| G3 | Float values in xmm registers: a second register class (xmm2-xmm15 allocatable), Float Binary/Compare/Convert/calls/returns without `movq` round trips | `X64/RegAlloc.jet`, `X64/Select.jet`, `X64/Encoder.jet` | open |
| G4 | Addressing modes: `PointerAdd(base, Mul(i, s))` + Load/Store → `[base + i*s + disp]` (SIB), `lea` for address arithmetic | `X64/Select.jet`, `X64/Encoder.jet` | open (after G3: same files) |
| G5 | Block layout: invert a branch so the hot successor falls through; loop rotation (test at the bottom); `test r, r` for compares with 0; `xor r, r` + `setcc` instead of `setcc` + `movzx` | `X64/Select.jet` | open (after G4) |

### O2 (later brief; listed so O1 does not block it)

GVN across blocks and LICM (pure instructions and loop-invariant loads with no clobber in the loop); scalar replacement
of non-escaping StackSlots (struct returns such as `multi_return`, `recursion_aggregate`); copy elision for returned
lists/strings (with S15 copies work); live-range splitting and better spill choice; loop unrolling of small counted
loops; tail calls; profile-guided layout and inlining. Exit: every required gate cell ≤1.05× Rust.

## Measurement

Cells: `Tools/perf/native-cells/Examples/features/<group>/<cell>.jet` with expected outputs computed independently
(JavaScript reference, `scratch/NativeO1/ref-cells.mjs`); the workloads are the function-boundary cells and gauntlet
kernels with N fixed in the source (the native harness passes no arguments). They run through `run-goldens.mjs` with
`JET_GOLDEN_FEATURES` pointing there, so a cell is only timed when its output is exact.

Per cell and checkpoint: native O0, native O1 and `jet build --release` (rustc/LLVM) wall time, median of 7 pinned runs
in one `kind=measure` proofq job; the reported number is the native/rustc ratio. Exit for O1: every baseline cell
≤2.0× rustc `--release`. A cell the native backend cannot lower yet is reported as unsupported with its first
lowering issue, never dropped.

## Proof per pass

1. LIR fixtures: `Tests/OptFixtures.jet` builds small LIR functions by hand, runs the pass, prints LIR before and
   after, and checks `lir_lint_module` is empty (pattern of `Tests/LowerFixtures.jet` / `run-lower-fixtures.mjs`).
2. Native goldens: the 140 stems passing at O0 (`NativeLead3/nat-n7full.results.tsv`) plus the cells, at O0 and at
   O1: 0 wrong, no stem lost.
3. The cell table before/after the pass.
